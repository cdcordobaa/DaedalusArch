## 1. Live Cypher against the in-memory mirrors

**Method** (`scripts/v1.3/apg2-live.ts fixtures`). For each of the seven projects of `tests/fixtures/v1.3-apg2/cases.json`:

1. Extract with `{ ...V13_APG2_OPTIONS, components }`.
2. Ingest with `ingestAPG` (the pipeline's ingestion: layer annotation, wipe, indexes, nodes, edges, verification). An `INGEST_002` or `INGEST_003` count mismatch fails the run.
3. Run each of the 9 templates of `APG2_TEMPLATES` as the compiler instantiates it (`instantiateTemplate`, so the `/*EXCLUDE*/` anchors are replaced), with `apg2Params` (`allowedAsync` from the case file).
   - Layers that the project's spec does not bind are passed as `null`, since Neo4j needs every `$parameter`. The mirror treats such a layer as absent, so neither side matches it.
4. Run each template a second time with `excludePatterns: ['^__no_such_path__$']`, which tests the injected `NONE(ep IN $excludePatterns …)` predicate.
5. Run the mirror (`APG2_IN_MEMORY`) on the same `APGResult`.
6. Convert the Neo4j values to plain values (Integer to number; arrays element by element). Compare the two sides as multisets of rows, and also as ordered lists.
7. Extract with `V13_DEFAULT_OPTIONS`, ingest, and run the templates again (arm b1).
8. Decide every case on the **live** rows (`match` fields), and compare with the mirror-based `ablation.json`.

**Result** (`Docs/DiagnosticRuns/apg2-live-2026-10-15/fixtures-live.json`):

| Project | Live rows = mirror rows (per template, in template order) | b1 rows |
|---|---|---|
| type-flow | boundary-type-leak 5, main-sequence-distance 1, others 0 | 0 |
| components | adp-cycle 5, sdp-violation 3, main-sequence-distance 2 | 0 |
| components-flat | adp-cycle 2 | 0 |
| public-api | main-sequence-distance 2, deep-import-declared 3, deep-import-inferred 1 | 0 |
| async | main-sequence-distance 1, undeclared-async-coupling 5 | 0 |
| io | main-sequence-distance 1, io-outside-adapters 3, nondeterminism-in-core 4 | 0 |
| control-clean | all 0 | 0 |

- All 63 template runs are equal as multisets and in order, with and without the exclude predicate. That includes every column value: the instability and distance floats, `positions`, `apis`, `lines`, `imports` and `inferred`.
- All 47 cases agree with `ablation.json` on `apg2`, `apg2Rows` and `v13Graph`, and all 47 pass.
- Every row checked here is a full row, not only a matched case. So the 19 near-misses and the control are also checked as Cypher: no template returns an unplanned row on them that the mirror does not.
- The ablation's open item ("Until that run, the claim 'the Cypher returns what the mirror returns' is unverified") is closed for these fixtures and for the dev set (§2).

The same check ran on the 71 dev variants (§2), on graphs that are larger and that the mirrors were not written against: 71 × 9 = 639 template runs, all equal. So the claim holds beyond the fixtures the mirrors were tuned on.

**No Cypher defect was found, so no template was changed.** The checks cover:

- the NULL handling of `instability` and `distance`, which `SET n = node` drops;
- the variable-length `EXISTS { MATCH (b)-[:DEPENDS_ON*1..]->(a) }`;
- the `File {filePath: p.filePath}` join in `undeclared-async-coupling`;
- array-valued properties, which the ingester writes as Neo4j lists.

## 2. Dev set: APG v2 plus the v1.3 rules on the 71 variants

**Method** (`scripts/v1.3/apg2-live.ts reference`). For each variant of the five v1.3 reference projects:

1. Materialise the variant, as `validate-reference.ts` does.
2. Parse the style's spec, and take the spec's exclude paths.
3. Extract with `{ ...V13_APG2_OPTIONS, excludePatterns, components: componentsFromLayerModel(spec.layerModel) }`.
4. Ingest, run the 9 templates live and through their mirrors, and compare (§1).
5. Compile the spec's rules (`compileFunctions`, `V13_COMPILE_OPTIONS`) and evaluate them (`evaluateSymbolic`) on **the same APG v2 graph**.
6. Extract with `V13_DEFAULT_OPTIONS`, ingest, and evaluate the v1.3 rules again.
7. Compare the two v1.3 finding lists.

The variants: 14 clean-architecture, 13 layered, 14 nestjs, 15 hexagonal and 15 DDD, of which 5 are clean, 14 near-miss and 52 violation. The parameters are `apg2Params(spec.layerModel)`, with threshold 0.7 and, for hexagonal, `allowedAsync` taken from `allowedDependencies`.

**The v1.3 rules are unaffected.**

- On all 71 variants, the v1.3 findings on the APG v2 graph equal those on the v1.3 graph.
- They also equal, finding for finding, the CLI output saved in `results/v1.3-reference/after-member-facts/raw/`.
- So the v1.3 precision and recall in `v1.3-reference-after-member-facts-2026-10-15.md` stand unchanged with `apg2` on.

All rows are in `Docs/DiagnosticRuns/apg2-live-2026-10-15/reference-live.json`. Each row carries its template and its tier from `APG2_TEMPLATE_TIERS`; the tiers are unratified.

### 2.2 Recall side: what the new rows on violation variants are

On 21 of the 52 violation variants, APG v2 adds rows that the clean variant lacks. **Every one of these 21 variants is already caught by a v1.3 rule at the same place.** APG v2 adds no planted catch on the dev set.

- **`component-adp-cycle` (blocking) and `component-sdp-violation` (advisory) on layer components.** These appear on 16 variants: clean-architecture v01, v02, v05, v08, v09; layered v01, v02; nestjs v01, v03, v10; hexagonal v01, v02, v03, v04, v10; DDD v09.
  - Every planted backward-layer import closes a cycle between two layer components, and these rows report it.
  - This is the case the design document predicts: "A cycle between ordered layers always contains a backward edge, which v1.3 dependency-direction already reports" (FF-S01, FF-S04).
  - It repeats the same finding at component level. The row's file column holds a component name, so it does not point at the offending file.
  - If the blocking tier is kept, one planted import gives one v1.3 blocking finding plus 2–4 ADP rows.
- **`boundary-type-leak` (blocking) at the planted locus.** It fires on clean-architecture v09 (`toLoanResponse` returns the HTTP adapter's `HttpResponse`) and on layered v04 (`renderProductRow` takes a `ProductRecord`). These are the same locus as FF-S01 and FF-S03 respectively.
- **`deep-import-declared-api` (blocking) at the planted locus.** It fires on DDD g03 and v08, the same locus as FF-DS02 `context-isolation`.
- **Moved rows, not new facts.** In DDD v05, the `InvoiceIssued` clock read moves from the domain to the application layer. In hexagonal v01, v02 and v10, and DDD v02, v05 and v09, the main-sequence distances move.

**The two v1.3 misses stay missed.** Both are FF-P05 "controller exposes a domain entity":

- clean-architecture v07 `LoanController`;
- nestjs v09 `WorkshopsController.findOne`.

`boundary-type-leak` looks only for infrastructure types, so neither is in its construct. The graph does hold the nestjs fact: there is a SIGNATURE_USES edge `WorkshopsController.findOne → Workshop` (`src/domain/workshop.ts`, return position, public surface). A "controller signature names a domain entity" variant of the template would catch nestjs v09. clean-architecture v07 uses the entity only in the method body, so no signature edge exists there. This is a candidate for a later template, not a change made here.

**Advisory rows: 40 rows on all 19 clean and near-miss variants.** They are of three kinds.

- **True to their construct, not violations under the reference's definition of the style.** These are the `nondeterminism-in-core` clock reads:
  - layered `OrderService.placeOrder`;
  - nestjs `RegistrationsService.register` and `.cancel`, already noted in the ablation document;
  - the two DDD domain events' `occurredAt = new Date()`.

  They are real clock reads in the core. Whether a style forbids them is an author call; no manifest plants them.
- **Metric artefacts on layer components: `component-main-sequence-distance`.**
  - The domain layer is maximally stable (I = 0: no domain file imports a file outside the layer) and mostly concrete. So D ≥ 0.7 in clean-architecture (0.73), hexagonal (1.0) and DDD (0.75, and the `ordering` module 0.71).
  - Martin's zone of pain is about components that are hard to change *and* volatile. A stable entity layer is the intended design here.
  - Hexagonal `config` (A = 1, I = 1, D = 1) is the composition root.

  On layer components this template is noise.
- **A false alarm from the inferred public API.** layered n03-views-import-model-barrel gets 4 `deep-import-inferred-api` rows.
  - The near-miss adds a barrel `business/model/index.ts`, and the views import the model through it.
  - Every barrel in a component becomes one of its inferred entry files. So the whole `business` layer now has a single entry file, and the four ordinary imports of `business/services/*`, `business/ServiceFactory.ts` and `business/errors/*` count as deep imports.
  - The rule that turns one sub-barrel into a whole layer's public API is too strong for layer components.

### 2.4 Reading

- On these five small reference projects, APG v2 adds **no recall** over the v1.3 rules.
  - The planted violations are import-level by construction, which the v1.3 rules already cover.
  - The enrichments whose ablation cases nothing else could see (type flow without an import, async channels, I/O in the core) have no planted case in the dev set.
  - So this run measures precision only. It cannot show the expressiveness gain of `apg2-ablation-2026-10-15.md`.
- **Precision before any APG v2 template enters a verdict:**
  - `deep-import-declared-api` needs the composition-root and ACL exemptions that FF-DS02 has.
  - `boundary-type-leak` needs a composition-root exemption, or a stricter exposing-layer set than every application-kind layer.
  - `component-adp-cycle` on **layer** components duplicates FF-S01 and should be restricted to `module` and `folder` components. That is also where the ablation's planted ADP cases live.
  - `component-main-sequence-distance` should not be read on layer components.
  - `deep-import-inferred-api` should infer entry files only from an index at the component root, not from every barrel.

  These are recommendations for the author. None is applied here, because each one changes a template's construct.

## 3. F-P01-ALIAS fix

**Defect** (round 2, §4). A bare specifier that tsconfig `paths` maps to a local declaration stub (`typeorm` → `vendor/typeorm.d.ts`) resolves to a file without a File node (`**/*.d.ts` is excluded). The import was dropped with only `EXTRACTOR_008`, so FF-P01 and every other package-based rule missed it.

**Fix** (v1.3 options only):

- **The option.** `ExtractorOptions.aliasDeclarationPackages` is `true` in `V13_DEFAULT_OPTIONS`, so also in `V13_APG2_OPTIONS`, and `false` in `V12E_DEFAULT_OPTIONS`.
- **The change** (`resolveModuleSilently`, `src/apg-extractor/import-resolver.ts`). Three conditions must all hold:
  - a non-relative specifier resolves through `ts.resolveModuleName` to a file under the project root that has no File node;
  - the file is a declaration file (`.d.ts`, `.d.mts`, `.d.cts`);
  - the specifier matches a `paths` rule.

  Then the result is a Package, named as every other alias or bare package is named (`packageRootForSpecifier`: `typeorm`, `@nestjs/common`). The resolution carries `declarationAlias: true`.
- **The warning.** `EXTRACTOR_008` is still emitted, now with `severity: 'info'` and the message `Import target outside the extracted set: <spec> (a declaration file reached through tsconfig paths; recorded as Package <name>)`. `ExtractorWarning` gains the optional `severity`, and the pipeline's extract stage passes it on in the warning's `context`.
- **Unchanged:**
  - relative imports of a `.d.ts`;
  - a `paths` alias to a `.ts` stub that has a File node (shape B, which needs an author decision);
  - ambient `declare module` (shape C);
  - non-declaration excluded files.

**Result.** From `npx tsx scripts/v1.3/judge-catch2-ffp01-repro.ts <scratch>`:

| Shape | Before (round 2) | Now, v1.3 options |
|---|---|---|
| A: `paths` → `vendor/typeorm.d.ts` | no IMPORTS edge, `EXTRACTOR_008` | `Package:typeorm`, `EXTRACTOR_008` with `severity: 'info'` |
| B: `paths` → `vendor/typeorm.ts` | `File:vendor/typeorm.ts` | unchanged |
| C: ambient `declare module` | `Package:typeorm` | unchanged |
| D: `fixtures/unit/antipattern-nest` | no edge | `Package:typeorm`; Package nodes `@nestjs/common`, `@nestjs/typeorm`, `typeorm` |

**FF-P01 now fires live.** The command was `firewall evaluate --project fixtures/unit/antipattern-nest --spec fixtures/unit/antipattern-nest/firewall.spec.yaml --symbolic-only`, on Neo4j. FF-P01 reports `src/invoice/invoice.entity.ts → typeorm` and `src/order/order.entity.ts → typeorm`, and the verdict is `hard-block`. So round 1's FF-P01 "both-catch control" on `antipattern-nest` is now readable. The fixture's v1.3 verdict changes accordingly. No test pinned the old verdict.

**Byte identity.** All 29 fixture projects in the repo were hashed with `scripts/apg-hash.ts --relative`, which is new: it replaces the repository root by `<repo>` before hashing, because the APG holds absolute paths inside inferred type strings. Both sides ran at the same absolute path, `origin/v1.3` `src/` first and then this branch's.

- **`V12E_DEFAULT_OPTIONS`: 29 / 29 identical.**
- `V13_DEFAULT_OPTIONS`: 28 / 29 identical. The only change is `fixtures/unit/antipattern-nest`, as intended.

The five v1.3 reference projects and the APG v2 fixtures do not change: they use ambient declarations.

The V12E hashes are now pinned in `tests/fixtures/v1.3-byte-identity/v12e-hashes.json`. `tests/unit/apg-extractor/v12e-byte-identity.test.ts` re-checks all 29 and fails when a fixture project is added without a pinned hash.

The hashes recorded in `apg2-ablation-2026-10-15/byte-identity.json` cannot be reproduced on this machine, because they embed the cloud checkout's absolute paths. The comparison above therefore ran both sides locally.

**Tests** (`tests/unit/apg-extractor/v13-alias-declaration-packages.test.ts`, 9 tests):

- the option defaults;
- shape A under v1.3: a Package edge, the info warning, `droppedNoFileNode` = 0, and **FF-P01 (the domain-purity mirror) fires**;
