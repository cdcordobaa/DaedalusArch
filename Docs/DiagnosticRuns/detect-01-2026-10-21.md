## 1. Question and inputs

Which Hexagonal (H1–H7) and DDD (D1–D11) violations can the instrument see? For the gaps, can a new symbolic rule or a
grounded semantic question see them? The test material is the nine violations that the HEXDDD-01 blind hand read found
and the instrument missed (`results/v1.4-pilot-hexddd-01/hand-read-log.csv` on `pilot/hexddd-01`, commit `c1805364`, PR
#332). The families come from `ops/notes/hexddd-01-violation-elicitation-design.md` §3.

## 2. Coverage map (summary; the full map is `ops/notes/detect-01-coverage-map.md`, committed before any code)

- **Families (19 rows, H1b included).**
  - 9 are detected today by a blocking rule: H1, H1b once the spec lists the SDK, H2, H3, H4, H7, D1, D2, D6.
  - D3 and D11 are seen only through advisory proxies.
  - 6 have a symbolic route needing facts the frozen extraction lacks: H5, D4, D5, D7, D8, D9.
  - H6 and D10 are semantic only. No family is wholly out of reach.
- **The nine misses.** 6 are symbolically reachable (cases 2, 5, 6, 7, 8, 9) and 3 are semantic only (1, 3, 4). Every
  symbolic case needs at least one fact that the frozen options do not emit:
  - calls through interfaces. CALLS keeps class-method targets only (`src/apg-extractor/edge-extractor.ts:281-323`), so
    no use case's call to a repository port appears in the graph;
  - SIGNATURE_USES, which exists only behind `apg2`;
  - statement-level guards;
  - the shapes of anonymous return types.
- **Advisory cross-check (`scores/`).** No advisory finding matches any of the nine. FF-SO02 (interface width) fires
  on the S1 `BookingRepository.ts` port from step 1. That file holds cases 2 and 4, but the finding does not move when
  either case is introduced. FF-DT06, the advisory meant for D3, never fired in S2.

## 3. Fixtures (development split)

`experiments/detect-01/fixtures/` holds 14 fixtures and 25 variants, and each variant typechecks under `tsc --strict`:
- 9 pairs, one per hand-read case: a positive derived from the pilot diff, and a twin that fixes only that violation.
  Each pair records its provenance: pilot commit, run snapshot commit, diff, and the file:line of the hand-read row.
- 2 variants that are not hand-read cases: `c4v` (H5 type form) and `c9v` (D9, an entity inside the contract).
- 3 negative controls.

**These are development material.** They were written alongside the detectors, and the detectors were adjusted while
looking at them and at the pilot trees. A confirmatory evaluation needs fresh, held-out cases (README in the folder).

One deviation is recorded in `c2/fixture.json`. In the pilot tree, `AuditEntry` is an interface whose `id` is added by
the store. The fixture uses a class with its own `id`.

## 4. Symbolic prototypes (zero calls)

`experiments/detect-01/evaluate.ts` builds the graph in three steps:
1. It runs the instrument's own extractor (`extractAPG`, `V13_APG2_OPTIONS`), imported read-only.
2. It adds the missing facts from a second ts-morph pass (`lib/extract.ts`):
   - `XCALL`: calls, including calls to interface methods;
   - `DISPATCH`: interface method → implementing class method (class-hierarchy analysis);
   - `SIGNATURE_USES_EXTERNAL`, `PROP_TYPE`, `GUARDS`;
   - the properties `returnShape`, `propShape`, `repoWrite`/`writes`, `messaging`, `isPort` and `identity`.
3. It loads everything into the interpreter's `MemoryGraph` and runs the rule files `rules/*.cypher` on `cypher-interp`,
   the same Cypher-over-facts path the instrument uses.

Roles come from folder conventions (`lib/layers.ts`), not from a spec.

| Rule | Family | Fires when |
|---|---|---|
| X1 | D4 | An application method reaches, through synchronous calls and port dispatch, the write methods of two repositories that persist different identity-bearing domain types, with no outbox, bus or publisher member on either path |
| X1b | D4 | A repository write method takes two or more identity-bearing domain types |
| X2 | H5 | A port method's parameter or return type comes from an external module (vendored `declare module` or `node_modules`) |
| X2b | H5 | A port method's parameter or return type is declared in an adapter |
| X3a | D9 | A published contract (`contracts/`, a context's `index.ts`, an inbound-port view) has a property typed by a domain class |
| X3b | D9 | A public domain method returns an anonymous object with exactly the property names of a contract type (3 or more) |
| X4 | D5 | An application method throws under a numeric or integrality guard on a value it then passes to a domain constructor or method (repository reads excluded). It is tagged *duplicated in domain* when the same normalised guard also stands in a domain class |

## 7. Limits

- **Development data, small n.** There are 9 cases, 11 pairs and 3 controls. The fixtures, detectors and questions
  came from one session that had read the pilot diffs, and X1b was adjusted after missing S1. Nothing here is a
  confirmatory number; held-out cases, written or seeded independently and labelled first, are required.
- **Same vendor.** The pilot generator (Sonnet), the hand reader (a coordinator session), and this session's fixtures
  and semantic judge (Sonnet through `claude -p`) are all Claude. The author's spot check of the hand read is still
  pending on #332.
- **Roles from folder names.** A tree with other conventions makes the rules silent, not wrong. The instrument's spec
  layers should replace `lib/layers.ts` on promotion.
- **Simple flow analysis.** X1 uses class-hierarchy dispatch, so a port with several implementers can create paths that
  never run. X4 follows argument text, not data flow (the vineyard `brix` miss). X3b requires equal property names
  (renamed fields escape it).
- **Layered check is partial.** The v1.4-exploratory snapshots are reconstructed from cassette excerpts. Only the
  Layered reference project is complete.
- **Pilot seed reproducibility (found on the way).** The committed S1 seed on `pilot/hexddd-01` lacks
  `src/application/ports/out/`, which the repository `.gitignore` rule `out/` drops; its negation covers `tests/fixtures`
  only. The step diffs do not apply to the committed seed until `build-seeds.mjs` regenerates it, and the regenerated
  tree matches `seeds.sha256.json`. This is worth a one-line fix on #332, outside this branch.

## 8. Recommended detections to promote (after Study 2b is scored)

These are proposed for after Study 2b is scored, as a versioned instrument change with an ADR. Each needs its tier set
a priori and an evaluation on held-out cases first. **Never retroactive to 2b.**

1. **Extractor option for calls through ports**: XCALL to interface methods, plus DISPATCH. It is off by default, like
   `memberFacts`, and is the precondition of D4. Cost: one ts-morph pass. Risk: class-hierarchy dispatch over-paths.
2. **D4 cross-aggregate write (X1 + X1b)**: DDD preset only, gated on the declared aggregates rather than an `id`
   heuristic, reporting once per entry method, **advisory** first. It is the best-supported candidate: 3/3 pilot cases
   found at the right step, and every hit outside the pilot is construct-true.
3. **D9 contract leakage (X3a, X3b)**: DDD preset, advisory. X3a, a domain class inside a published contract, is a
   **blocking** candidate after held-out evaluation, because its construct is unambiguous.
4. **H5/D8 external type in a port (X2)**: Hexagonal and DDD, a **blocking** candidate. Its construct is unambiguous, but
   the pilot has no such case, so it needs held-out positives from a vendor-integration step. It also needs
   SIGNATURE_USES (APG v2) or the external-type fact alone.
5. **D5 domain guard in an application service (X4)**: **advisory**. The *duplicated in domain* subclause is the
   stronger signal (both pilot hits had it; the vineyard hit has it too, at low severity).
6. **Semantic questions**: Q-D5 and Q-H5 as C4/C1d questions, with two changes. First, a **delta form** ("introduced
   by this diff") for drift, so that a pre-existing condition does not count (pilot case 1). Second, an explicit
   exclusion of cross-aggregate uniqueness for D5 (n1). Q-D4 and Q-D9 duplicate the symbolic rules on the fixtures and
   are useful as a cross-check, not as detectors. **Q-D3 is not ready**: it did not separate positive from twin.

Not recommended yet: lexical proxies for the H5 mechanism form (`lock`, `transaction` in port names) and an arithmetic
proxy for D3. Both would fire on most report and persistence code.

## 9. Reproduce

The commands below run from the repository root. `<trees>` is a scratch directory with the rebuilt pilot trees (the
seeds from `build-seeds.mjs`, then the step diffs applied with `git apply`).

```
npx tsx experiments/detect-01/evaluate.ts --fixtures
npx tsx experiments/detect-01/evaluate.ts --trees <manifest.json> --out pilot-steps
python3 -I experiments/detect-01/reconstruct-layered.py none-L2__hive-health__rep1__step-05 <dir>
DETECT01_PILOT_TREES=<trees> npx tsx experiments/detect-01/semantic.ts --plan     # 0 calls
DETECT01_PILOT_TREES=<trees> npx tsx experiments/detect-01/semantic.ts --score    # 0 calls; --run replays nothing already answered
python3 -I experiments/detect-01/complementarity.py
```
