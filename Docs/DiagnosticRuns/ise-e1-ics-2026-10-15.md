# ISE on E1: intrinsic consistency vs extrinsic conformance (exploratory), 2026-10-15

Branch `v1.3-ise-e1`, cut from `origin/v1.3` (e8a966d). **Exploratory.** Nothing here is pre-registered, the AI-DLC
workflow was not run, and no result below is a confirmatory test. The question is thesis §16.1: "even without a
spec, LLMs partially follow architectural conventions and then violate them within the same codebase", read through
the §16.8 2×2 grid (intrinsic consistency × extrinsic conformance) on the 65 accepted E1 cells.

## 1. Definitions (fixed and committed before any cell was run)

This section was committed on its own, before the measurement script was run on any E1 cell. Nothing in it was
changed after the results were seen.

### 1.1 Inputs per cell

- **Cell.** Each `status: accepted` run record of `results/e1-grid/runs/` (65: 47 Claude, 18 Codex). The project is
  `<daedalus-e1-outcomes>/<projectId>` (read-only). It is copied to a temporary directory before anything runs.
- **Pinned tsconfig.** As in `scripts/v1.3/e1-v13-evaluate.ts` (ADR-032): `harnessTsconfigText(<dir>)` for the
  directory being analysed, written outside the tree; the agent's own `tsconfig.json`, if any, is ignored.
- **ISE input.** A neutral snapshot (`<tmp>/ise-snap-XXXX/project`) holding only the cell's `src/`, the pinned
  tsconfig for the snapshot directory, and a `node_modules` symlink to the shared generator skeleton install (the same
  symlink the cell has; it is not cell content). `envelope.json`, `generation.json`, `package.json` and the cell path
  (which names the spec level) are not visible to the inferrer.
- **ISE Option 2** (`inferSpec`, preset-first): the classified style with its confidence (the top style's share of
  points), the runner-up, the evidence, and the emitted spec.
- **Given spec.** The E1 task spec of `experiments/e1-grid/plan.json`: `specs/clean-arch.yaml` for both tasks and
  every spec level. A `none` cell was not shown that spec; it was shown only the shared folder-layout sentence of
  every E1 prompt (`src/domain`, `src/application`, `src/infrastructure`, `Docs/generator-protocol.md`). E1 scored
  every cell against `specs/clean-arch.yaml`, so that is the extrinsic yardstick for all levels.
- **Evaluation.** `firewall evaluate --symbolic-only --format json` (v1.3 scoring, the CLI default), the pinned
  tsconfig, the shared Neo4j, once with the given spec (extrinsic) and once with the inferred spec (intrinsic), on the
  same copy. Tiers are those of `src/scoring-engine/rule-tiers.ts` under each spec's own style.

### 1.2 Extrinsic conformance

- **Primary: `ext_ahs`** = `tiers.blockingAhs` of the evaluation under the given spec. `ext_ahs = 1` iff the v1.3
  verdict is pass (no blocking violation).
- Reported alongside: blocking and advisory finding counts, in total and per file (findings ÷ source files), and
  `ext_sites`, the site ratio of §1.3 computed under the given spec.

### 1.3 Intrinsic Consistency Score (ICS)

**Primary: `ICS` (site ratio)** = `1 − min(1, V / N)`, where, under the cell's **own inferred spec**:

- **N, checked dependency sites**: the distinct ordered pairs `(a, b)` such that `a` is a `src/` file with a layer
  under the spec (the firewall's own `annotateNodes` over the spec's layer directories and file patterns) and `b` is
  either another `src/` file that `a` imports or re-exports from (the ISE graph's file edges), or an external package
  that `a` imports. Within-layer edges count; edges from unlayered files do not.
- **V, violated sites**: the distinct sites named by the evaluation's **blocking** findings. A finding with a target
  contributes `(filePath, target)`; an FF-S02 cycle finding contributes every consecutive pair of its cycle path; a
  blocking finding with no target contributes one site per `(filePath, ruleId)`. Sites are deduplicated across rules.
  A blocking finding that is not an import (e.g. a port-placement fact) still counts in V; this is conservative (it
  can only lower ICS).
- ICS is **n/a** when `N = 0`.

**Secondary: `ICS_ahs`** = `tiers.blockingAhs` of the evaluation under the inferred spec (the same metric as
`ext_ahs`, so the two axes can also be compared on one scale).

Reading: ICS = 1 means that no checked dependency site breaks a blocking rule of the style the code itself appears to
follow. ICS < 1 means that the code adopts a convention (enough to be classified and mapped) and then violates it at
the stated fraction of its own sites, which is the §16.1 "partially follow, then violate" pattern.

### 1.4 Style match and abstention

- **Style match** = the ISE best style equals `clean-architecture`, the style of the given spec. For `none` cells
  this is "did the model, unprompted by a spec, build what the E1 scorer assumed", not "did it obey".
- ISE has no abstention of its own: with no evidence it returns `clean-architecture` at confidence 0.20. **ISE is
  counted as abstaining** (the §6.4 gate of the ISE prototype note, fixed here before the runs) when any of these
  holds: the total style points are 0; the top confidence is below 0.60; the top two styles tie on points. Abstaining
  cells are still evaluated with the spec ISE emitted; they are flagged in every table and every grid is also given
  without them. Units mapped by structure only (no token support) are counted per cell and reported.

### 1.5 2×2 grid (thresholds fixed in advance)

- **High ICS** ⇔ `ICS ≥ 0.95` (at most one in twenty of the cell's own checked sites breaks its own inferred rule).
- **High extrinsic** ⇔ `ext_ahs = 1` (v1.3 pass verdict under the given spec).

| | high extrinsic | low extrinsic |
|---|---|---|
| **high ICS** | consistent and conformant | consistent but a different (or wrong) style: §16.8 "consistent but wrong" |
| **low ICS** | conformant on the given rules, inconsistent on its own: rare by construction | partially follows, then violates |

Sensitivity grids, reported but not primary: (i) `ICS_ahs = 1` × `ext_ahs = 1`; (ii) `ICS ≥ 0.95` × `ext_sites ≥ 0.95`.
Cells with ICS n/a are counted in their own row.

### 1.6 Reporting and determinism

- Tables by spec level (`none`, `minimal-prose`, `full-aac`) × model (four models): cells, style-match rate,
  abstentions, mean ICS, mean `ICS_ahs`, mean `ext_ahs`, mean blocking and advisory findings per file.
- The `none` cells individually: the inferred style, confidence, runner-up, evidence, and ICS.
- The E1 "no spec scores best" reversal (`Docs/DiagnosticRuns/e1-size-analysis-2026-10-10.md`) is discussed
  descriptively only. No hypothesis test is presented, and no p value is computed.
- Determinism: five cells (one per model at least, including `none` cells) are run a second time from fresh copies,
  and the ISE output, both inferred specs and both finding sets (ids and rows, excluding timings) are compared byte
  for byte.
