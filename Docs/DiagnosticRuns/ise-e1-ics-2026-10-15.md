# ISE on E1: intrinsic consistency vs extrinsic conformance (exploratory), 2026-10-15

Branch `v1.3-ise-e1`, cut from `origin/v1.3` (e8a966d). **Exploratory.** Nothing here is pre-registered, the AI-DLC
workflow was not run, and no result below is a confirmatory test. The question is thesis §16.1: "even without a
spec, LLMs partially follow architectural conventions and then violate them within the same codebase", read through
the §16.8 2×2 grid (intrinsic consistency × extrinsic conformance) on the 65 accepted E1 cells.

## 1. Definitions (fixed and committed before any cell was run)

This section was committed on its own, before the measurement script was run on any E1 cell. Nothing in it was
changed after the results were seen.

### 1.1 Inputs per cell

- **Cell.** Each `status: accepted` run record of `results/e1-grid/runs/` (65: 47 Claude, 18 Codex). The project is
  `<daedalus-e1-outcomes>/<projectId>` (read-only). It is copied to a temporary directory before anything runs.
- **Pinned tsconfig.** As in `scripts/v1.3/e1-v13-evaluate.ts` (ADR-032): `harnessTsconfigText(<dir>)` for the
  directory being analysed, written outside the tree; the agent's own `tsconfig.json`, if any, is ignored.
- **ISE input.** A neutral snapshot (`<tmp>/ise-snap-XXXX/project`) holding only the cell's `src/`, the pinned
  tsconfig for the snapshot directory, and a `node_modules` symlink to the shared generator skeleton install (the same
  symlink the cell has; it is not cell content). `envelope.json`, `generation.json`, `package.json` and the cell path
  (which names the spec level) are not visible to the inferrer.
- **ISE Option 2** (`inferSpec`, preset-first): the classified style with its confidence (the top style's share of
  points), the runner-up, the evidence, and the emitted spec.
- **Given spec.** The E1 task spec of `experiments/e1-grid/plan.json`: `specs/clean-arch.yaml` for both tasks and
  every spec level. A `none` cell was not shown that spec; it was shown only the shared folder-layout sentence of
  every E1 prompt (`src/domain`, `src/application`, `src/infrastructure`, `Docs/generator-protocol.md`). E1 scored
  every cell against `specs/clean-arch.yaml`, so that is the extrinsic yardstick for all levels.
- **Evaluation.** `firewall evaluate --symbolic-only --format json` (v1.3 scoring, the CLI default), the pinned
  tsconfig, the shared Neo4j, once with the given spec (extrinsic) and once with the inferred spec (intrinsic), on the
  same copy. Tiers are those of `src/scoring-engine/rule-tiers.ts` under each spec's own style.

### 1.2 Extrinsic conformance

- **Primary: `ext_ahs`** = `tiers.blockingAhs` of the evaluation under the given spec. `ext_ahs = 1` iff the v1.3
  verdict is pass (no blocking violation).
- Reported alongside: blocking and advisory finding counts, in total and per file (findings ÷ source files), and
  `ext_sites`, the site ratio of §1.3 computed under the given spec.

### 1.3 Intrinsic Consistency Score (ICS)

**Primary: `ICS` (site ratio)** = `1 − min(1, V / N)`, where, under the cell's **own inferred spec**:

- **N, checked dependency sites**: the distinct ordered pairs `(a, b)` such that `a` is a `src/` file with a layer
  under the spec (the firewall's own `annotateNodes` over the spec's layer directories and file patterns) and `b` is
  either another `src/` file that `a` imports or re-exports from (the ISE graph's file edges), or an external package
  that `a` imports. Within-layer edges count; edges from unlayered files do not.
- **V, violated sites**: the distinct sites named by the evaluation's **blocking** findings. A finding with a target
  contributes `(filePath, target)`; an FF-S02 cycle finding contributes every consecutive pair of its cycle path; a
  blocking finding with no target contributes one site per `(filePath, ruleId)`. Sites are deduplicated across rules.
  A blocking finding that is not an import (e.g. a port-placement fact) still counts in V; this is conservative (it
  can only lower ICS).
- ICS is **n/a** when `N = 0`.

**Secondary: `ICS_ahs`** = `tiers.blockingAhs` of the evaluation under the inferred spec (the same metric as
`ext_ahs`, so the two axes can also be compared on one scale).

Reading: ICS = 1 means that no checked dependency site breaks a blocking rule of the style the code itself appears to
follow. ICS < 1 means that the code adopts a convention (enough to be classified and mapped) and then violates it at
the stated fraction of its own sites, which is the §16.1 "partially follow, then violate" pattern.

### 1.4 Style match and abstention

- **Style match** = the ISE best style equals `clean-architecture`, the style of the given spec. For `none` cells
  this is "did the model, unprompted by a spec, build what the E1 scorer assumed", not "did it obey".
- ISE has no abstention of its own: with no evidence it returns `clean-architecture` at confidence 0.20. **ISE is
  counted as abstaining** (the §6.4 gate of the ISE prototype note, fixed here before the runs) when any of these
  holds: the total style points are 0; the top confidence is below 0.60; the top two styles tie on points. Abstaining
  cells are still evaluated with the spec ISE emitted; they are flagged in every table and every grid is also given
  without them. Units mapped by structure only (no token support) are counted per cell and reported.

### 1.5 2×2 grid (thresholds fixed in advance)

- **High ICS** ⇔ `ICS ≥ 0.95` (at most one in twenty of the cell's own checked sites breaks its own inferred rule).
- **High extrinsic** ⇔ `ext_ahs = 1` (v1.3 pass verdict under the given spec).

| | high extrinsic | low extrinsic |
|---|---|---|
| **high ICS** | consistent and conformant | consistent but a different (or wrong) style: §16.8 "consistent but wrong" |
| **low ICS** | conformant on the given rules, inconsistent on its own: rare by construction | partially follows, then violates |

Sensitivity grids, reported but not primary: (i) `ICS_ahs = 1` × `ext_ahs = 1`; (ii) `ICS ≥ 0.95` × `ext_sites ≥ 0.95`.
Cells with ICS n/a are counted in their own row.

### 1.6 Reporting and determinism

- Tables by spec level (`none`, `minimal-prose`, `full-aac`) × model (four models): cells, style-match rate,
  abstentions, mean ICS, mean `ICS_ahs`, mean `ext_ahs`, mean blocking and advisory findings per file.
- The `none` cells individually: the inferred style, confidence, runner-up, evidence, and ICS.
- The E1 "no spec scores best" reversal (`Docs/DiagnosticRuns/e1-size-analysis-2026-10-10.md`) is discussed
  descriptively only. No hypothesis test is presented, and no p value is computed.
- Determinism: five cells (one per model at least, including `none` cells) are run a second time from fresh copies,
  and the ISE output, both inferred specs and both finding sets (ids and rows, excluding timings) are compared byte
  for byte.

## 3. Results (definitions of §1)

### 3.1 The inferred spec is the given spec

Every one of the 65 cells has exactly three top-level units: `src/domain/`, `src/application/` and
`src/infrastructure/`. Nine Haiku cells also have one root entry file (`src/index.ts` or `src/server.ts`), which gets
no layer under either spec. ISE classifies all 65 cells as `clean-architecture` and keeps the preset globs unchanged.
The emitted spec is therefore `specs/clean-arch.yaml` up to comments and quoting: the same rules, thresholds and layer
globs, and the same per-file layer assignment in all 65 cells. The two evaluations of a cell return identical finding
sets. **By construction, intrinsic consistency equals extrinsic conformance on this grid.**

This follows from the E1 protocol. Every prompt, `none` included, carries the shared folder-layout sentence
(`src/domain`, `src/application`, `src/infrastructure`; `Docs/generator-protocol.md`). The classifier takes 6 of its 8
clean-architecture points from those directory tokens. So a `none` cell got no spec, but it did get the directory
names of the style it was scored against.

### 3.4 `none` cells: chosen style and self-consistency

- **Style.** All 21 `none` cells are clean-architecture. Nineteen are at confidence 1.00, from the directory tokens
  (+6) and dependency inversion, with cross-unit `implements` pointing inward (+2). The other two are Haiku cells
  (task-management run-0 with 4 files; order-fulfilment run-0 with 13 files). They are at 0.75, with **layered** as
  the runner-up at 0.25. Both have the three directories but no cross-unit `implements`, so the structural evidence
  reads "a 3-level chain without dependency inversion". In these two cells the model used the clean-architecture
  folder names from the prompt and built a layered dependency structure.
- **Self-consistency.** ICS = 1.000 in all 21. The `none` projects are small (4 to 15 files, median 8) but not flat:
  every one uses the three layer directories.
- **Abstention.** ISE abstained on no cell. The lowest confidence was 0.75 (the two Haiku cells), every cell had style
  evidence, and no top tie occurred. **This run could not test whether ISE is confident on small flat no-spec
  projects or abstains, because no E1 project is flat.** On a flat project (no directories) the token points would be
  0. ISE would then return `clean-architecture` at confidence 0.20, or rest on structure alone, and the §1.4 rule
  would count that as an abstention. It did not happen here.

## 4. Does this explain the E1 "no spec scores best" reversal?

**No, not through ICS.** Two facts settle it, descriptively:

1. **Under v1.3 blocking scoring there is no reversal to explain.** `ext_ahs` is 1.000 at every level for every model.
   The E1 reversal (`ahsCombined` on the Claude arm: 0.951 for `none`, 0.887 for `minimal-prose`, 0.920 for
   `full-aac`) lies entirely in rules that v1.3 tiers as **advisory**. The size analysis attributes it to FF-C02
   module-fan-out, FF-P02 dependency-inversion and FF-C06. In this run's advisory findings:

   | Rule | none | minimal-prose | full-aac |
   |---|---|---|---|
   | FF-C02 | 0/21 cells | 15/22 | 6/22 |
   | FF-P02 | 2/21 | 11/22 | 6/22 |
   | FF-C06 | 0/21 | 4/22 | 2/22 |
2. **ICS is identical to the extrinsic score here** (§3.1). It cannot separate "the model chose a different style" from
   "the model broke its own style". Every model at every level chose the scored style (the folder sentence ensured
   that) and broke none of its blocking rules.

## 5. Post-hoc supplement: style-free self-deviations (ISE Option 1)

**Status: post-hoc.** This analysis was decided after §3 came out degenerate, and it is not part of the §1
definitions.

ISE Option 1 (majority vote, no style, no preset) was run on each cell's own graph. Every mined rule that at least 60%
of its instances follow was then applied back to the same cell. A rule with support below 1 is a convention that most
of the cell follows and that the same cell breaks elsewhere: the literal §16.1 pattern. The closed-world allowlist is
excluded, because its support is 1 by construction.

| Spec level | Cells | Cells with a partial rule (excl. framework-free) | Partial direction / acyclic / implements-port rules | Partial inject-interfaces rules (deviating injections / all) | Self-deviation rate (excl. framework-free) |
|---|---|---|---|---|---|
| none | 21 | **0/21** | 0 / 0 / 0 | 0 of 14 applying (0/54) | 0.000 |
| minimal-prose | 22 | **15/22** | 0 / 0 / 0 | 15 of 15 applying (53/164) | 0.028 |
| full-aac | 22 | **10/22** | 0 / 0 / 0 | 10 of 17 applying (37/188) | 0.019 |

Per model and per cell: `results/v1.3-ise-e1/option1.md`.

- **Where the self-inconsistency is.** No cell has a minority dependency direction between units, an import cycle,
  or a `*Repository` outside the core that skips its port. The only convention that cells follow partially is
  **constructor injection through interfaces**. For example, in opus task-management minimal-prose run-0, 11 of 14
  cross-unit injections target an interface and 3 target a concrete class. This is the construct of FF-P02, one of the
  advisory drivers of the E1 reversal.
- **By level.** In the `none` cells the injection convention is all-or-nothing. Fourteen cells inject only
  interfaces and 5 have no cross-unit injection. The 2 Haiku cells of §3.4 inject only concrete classes (0/7 and 0/2);
  that is below the majority threshold, so it is no rule. The spec-prompted cells mix the two. The mean share of
  cross-unit injections that target an interface is:

  | Arm | none | minimal-prose | full-aac |
  |---|---|---|---|
  | Claude | 0.83 | 0.60 | 0.71 |
  | Codex | 1.00 | 0.68 | 0.78 |
- **Size caveat.** The applying `none` rules cover about 4 injections per cell, against about 11 at the spec levels. A
  cell with 3 injections has less room to be partial than one with 15. This is the same size-on-the-path issue the size
  analysis raises, and it cannot be separated here.
- **Reading (descriptive only).** On E1, §16.1 appears only in this advisory, style-free form, and in the opposite
  direction from "even without a spec". The spec-prompted generators adopt dependency injection through interfaces,
  then inject concrete classes in some places of the same codebase. The `none` generators either do it uniformly or
  not at all. This fits the P02 part of the E1 reversal: the spec makes the models attempt a convention that they then
  apply inconsistently. It does not account for the FF-C02 (fan-out) part, which is a size and structure effect. No
  test was run, and nothing here is confirmatory.

## 6. Threats and limits

- **Construct collapse.** The E1 grid fixes the layer directory names in every prompt and uses one style. An
  intrinsic-vs-extrinsic contrast needs cells whose own style can differ from the scored one. E1 has none, so §16.8 is
  not tested here. Testing it needs either prompts without the folder sentence or a corpus that was not generated
  against one style.
- **Ceiling.** The v1.3 blocking rules never fire on E1, so ICS has no variance. The probe in §2 shows that the
  instrument is not blind on these graphs, but the ceiling remains.
- **ISE's preset-first mode** keeps the preset globs whenever they match. On projects that use the preset's own names,
  inference is close to a lookup, as the ISE prototype note says of its reference projects. That note's rename probes
  are the stronger test of the inferrer.
- **The §5 supplement is post-hoc.** Its threshold (0.6) is Option 1's own, not one chosen for this question.
  `framework-free` is excluded because Option 1 has no notion of an infrastructure layer that may import `express`.
  Including it would add 17 partial rules in `none`, 3 in `minimal-prose` and 5 in `full-aac`.
- **Small n:** 3 to 6 cells per level × model, two tasks, one style.
