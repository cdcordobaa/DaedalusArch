## Hexagonal trap failures the rules did not see (hand read of the agent diffs)

In 4 of the 6 functional Hexagonal trap failures (f2 vendor port, f14 geocoding; 2 runs each) the agent kept every
vendor import inside the adapter and translated vendor errors, but re-declared the vendor's vocabulary in the core: the
provider's decline codes as a port type (`'insufficient_funds' | 'expired_card' | 'other'`) and the geocoder's match
precisions as a domain field (`'ROOFTOP' | 'STREET' | …`) that the service branches on. No import or type reference
carries the vendor into the core, so the admitted rules (R-H5 checks vendor types in ports) had nothing to see; the
oracle did. This motivated row H11 and rule R-MIRROR (`ops/notes/cn-04-hex-catalog.md`, `cn-05-hex-h11.md`), whose
development checks fire on all four runs; their admission rests on sealed sets only.
