## Measures

1. **Removal rate** per set, per data set (external, wild): removed advisory rows / advisory rows of the `none` run,
   Wilson 95% interval. Also per rule (FF-CV05, FF-C03, FF-C02, FF-C04, FF-SO01/02) and per repository. Rows are
   clustered in repositories, so the interval is a row-level description, not a repository-level inference; the
   per-repository range is reported beside it. An advisory row is a row whose rule is not in the report's
   `tiers.blocking.rules` (the filter's own guard).
2. **Blocking identity** per set, per repository: the JSON of the blocking rows (rows whose rule is in
   `tiers.blocking.rules`), in order, before and after; plus `tiers`, `verdict`, `functionResults` and
   `perDimensionScores` identical. **Pass iff identical on every repository for every set.**
3. **Correctness of removed rows:** pool = the distinct rows (by violation id per repository) removed by any set on
   either data set; sample = the first 40 rows when the pool is ordered by `sha256("20261016:" + projectId + ":" + id)`.
   Run `scripts/v1.3/check-correct.ts` on the sample. Report correct / incorrect / not-checkable. Only FF-CV05
   (`test-file-pairing`) among the filterable rules has a deterministic checker; the other rows are expected to be
   not-checkable, and that is reported, not hidden. A removed row that is *correct* is a presentation loss (a true
   statement the user no longer sees in the main list; it stays in `advisoryFilter.suppressed`), not a defect of the
   filter. Whether it was *meaningful* needs the panel and is not measured here.
4. **In-sample vs out-of-sample table:** #139's advisory-volume reduction on the dev set and E1 (its §4) next to the
   external and wild removal rates of the same set. #139's judge-dismissed share has no out-of-sample counterpart (no
   judge call is allowed tonight); the table says so.

## Reading fixed in advance

- **Blocking identity is the only pass/fail line.** Any non-identical blocking row is a defect and is reported first.
- For each set, the out-of-sample removal rate is read as **"transfers"** when its Wilson interval overlaps or exceeds
  the lower of #139's two in-sample volume reductions (dev, E1), and as **"shrinks out of sample"** when its upper
  bound is below that number. A larger out-of-sample rate is not read as better: without relevance labels, more
  removal can also mean more lost signal.
- Results are reported whatever they are, including null or adverse ones.
