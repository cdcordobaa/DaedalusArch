# v1.3 external set: barrel and long-cycle sensitivity of FF-S02 (B2)

Written 2026-10-16 on branch `v1.3-jury-fixes` (from `origin/v1.3` at `ae0c8d57`). No template, tier or default
changed; no LLM, no Neo4j. Answers mock-defence point B2: of the 208 pooled FF-S02 cycle rows on the 35 external
projects, 189 pass through an `index.ts` barrel. Are those cycles artefacts of barrel files? And does the length bound
of 10 hide longer cycles?

Data: `b2-cycle-collapse.json` in `v1.3-jury-fixes-2026-10-16/`. Script: `scripts/v1.3/cycle-collapse-sensitivity.ts`.

## 1. Collapsing the reported cycles

A cycle row "survives" a collapse when its image visits at least two distinct units. It is then a cycle *between*
folders or components, not one that closes inside a single unit.

- **folder**: the file's directory.
- **component**: the spec layer matched by path (`annotateNodes` on path-only nodes, so decorator-only layering is
  not seen), else `~<top folder>`.

| | All rows | Barrel-routed rows |
|---|---:|---:|
| FF-S02 rows | 208 | 189 |
| survive the **folder** collapse | **172** (83 %) | 163 (86 %) |
| survive the **component** collapse | **134** (64 %) | 133 (70 %) |

Most barrel cycles are not a barrel looping back into its own folder. 163 of the 189 cross folders, and 133 cross
components. The 26 barrel rows that collapse into one folder are the `x.ts → ./index.ts → x.ts` self-imports (for
example adilsonfuxe's `controller.ts ↔ protocols/index.ts`). They are real module cycles too (§3), but they are
local.

Unbounded SCC (Tarjan) on the union of the rows' edges:

| Grain | SCCs | SCCs with more than 10 members |
|---|---:|---:|
| file | 31 | 3 (bank-server 35, neoteric 20, typeplate 12) |
| folder | 14 | 1 (bank-server, 11 folders) |
| component | 7 | 0 |

## 2. Unbounded SCC on the full graph

The cycle rows are bounded twice: simple cycles of length 2–10, and at most `CYCLE_ROW_CAP` = 100 rows. So the
literal-view file graph of every project was rebuilt and SCCs were computed without either bound. The graph used:
the v1.3 extractor, the spec's and FF-S02's exclusions, `IMPORTS` without `viaReExport` plus `RE_EXPORTS`, which is
FF-S02's view.

| | Value |
|---|---|
| Projects with a file SCC (size ≥ 2) | 17 of 35 |
| File SCCs | 42 |
| **File SCCs with more than 10 files** | **5**: bank-server 44, neoteric-nestjs-auth 22, finance-project-ddd 19, talyssonoc-node-api 13, typeplate 12 |
| Folder SCCs (with more than 10 folders) | 43 (6) |
| Component SCCs (with more than 10 components) | 29 (0) |
| Same on the union of both edge views (what `scc-cycles.ts` reads) | identical: 42 file SCCs, 5 above 10 |

Findings:

- **Cycles outside the rule's reach.** ddd-forum (SCCs of 5 and 4), finance-project-ddd (19) and talyssonoc-node-api
  (13) have file SCCs but 0 FF-S02 rows. Their specs come from the DDD preset, which **does not declare FF-S02**. The
  same holds for 7 of the 35 specs in all. These cycles are a spec-scope gap, not a detector miss.
- **Coverage where FF-S02 runs.** On the 14 projects whose spec declares FF-S02 and which have an SCC, 145 of 161
  SCC files lie on at least one reported cycle row. The 16 that do not:
  - **bank-server, 14 files.** Its FF-S02 result is **truncated at the 100-row cap**: its report carries
    `EVAL_003 "Cycle result for FF-S02 truncated at 100 rows"`. The "100 rows" counted in the pooled 208 are a cap,
    not a count. #181 does not mention this. The real number of simple cycles of length ≤ 10 is larger. One SCC
    (44 files) contains them all, and the SCC path reports 5 SCCs where the Cypher rows touch 3 (see B1).
  - **neoteric-nestjs-auth, 2 files.** Its result is not truncated (56 rows) and its longest row has 10 files. So the
    2 SCC files on no reported cycle can only lie on cycles longer than 10 files. These are the only cycles in the
    data that the length bound itself hides.
- **"Longer than 10" at coarser grains.** At folder grain 6 SCCs have more than 10 folders; at component grain none
  does.

## 3. Construct defence: why a cycle through a barrel is a real cycle

FF-S02 reads the literal view (ADR-V13-01): the module graph as written, which tsc and dependency-cruiser also see
(`Docs/DiagnosticRuns/v1.3-default-view-coverage-2026-10-16.md`: 3,717/3,717 edges equal). A barrel is a module.
`export * from './x'` and `export { y } from './y'` are module dependencies with load-order semantics, not
documentation. The mechanism differs by module system:

- **ESM.** A cycle that is evaluated before its bindings are initialised throws. MDN ("JavaScript modules",
  *Cyclic imports*, <https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules#cyclic_imports>) shows
  `import { a } from "./a.js"` in a module that runs first. The result is
  `ReferenceError: Cannot access 'a' before initialization`. Imports through a barrel are linked and evaluated the
  same way, so `controller.ts → index.ts → controller.ts` has the same hazard.
- **CommonJS** (what `tsc` emits for `module: commonjs`, as in most of these NestJS/Express projects). Node.js
  ("Modules: CommonJS modules", *Cycles*, <https://nodejs.org/api/modules.html#cycles>): with circular `require()`
  calls, "an **unfinished copy** of the `a.js` exports object is returned", and "careful planning is required to
  allow cyclic module dependencies to work correctly". A barrel's `export *` compiles to `require('./x')`, so a
  barrel cycle is a `require` cycle. Its symptom is a binding that is `undefined` at import time.
- **Practice.** eslint-plugin-import's `import/no-cycle`
  (<https://github.com/import-js/eslint-plugin-import/blob/main/docs/rules/no-cycle.md>) "ensures that there is no
  resolvable path back to this module via its dependencies". It is unbounded unless `maxDepth` is set, and it makes
  no exception for re-exports or barrels. The rule practitioners use counts these cycles. FF-S02 agrees with it.

All three URLs were fetched and the quoted text checked on 2026-10-16.

The remaining construct question is **severity, not existence**. A same-folder barrel self-import (26 of the 189
barrel rows) is a real cycle with a local, usually harmless, fix. A cross-component barrel cycle (133 rows) couples
components. Reporting the collapsed counts (172 / 134) beside the raw 208 answers the "barrel inflation" objection
without changing the rule.

## Limits

- Component grain uses the spec layers by path only. Projects layered by decorators fall back to top folders, so the
  component counts are approximate.
- The full-graph SCC answers "is there a cycle through these files", not "how many simple cycles". Simple cycles can
  be exponential in number, which is why the template has a bound and a cap.
- The literal and union views gave identical SCCs on all 35 projects. On these projects the `viaReExport` edges add
  no new cycle.
