## How the blind view was re-scored

The blind manifests themselves are sealed outside the repository (`ue-score.ts --blind <daedalus-sealed/v1.3-blind>`).
Neither `tests/fixtures/v1.3-reference/` nor any committed results directory holds them. What the repository does hold
is what `ue-score.ts` wrote for the run. `blind-misses-rescore.ts` rebuilds the blind-expanded key of every variant
from that:

- every row of `adjudication.csv` with `blind = finding` and `scope = scored` (the sheet lists every row any source
  disagrees on);
- plus every scoped tool row of `raw/` that the sheet does not list as `tool = finding, blind = none` (rows all three
  sources agree on are not on the sheet).

**Check.** The rebuilt key reproduces the committed `scores.json` blind-expanded counts exactly, blocking and all
rules, in all five styles. The script refuses to run otherwise. With Q8 B it gives 50/64 and 50/54, equal to
`ffp06-na-recount.mjs`. Matching is `ue-score.ts`'s: one-to-one, exact targets first, cycles keyed on their sorted
file set.

**Not rebuilt.** The blind-primary view needs each agreed row's basis (primary or alsoMatches), and the sheet does
not record that for agreed rows. It is not re-scored here.

**Engine.** Offline, no Neo4j. The saved rows of `after-member-facts` go through `rescore()`
(`lib/construct-rescore.ts`). That applies the switch compile hook, the row stage (the pipeline's own
`applyConstructRows`) and the switch-aware tiers. Each variant's graph is re-extracted in-process. Every answer set
includes **Q8 B**, the FF-P06 FLOWS_TO N/A correction. The author view is the rescore's own metrics, so it is
cycle-normalised.

Under Q5 C or D, the blind key is renamed the way the author key is. Adapter → adapter FF-S03 rows take the new id.
Under D, the blind FF-S01 adapter → adapter rows (the blind reader's id for adapter isolation) also become FF-S05.

```sh
node --import tsx scripts/v1.3/blind-misses-rescore.ts --base results/v1.3-reference/after-member-facts \
  [--graph-cache <file>] [--json <file>]
```

## What was not done, and why

- **No extractor fix and no extractor option**: there is no class (a) row (see the summary).
- **No new construct switch**: every class (b) row maps to a question that already has a code switch. The one row
  no switch recovers (#8) needs a nestjs preset change (`@nestjs/common` in FF-P01 `forbidden_imports`) and a target
  convention for transitive purity. Both are construct decisions for the author, which this unit does not make.
- **No re-run with Neo4j.** No extractor option was added and no switch changed, so the offline re-score is the
  complete measurement. `--engine cypher-interp` was not needed.
- **Blind-primary view**: not re-scored (see the method section).
