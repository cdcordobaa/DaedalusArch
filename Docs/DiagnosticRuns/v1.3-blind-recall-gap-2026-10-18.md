## 1. How each row was classified

The split between (b) and (c) uses a rule fixed in advance: the literature recommendation of
`Docs/v1.3/construct-decisions.md` (revision 1, 2026-10-15). That file argues each question from the style-rule sources
and its principles P1 (the source wins over a rule's wording) and P2 (one fact, one rule), before any score target was set.

- **(b)**: the recommendation agrees with the blind reader. The tool then departs from its own construct source, so this is a rule or template defect.
- **(c)**: the recommendation agrees with the tool. The blind reader applied a reading that the sources do not support, or applied it to some cases and not to others where the same construct holds.

This rule does not depend on which choice raises recall. All the questions are still unanswered (`[Answer]:` is empty
at `Docs/v1.3/construct-decisions.md:201, 232, 258, 284, 382, 433, 469, 651`).

## 7. Overfitting guard

- **What counts as a fix.** Only the four class (b) switches, each because the recommendation in
  `construct-decisions.md` argues it from the sources (P1/P2), not from these rows. That file was written with sight of
  the development effects, so each is a **post-seal construct change** and must be a declared deviation, with an ADR,
  in G14's single list (`ops/03-gap-closing-plan.md:105`).
- **Excluded as tweaks**: Q4 B scoped to one style; adding `@nestjs/common` to the NestJS FF-P01 list to catch #8;
  any package list beyond the minimum Q10 C needs; any of Q4 B, Q7 B or Q20 B adopted to match the blind key.
- **Fresh checks needed** (development or external material, never the sealed hold-out):
  - **Q5 D**: re-score the MO-H03 seeds (inbound → outbound adapter, 10 reference and 30 real, twins 0/6 and 0/18;
    `Docs/DiagnosticRuns/v1.3-operators-hexddd-2026-10-16.md:76-90`; `Docs/v1.3/operator-catalogue-hexddd.md:18`). Expect FF-S05 on every seed and none on twins.
  - **Q6 B**: re-score the MO-H02 seeds (a use case injects a concrete outbound adapter; `operator-catalogue-hexddd.md:16`)
    with FF-S04 added to the expected rules, and check for no new rows on the twins.
  - **Q10 C/D and Q12 B**: re-run on the 5 external layered repositories
    (`Docs/DiagnosticRuns/v1.3-external-set-3-2026-10-16.md:54-58`). Their FF-P01 and FF-S03 rows (for example
    q00-api-server FF-S03 8 and FF-P01 2; bymi15-express-typeorm FF-S03 5 and FF-P01 4; `:124-126`) are the rows these
    switches remove. If the external correctness labels judged them correct and meaningful, that counts against the switch.
  - **N33/N38 (G04/G05)**: one development re-run after they land, to confirm no blind row moves (§2).
- **Never consult the sealed hold-out** or the sealed blind manifests to choose or check any of these. The development
  blind key is read only through `ue-score.ts` outputs.
- **One loop.** Apply the chosen answers once, re-run the development set once, then freeze. Do not iterate on the
  development blind figures (`Docs/v1.3/construct-switches.md:23-24`).
