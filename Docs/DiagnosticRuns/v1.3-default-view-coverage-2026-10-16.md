# v1.3 default-view coverage on the external set, 2026-10-16

Branch `v1.3-default-view-coverage`, cut from `origin/v1.3` at `4339bad5`. This is an exploratory diagnostic that follows up the graph-fidelity result of PR #133 (`Docs/DiagnosticRuns/v1.3-external-set-2026-10-16.md` on branch `v1.3-external-set`). It adds no AI-DLC workflow and no pre-registration, and `aidlc-docs/` is untouched.

**The question.** PR #133 reported two results:
- the v1.3 literal graph view matches tsc and dependency-cruiser exactly (3,717/3,717 edges);
- the "default graph that `evaluate` uses" (`apg-v12e-default`) reaches only 0.926 coverage and 0.904 confirmation pooled, and 9 projects are between 0.67 and 0.89.

This run reproduces the gap, classifies every edge in it, and decides for each class whether it is an extractor bug or a view choice under ADR-V13-01.

## Summary

1. **Reproduced exactly.** The `apg-v12e-default` graph gives 3,443 of 3,717 tsc edges and 3,810 APG edges: coverage 0.926, confirmation 0.904. The per-project figures match #133 on all 15 projects.
2. **`firewall evaluate` does not use that graph.** This corrects the premise of #133.
   - The pipeline's `ExtractCommand` calls `extractAPG` with `V13_DEFAULT_OPTIONS`. That turns on `reExportEdges: 'both'` and `dynamicImports`.
   - `CompileCommand` compiles with `V13_COMPILE_OPTIONS`, which turns on edge views.
   - So each template reads its ADR-V13-01 view. The 13 literal-view templates (direction, cycles, layer skip, metrics, context isolation) read a graph that matches tsc at **1.000 / 1.000** on all 15 projects.
   - `apg-v12e-default` is the frozen v1.2E instrument's graph. The harness measures it as its first variant, explicitly with `V12E_DEFAULT_OPTIONS`.
   - The same was true at the tool commit #133 ran (`133c261a`).
   - A new unit test pins this (`tests/unit/pipeline/extract-command-v13-graph.test.ts`).
3. **Every edge in the gap has a known cause:**
   - 274 missing and 367 extra edges in total;
   - 270 + 367 are **barrel routing**;
   - 4 are **CommonJS `require`**;
   - 0 are dynamic import, 0 are caused by a path alias, 0 are "other".
4. **No extractor bug was found.** An independent oracle asked the TypeScript checker (`getAliasedSymbol`) for the declaring file of all 3,906 named and default imports of project files. The resolved view agreed on every one, including the 386 that route through a re-export, across 1, 2 and 3 barrel hops.
5. **Both classes are view choices, and their options already exist.**
   - Barrel routing is `reExportEdges` (ADR-V13-01). `require` is `dynamicImports`.
   - Both are OFF in `V12E_DEFAULT_OPTIONS` (the frozen instrument) and ON in `V13_DEFAULT_OPTIONS` (what `evaluate` uses).
   - **No new option was added**, because one would duplicate these two (§5).
6. **No source change.** `src/` is untouched, so the 71 reference cases are byte-identical by construction (§7).
7. **The same findings on the current engine.** `evaluate --engine cypher-interp` on the current `v1.3` head reproduces all 1,238 findings of #133 (Neo4j 5.26.24) row for row. The verdict and `graphStats` match on all 15 projects.
8. **What the view choice changes in the findings:**
   - 55 FF-S02 cycle rows pass through an `index.ts` barrel;
   - 6 layer rows have a barrel as their target;
   - 0 rows of the 4 resolved-view templates sit on a routed edge.
   - These are construct questions for the author (§8). Nothing here needs a fix.

## 3. Which graph `evaluate` reads

**The code path:**
- **Extraction.**
  - `src/pipeline/pipeline-factory.ts` builds `new ExtractCommand(projectPath, specExcludePaths, graphMode, tsconfigPath)`.
  - `ExtractCommand` calls `extractAPG(path, { excludePatterns, graphMode? }, tsconfig)`.
  - `extractAPG` merges those options over `DEFAULT_OPTIONS`, which is `V13_DEFAULT_OPTIONS` (`src/apg-extractor/types.ts`).
  - No `evaluate` flag selects `V12E_DEFAULT_OPTIONS`. `--rules`, the scoring mode and the instrument version change compilation and scoring, not extraction.
- **Compilation.**
  - `CompileCommand` compiles with `{ ...V13_COMPILE_OPTIONS, instrumentVersion }`, and `edgeViews: true`.
  - So `applyEdgeView` gives each template its view from `TEMPLATE_EDGE_VIEWS` (`Docs/v1.3/edge-views.md`).
- **At the #133 tool commit.** Both lines are the same at `133c261a`, where #133 ran (`git show 133c261a:src/apg-extractor/types.ts`, `…/compile-command.ts`).

**Evidence in the output:**
- **neoteric-nestjs-auth.** #133 counted 53 FF-S02 cycle rows whose path passes through an `index.ts` barrel. Under the v1.3 views, such a cycle runs over the literal edges into the barrel, which the `'resolved-only'` graph drops.
- **Row-for-row match.** `results/v1.3-default-view-coverage/evaluate-crosscheck.json` compares the `cypher-interp` run on `4339bad5` with the Neo4j reports of #133.
  - The key is functionId, filePath, target, message, severity and line.
  - Result: 1,238 / 1,238 rows identical, the same verdicts, and equal `graphStats` (IMPORTS edge counts included) on all 15 projects.

**The regression test.** `tests/unit/pipeline/extract-command-v13-graph.test.ts` runs the real (unmocked) `ExtractCommand` on a temporary project with an `export *` barrel and a `require()` call. It asserts three edges:

## 4. Classification of every missing or unconfirmed edge (v1.2E default view)

- **barrel**: the literal edge carries `reExportHop` (a missing edge), or every v1.3 occurrence of the edge carries `viaReExport` (an extra edge).

### Barrel resolution, by construct

Missing edges are the literal importer → barrel edge. Extra edges are the routed importer → declaring-file edge.

| Construct (first barrel) | Specifier | Chain | Missing | Extra |
|---|---|---:|---:|---:|
| `export * from` | relative | 1 | 155 | 213 |
| `export * from` | alias (`paths`/`baseUrl`) | 1 | 68 | 87 |
| `export * from` | relative | 2 | 23 | 30 |

| `export { A } from` (named) | relative | 1 | 17 | 19 |

**Reading the construct table:**
- **Missing and extra counts differ** because one import of several names through a barrel gives one missing edge and one extra edge per declaring file.
- **`export *` dominates**, at 247 of 270 missing edges. That fits the projects' `index.ts` files: neoteric, finance-project-ddd and zeldaplay re-export whole folders.
- **No renamed or namespace re-exports.** None occurs on an import path in this set. The resolver's handling of both is covered by `fixtures/unit/v13-barrels` (`tests/unit/apg-extractor/v13-reexport-edges.test.ts`).
- **Alias specifiers resolve correctly.** 69 missing edges are barrels reached through an alias specifier: finance-project-ddd 62 (`@shared/*`, `@modules/*`), conduit 5 and ddialar 2. The literal view resolves every one of them to the same barrel tsc does (1.000 / 1.000). The alias decides only how the barrel is reached, not whether the edge exists, so "path alias" is **not a cause** of any gap edge. Path aliases are the right column of the table, not a class.

### CommonJS `require`

All 4 edges are string-literal `require()` calls. Each is an IMPORTS edge with `dynamic: true` under `V13_DEFAULT_OPTIONS`, so the literal and resolved views both cover them.

## 5. Decision per class

| Class | Bug or view choice | Where it lives | Default on `v1.3` (`evaluate`) | Frozen v1.2E |
|---|---|---|---|---|
| Barrel resolution (all constructs above) | **(b) view choice**, ADR-V13-01 | extractor option `reExportEdges` (`'resolved-only'` / `'both'`); per-template view in `TEMPLATE_EDGE_VIEWS` | `'both'`, each template reads its view | `'resolved-only'` |
| CommonJS `require` | **(b) view choice**, FR-V1 | extractor option `dynamicImports` | on | off |
| Dynamic import | **(b)**; none on this set | `dynamicImports` | on | off |
| Path aliases | not a cause (resolved correctly) | — | — | — |
| Other | none | — | — | — |

**Why no bug.**
- **Missing edges.** Each one is the literal edge that `'resolved-only'` drops on purpose.
- **Extra edges.** Each one goes to the file the TypeScript checker names as the declaring file. 386 of 386 routed imports agree with `getAliasedSymbol`, and so do the 3,520 non-routed ones.
- **Require edges.** Each one is a call that `dynamicImports` models and the frozen instrument does not.

**Why no new option.** The task asks for every view-choice fix to go behind an extractor option that is OFF by default. That condition already holds, and adding a third flag would only duplicate it:
- the fixes are `reExportEdges: 'both'` and `dynamicImports: true`;
- both are OFF in the frozen `V12E_DEFAULT_OPTIONS`, which `main` and `v1.2e` keep;
- both are already ON in `V13_DEFAULT_OPTIONS`, a default ADR-V13-01 and FR-V1 set before this run.

What remains open is a question about views, not extractors (§8, Q-DV1).

## 8. Construct questions for the author

The 4 questions are listed below; they are not decided here. Counts are from `evaluate-crosscheck.json`, on the 1,238 external-set rows.

- **Q-DV1. Should the four usage templates keep the resolved view?**
  - The templates are `domain-purity` (FF-P01 / FF-DT04), `controller-no-entity`, `aggregate-boundary` (FF-DT01) and `repository-aggregate-root` (FF-DT02).
  - ADR-V13-01 puts them on the resolved view, so a name used through a barrel counts as a use of the declaring file. That view is 0.927 / 0.904 against tsc, by design.
  - On this set, their 57 rows (FF-P01 15, FF-DT04 13, FF-DT01 23, FF-DT02 6) include **none** on a routed edge. No row would change either way.
  - Options:
    - **(A)** keep ADR-V13-01 as is;
    - **(B)** move them to the literal view (a `TEMPLATE_EDGE_VIEWS` change, not a template edit);
    - **(C)** read both: a row when either view has the edge.
  - Recommendation: **(A)**. The data gives no reason to change it.
- **Q-DV2. Barrel-induced cycles.**
  - 55 FF-S02 rows name an `index.ts` in their cycle: 53 in neoteric-nestjs-auth and 2 in vivify-nestjs-boilerplate. FF-S02 is blocking.
  - ADR-V13-01 says a cycle between modules as imported is a finding, even when the barrel creates it.
  - A labeller may judge some of these as artefacts of `index.ts` aggregation rather than design cycles. That is the human labelling sheet's question (#133 `labelling-sheet.csv`), not an extractor one.
  - Confirm the ADR, or open a variant that drops `reExportHop` edges from `no-cyclic-deps`.
- **Q-DV3. Layer rows whose target is a barrel.**
  - 6 rows have an `index.ts` barrel as their target:
    - talento90: FF-S01 ×2 and FF-S03 ×2 (`repositories/*` → `entities/index.ts`);
    - conduit: FF-S03 ×1 (`ports/express/server.ts` → `ports/adapters/db/index.ts`);
    - ddd-forum: FF-S01 ×1 (`redisAuthService.ts` → `config/index.ts`).
  - The barrel's layer decides each of these rows. Under the literal view that is ADR-V13-01's intent: "the module an import statement depends on is what crosses the layer boundary". Confirm.
- **Q-DV4. `require()` and `import()` as dependencies.**
  - The literal and resolved views keep `dynamic: true` edges, so every template reads them, including direction and cycles.
  - That is 4 edges here and 164 in W1.
  - Confirm that a lazy or CommonJS load counts as a module dependency for layer rules, or add a view that drops `dynamic` edges.

## 9. Errata to the #133 report (`v1.3-external-set-2026-10-16.md` §4)

These are for the author of #133 to apply on that branch; this branch does not touch it.

1. **The default graph is mislabelled.** The column header "Default graph (`apg-v12e-default`, used by `evaluate`)" and the sentence "The graph that `firewall evaluate` actually uses differs" are wrong. `evaluate` uses `V13_DEFAULT_OPTIONS` with per-template views (§3). The literal-view templates read the exact graph; `apg-v12e-default` is the frozen v1.2E instrument.
2. **The routed-graph sentence is reversed.** "The findings in §3 were computed on the routed graph" is not true. Only the 4 resolved-view templates read the routed edges (57 rows, none on a routed edge). The cycles through `index.ts` and the layer rows with a barrel target come from the literal view, which is why they exist.
3. **The disagreement classes are correct.** The barrel routing and `require` classes in that table do describe the v1.2E instrument's graph.

## 11. Limitations

- **Only the 15 external projects were re-measured.** For W1 this report relies on the W1 report's own classes (§4); the W1 repositories were not re-cloned.
- **tsc is a second extractor, not ground truth.** So is dependency-cruiser; agreement with them is agreement, not correctness.
- **The checker oracle has narrow reach.** It covers named and default imports of project files. Namespace imports and side-effect imports are not routed by either view, so they have nothing to check.
- **No `node_modules` were installed.** Package-side re-exports are invisible to every tool alike. For example, `event-dispatch` in bulletproof and w3tec reaches a Package node through a project barrel.
- **The reference cases were not re-run.** With no source change, a live run of the 71 reference cases was not made; the identity follows from the unchanged code (§7).
