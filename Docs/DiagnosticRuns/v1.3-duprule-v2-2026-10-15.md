## 4. Reading

- **The twin is now a working control.** With no foreign method, the judge passes the relocation in 7/9 twins. Of the two fails, one is inherited from the base. The other is a fair finding:
  - In sonnet full-aac run-1, once `assertOrderStatus` exists, all 3 runs point out that `AdvanceOrderUseCase` still carries its own inline `isOrderStatus` check with a different message. That is a near-duplicate already in the base, which the shared guard makes visible.
  - The same twin moved a request-worded message ("Query parameter 'status' must be…") into the domain, and the domain-unit runs cite it as a request concern in the domain.
  - So the domain host is not entirely smell-free when the moved rule's *message* is application-flavoured. The operator moves the rule text verbatim by design.
  - This is the one paired twin fail. Pooled, the paired twin false-fail rate is 1/9.
- **The positive is still confounded, and the judge's own words show it.**
  - All 9 seeds fail. In every first run, the violation names the copy ("copies", "repeats … word for word", "duplicates the rule").
  - All 9 also say that the method does not belong to the second service ("puts an order-placement rule into the catalogue service", "does not fit a list query").
  - Round 2 showed that the foreign method alone, with no duplication, fails 5/5.
  - So a v2 catch is consistent with *both* cues. The pair now shows the judge does not fail the rule-relocation machinery. It still cannot show that duplication alone is sufficient. Catalogue §8 records this limit.
  - Isolating duplication would need a positive whose copy sits where the rule plausibly applies. In the E1 cells no such place exists.
- **Strict construct flag.** The round 1 and 2 regex (`duplicat|copied|same (rule|check|validation)|repeat`) fires in ≥ 2 runs on 4/9 seeds and on 0/9 twins. It misses "copies" and "duplicates the rule in", and it is not a catch criterion that changed any row here.
- **The added descriptive measure `duplicationCited` is uninformative.** It is 9/9 for seeds and 9/9 for twins, because it reads the free-text reasoning, and passing runs write negations ("the stock rule itself is not repeated"). It is reported in `scores.json` but should not be cited.
- **Test-retest on identical code.** The 8 E1 seed copies are identical to round 2's. The verdicts are identical too: 8/8 fail in both rounds, with the same unpaired haiku row.

**Why the clone proxy misses the E1 seeds.** A post-hoc diagnostic (`scripts/v1.3/cheap-v2-clone-diagnostic.ts`, written after the frozen run; `clone-diagnostic.posthoc.json`) shows the two filters the proxy was designed with:
- **5 of the 8 E1 rules are bare guards**: `if (!isOrderStatus(s)) throw …` and `if (!request.customerId) throw …`. The fragment density filter drops them (no value comparison or arithmetic). That filter was added on the clean reference projects, where such guards were Type-2 clones across every component (cheap-semantics §6, revision 2).
- **The other 3 do produce a `SAME_LOGIC_AS` exact-structural edge** between the copy and the original. The proxy flags only cross-component pairs, and both use cases sit in the one `application` component of `clean-arch.yaml`, so no flag is raised.
- The fixture seed is caught because `invoice` and `order` are separate components and `quantity <= 0` is a value comparison.

**Twin.**
- The one raw `shared-literals` twin flag is on the gpt cell's own-file twin: the message literal also appears elsewhere in the base. It is inherited, so the paired rate is 0/9.
- The v2 twin leaves no copied fragment and keeps one literal site, so the proxies are silent on it, as on the v1 twin in round 1.

**Three-way reading.** On this construct, the judge is the only instrument that sees the E1 duplications: 9/9 against 2/9 for the proxies and 0/9 for the symbolic rules. Two things temper that:
- the judge's catch is confounded with the foreign-method cue (§4);
- the proxies' clean-control silence comes from the same filters that make them miss intra-component and guard-shaped copies.

The proxies' strength in the earlier cheap-semantics run (DUP-RULE 1/1) was a fixture property: cross-component, with a value comparison.
