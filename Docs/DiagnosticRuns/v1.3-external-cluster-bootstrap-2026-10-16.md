reported with a finding-level Wilson interval, but 3 of the 15 repositories hold 214 of the 283 findings, so the

## Results

`v1.3-external-cluster-bootstrap-2026-10-16.json` beside this file. 10,000 resamples, seed 20261016. The statistic is the
ratio of sums (correct / checked) over a resample of whole repositories.

| Interval (95 %) | Unit | n | Interval |
|---|---|---:|---|
| Wilson (as reported in #167) | finding | 283 | [0.987, 1] |
| Clopper-Pearson | finding | 283 | [0.987, 1] |
| **Cluster bootstrap, percentile** | repository (11 with findings) | 11 | **[1, 1]** |
| Cluster bootstrap, percentile | repository (all 15) | 15 | [1, 1] |
| Wilson, unit = repository ("all its findings correct") | repository | 11 | [0.741, 1] |
| Clopper-Pearson, unit = repository | repository | 11 | [0.715, 1] |
| Wilson without the three largest repositories | finding | 69 | [0.947, 1] |

**Reading.** The cluster bootstrap is degenerate here: with zero incorrect findings every resample has precision 1,
so its interval is [1, 1]. It cannot express uncertainty that the sample does not contain, and it should not be
quoted as "tighter than Wilson". It does not narrow or widen anything; it just has nothing to resample.

The defensible statement under clustering is the repository-level one. All 11 repositories with blocking findings
had every finding correct. If repositories are treated as the independent unit, the 95 % lower bound for "a
repository's blocking findings are all correct" is 0.74 (Wilson) or 0.72 (Clopper-Pearson). Dropping the three
largest repositories leaves 69/69 findings, with a finding-level lower bound of 0.947.

### Sensitivity: one incorrect finding

The bootstrap's behaviour with one error was checked by flipping one finding to incorrect in each repository in turn
(`sensitivityOneIncorrect`). Point estimate 282/283 = 0.9965 in every case.

| Error placed in | Cluster bootstrap 95 % | Finding-level Wilson 95 % |
|---|---|---|
| ddd-forum (92) | [0.992, 1] | [0.980, 0.999] |
| neoteric-nestjs-auth (72) | [0.990, 1] | [0.980, 0.999] |
| finance-project-ddd (50) | [0.988, 1] | [0.980, 0.999] |
| a repository with 1–9 findings | [0.980, 1] to [0.982, 1] | [0.980, 0.999] |

With one error the percentile bootstrap is still no wider than Wilson. Its upper end is 1 because about a third of
resamples leave out the repository that holds the error. With 11 clusters and a rare event, percentile cluster
bootstraps are known to under-cover. **The bootstrap is not a more conservative interval for this data.** The
repository-level bound above is the conservative reading.

## What to report

Report 283/283 with the finding-level Wilson [0.987, 1], and add the clustering explicitly: 11 of 11 repositories
fully correct, repository-level Wilson [0.741, 1], and 69/69 outside the three largest repositories (Wilson
[0.947, 1]). The cluster bootstrap gives [1, 1] and is uninformative at zero errors. #167's own caveat, that the
pooled interval is too narrow, stands.
