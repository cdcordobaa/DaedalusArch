# v1.3 external set: deterministic correctness of the blocking findings (2026-10-16)

> **Exploratory / development-set banner.** This is a precision-of-*correctness* figure on human-written code. Correct is not meaningful; nothing here claims validity on its own.

Backlog job X1 (`Docs/v1.3/night-backlog-2026-10-16.md`, job #3). Input: PR #133 (`origin/v1.3-external-set`, tip `b8492a7a`), read, not merged. Nothing in #133's documents is changed; this report cross-references `Docs/DiagnosticRuns/v1.3-external-set-2026-10-16.md` only.

## 1. Pass criterion (committed before any check was run)

1. **Population.** Every finding whose rule the evaluate report itself places in its blocking tier (`tiers.blocking.rules`), over the 15 repositories of `results/v1.3-external/selection.json`. #133 counts 283. If `ruleTier(ruleId, style)` (which the labelling harness uses) disagrees with the report for any finding, the disagreement is listed and the report's tier wins.
2. **Pass.** All 283 blocking findings carry a label in {correct, incorrect, not-checkable} from `scripts/v1.3/check-correct.ts`, each with the checker's evidence (facts or reason). Anything short of 283 is a fail and is reported as such.
3. **No threshold on precision.** The figure is reported whatever it is, null included. For reference only: on the development set (the 71 reference variants) the checker found 53 of 53 checkable blocking findings correct (`Docs/v1.3/labelling.md` §3).

## 1a. Negative control (added after the first run, before the control was run)

The first run labelled all 283 findings `correct` (§3). A checker that says `correct` to everything would give the same table, so a negative control is added, fixed here before it runs: every blocking finding is perturbed so that its claim is false, without reading rule text (`controlItems` in `scripts/v1.3/lib/external-correctness.ts`):

- **line**: an edge finding's line is moved to another import or re-export statement of the same file that reaches neither the target file nor the target package (skipped when the file has no such statement);
- **target**: an edge finding's target is replaced by its own file;
- **cycle**: a cycle's second file is replaced by a project file (taken from the other findings) that the first file does not import (skipped when none).

**Control pass:** every perturbed finding comes out `incorrect`. Any `correct` or `not-checkable` is listed and counts against the checker's discrimination on this set. Skips are counted. It is in addition to the criterion of §1, not a replacement.

## 2. Analysis (fixed before any check was run)

- **Label** = the checker's verdict, unchanged. The checker reads the source (TypeScript compiler API, each repository's own `tsconfig.json`, no `node_modules`, the same conditions as #133's evaluation) and the spec #133 committed; never the graph.
- **Precision-of-correctness** = correct / (correct + incorrect), per style, per rule (style × `ruleId/template`), per template, per project and pooled, each with a Wilson 95% interval (`scripts/lib/stats.ts` `wilson`). Findings within a project are not independent; the intervals are per-finding and therefore too narrow at the pooled level. The per-project table is given so the reader can see clustering.
- **Not-checkable share** = not-checkable / n per template (and per group). Each not-checkable finding is listed with its reason.
- **Incorrect findings** are listed with one line each (the failing fact).
- **Checker gaps.** Every blocking template on the external set (`dependency-direction`, `no-cyclic-deps`, `no-layer-skip`, `no-domain-outward-dep`, `domain-purity`, `dependency-direction-graph`, `context-isolation`, `aggregate-boundary`, `repository-aggregate-root`) is listed as *full* coverage in `check-correct --coverage`; no checker extension is planned. If one were needed it would be stated from the finding's claim and the source alone, never from rule text.
- **Secondary table.** The 30 advisory findings #133 already drew for its labelling sheet (seed 20261016, `seededSample` over the pooled advisory findings) are checked the same way. Reusing #133's draw instead of a fresh one keeps the human sheet and this table on the same items (option taken under delegation). Most advisory rules are metrics without a deterministic check; they come out not-checkable by design.

Tooling: `scripts/v1.3/external-correctness-jobs.ts` (jobs file and finding lists), `scripts/v1.3/check-correct.ts` (unchanged), `scripts/v1.3/external-correctness-summary.ts` (the analysis above), `scripts/v1.3/lib/external-correctness.ts` (pure functions, unit-tested).

## 4. Limitations

- **Correct is not meaningful.** The checker confirms that the stated import exists at the stated line, reaches the stated target, and that both ends fall where the *spec's* globs put them so as to break the template's condition. Whether an architect would want the dependency changed is a separate question (`label-meaningful`, not run: no vendor key). Post hoc and descriptive only: 6 of the 283 sit in test or mock files (conduit-ports-adapters 1, a `.test.ts.ts` use-case test; finance-project-ddd 5, `application/mocks/`), which a reader may judge not meaningful even though correct.
- **The checker shares the spec with the tool.** A wrong layer glob in a spec produces findings that are *correct under the spec*. All 15 specs were written by one session (#133, `spec-rationale.md`); the spread a second blind spec author would cause is backlog job K2, not measured here.
- **Same team, same conditions.** The checker was written by the same project as the tool (independent code path: TypeScript compiler API against the spec, never the graph, the extractor or the Cypher). It reads the code without `node_modules`, as the tool did; findings that depend on package resolution (domain-purity's package roots) are checked on specifier text, not installed packages.
- **15 repositories, pinned before 2023,** chosen by one session from a named pool (`selection.json` method); 4 contribute no blocking finding and 3 contribute 214 of 283.
- This is the first precision-of-correctness figure on non-Claude-written code; it says nothing about recall (what the tool misses on these repositories).

## 5. Reproduce

```bash
git fetch origin v1.3-external-set
git archive origin/v1.3-external-set results/v1.3-external | tar -x -C <scratch>   # <external> = <scratch>/results/v1.3-external
# clone each selection.json entry into <clones>/<id> and check out its sha
npx tsx scripts/v1.3/external-correctness-jobs.ts --external <external> --clones <clones> --out <out>
npx tsx scripts/v1.3/check-correct.ts --jobs <out>/jobs.json --sample <out>/blocking.json --out <out>/blocking
npx tsx scripts/v1.3/check-correct.ts --jobs <out>/jobs.json --sample <out>/advisory.json --out <out>/advisory
npx tsx scripts/v1.3/external-correctness-summary.ts --dir <out>
npx tsx scripts/v1.3/external-correctness-control.ts --dir <out>
```

`results/v1.3-external-correctness/` holds the outputs (`jobs.json` with the scratch paths replaced by `<clones>` and `<external>`).
