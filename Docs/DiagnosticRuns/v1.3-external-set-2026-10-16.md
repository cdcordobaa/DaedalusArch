# v1.3 external set: human-written, pre-2023 TypeScript backends, 2026-10-16

Branch `v1.3-external-set`, cut from `origin/v1.3` at `133c261a`. This is an exploratory evidence unit: it adds no AI-DLC workflow and no pre-registration, and `aidlc-docs/` is untouched.

**Why this set exists.** Every earlier reference project, answer key and hold-out case was written by Claude-family models, which is a same-vendor threat to validity. This set is 15 real projects, 3 per style. People wrote them before AI coding tools were common, and each is pinned to a commit dated before 2023-01-01.

**What this report does not contain:**
- No precision figures. Every finding is an unlabelled candidate.
- No correctness or meaningfulness verdict by the author of this report. The labelling sheet leaves both columns empty for humans.

Outputs are in `results/v1.3-external/`:

| File | Content |
|---|---|
| `selection.json` | Per project: URL, licence, pinned SHA, style claim, file count, provenance, notes. Also the rejected candidates with reasons. |
| `specs/<id>.yaml`, `spec-rationale.md` | The 15 layer specs and every mapping judgement. These were committed before any tool run (§2). |
| `validate/<id>.txt` | `firewall validate` output, run after the spec commit and before evaluation. |
| `findings/<id>.json` | Full `firewall evaluate --format json` report per project. |

To regenerate: `node --import tsx scripts/v1.3/external-sheet.ts` (seed 20261016).

## 1. Projects

1. Public, with a permissive licence at the pin (MIT, ISC).
2. A TypeScript backend that claims the style in its README or folder structure.
3. Pinned to the last commit before 2023-01-01 on the default branch.
4. 15 to 300 non-test, non-`.d.ts` `.ts` files under `src/` of the analysis root.
5. Not in the Study 1 corpus, and not one of the 14 repositories of the W1 wild job (PR #114, `results/v1.3-wild/selection.json`).
6. Well-known references preferred.

### Evidence that the code predates AI coding tools

- **Pin dates against tool releases.** Every pinned commit predates ChatGPT (2022-11-30). 12 of the 15 also predate the general availability of GitHub Copilot (2022-06-21). The three exceptions:
  - **conduit:** pinned 2022-06-29, eight days after Copilot GA. The repository is a fork of Fernando Daciuk's MIT boilerplate `fdaciuk/nodejs-ports-adapters-fp` (32 commits, 2021-04..06), which is why the LICENSE names him. All 80 of Rharison Lucas's commits, the Conduit app itself (+1,271 lines in 49 `src` files), date from 2022-05-31 to 2022-06-29. That straddles Copilot GA, so this project carries the highest AI-assistance risk in the set.
  - **finance-project-ddd:** pinned 2022-11-20, after Copilot GA.
  - **pvarentsov-clean:** its pin is a 2022-06-25 dependabot commit, but its last human commit is 2021-09-19.
- **Exposure to the Copilot preview.** 6 of the 15 pins are before the Copilot technical preview (2021-06-29): luizomf, w3tec, Talento90, zeldaPlay, neoteric and ddialar. The other 9 fall inside the preview or GA period.
- **Long human histories.** Most histories begin years before the pin:
  - neoteric 2018-06, w3tec 2017-05, dannielhugo 2017-06, Talento90 2015-09, zeldaPlay 2018-03, bulletproof 2019-04, ddd-forum 2019-10, pvarentsov 2020-07.
  - The pinned trees are therefore the result of years of human edits.
- **Residual risk.** Copilot completions cannot be ruled out for code written between 2021-06 and 2022-12. The commit dates are what the committer recorded. They are evidence, not proof; author and committer dates agree for every pin (`selection.json` → `provenance`).
- **Commits after the pin.** Where later commits exist, they are listed, and none is part of the analysed tree.

**Forks (found in review).** Two entries were first probed through forks.
- **ddialar-hexagonal-boilerplate.** The upstream of record is `ddialar/typescript.service.boilerplate`, by Dailos Rafael Díaz Lara, who is named in the LICENSE. The pinned SHA `cc6ebdc5` is the same commit in both repositories. Upstream has one later commit (`53ed8c0`, 2020-08-25), and it changes only `README.md` and `docs/README_SPA.md`. The analysed tree is therefore identical, and no run was repeated; `selection.json` and the sheet links now point to upstream.
- **conduit-ports-adapters.** The analysed code is the fork's own app, so the fork stays the repository of record, and the boilerplate author is credited in `NOTICE.md`.

**Style-claim strength.** The README states the style in 12 projects. Talento90 (layered) and nest-products-hexagonal claim it through folder structure only. zeldaPlay is identified as NestJS by its framework and file layout.

### Errata to the rationale, found after the run

The specs are unchanged; this lists only the explanatory text that turned out wrong.

1. **The clean ring order sentence is reversed.** The rationale says "an infrastructure file importing a presentation file is a direction finding; a presentation file importing infrastructure is not". The opposite is true. Clean layers are listed inner to outer, so an import from presentation (inner) into infrastructure (outer) is FF-S01. All 18 blocking findings on pvarentsov-clean are of this kind (`application/api` importing `infrastructure/config` and adapters). The layer order in the specs is the one the rationale intended.
2. **finance-project-ddd shared kernel.** The rationale says `src/modules/shared/domain/**` is unmapped. The domain glob `src/modules/*/domain/**` also matches `shared`, so those files are in the `domain` layer. The same applies to `application/mocks`, which the rationale lists as unmapped but which `src/modules/*/application/**` maps to application. Those mocks are behind 3 of the 27 FF-S01 rows. FF-DS02 is unaffected, because `shared` is declared outside every context.
3. **conduit test file.** `src/core/article/use-cases/add-comment-to-an-article.test.ts.ts` has a doubled extension, so the default `**/*.test.ts` exclusion misses it. The only blocking finding on conduit comes from this test file importing test fixtures. The rationale did not anticipate it.

## 3. Runs

- **Engine.** `--engine cypher-interp` is not on `v1.3`; PR #128 is still open. Runs used a local Neo4j 5.26.24 community server with APOC 5.26.24 core, from the release tarball and bound to 127.0.0.1. That is the same kernel and APOC versions as `Docs/environment.md`.
- **Command:** `npx tsx bin/firewall.ts evaluate --project <clone>/<root> --spec results/v1.3-external/specs/<id>.yaml --symbolic-only --format json`.
- **Defaults kept:** v1.3 scoring (rule tiers), instrument v2, full graph mode, `<root>/tsconfig.json`.
- **Judge not run.** `--symbolic-only` means the LLM judge rules FF-N01 and FF-N02 were not run. They are non-blocking in v1.3, and running them would have used a Claude-family judge on this vendor-independent set.
- **No dependencies installed.** The clones have no `node_modules`.
- **Cost.**
  - All 15 runs finished, with a wall time of 2.8 to 8.5 s each and 72 s in total.
  - Exit code 1 means a failing verdict, not an error.
  - Parse coverage is 100% everywhere.
  - Import resolution is 0 unresolved, except one alias in ddialar (`@manifest`).
- **Clones untouched.** The runs wrote nothing into the clones; `git status` was clean.

**Results:**
- **The v1.3 literal view is exact on all 15 projects:** every edge tsc reports, and no extra edge. This repeats the W1 result (14/14 at 1.000) on an independent, pre-2023 set.
- **The frozen v1.2E instrument's graph differs.** `firewall evaluate` does not use it: v1.3 `evaluate` runs with `V13_DEFAULT_OPTIONS` and per-template views, so the literal-view templates read the exact graph above (errata from #149 §9, items 1–2, applied in merge train MT6). The v1.2E graph (`apg-v12e-default`: `V12E_DEFAULT_OPTIONS`, `reExportEdges: 'resolved-only'`) falls below 0.95 on 8 projects: w3tec, Talento90, zeldaplay, neoteric, vivify, conduit, ddialar and finance-project-ddd. On those, coverage is 0.74 to 0.91 and confirmation is 0.67 to 0.86, and every one has barrel-routing disagreements. The other 7 are at 0.95 or above. ddd-forum also has barrel-routed edges, 2 missing and 4 extra, but stays at 0.998/0.996. (Corrected after review; the first version said 9 projects at 0.67–0.89.)

  - This is by design for the v1.2E instrument. **The findings in §3 were not computed on the routed graph** (corrected per #149 §9 item 2): only the 4 resolved-view templates read routed edges (57 rows, none on a routed edge). The cycles through `index.ts` (neoteric, vivify) and the layer rows with a barrel target come from the literal view, which is why they exist.
- **Unscoped differences.**
  - `missing-in-apg:excluded-file` is the default exclusion of tests and specs.
  - zeldaplay's `missing-in-apg:out-of-root` (17 edges) is imports into `libs/api-interface`, outside the `apps/api` analysis root.
- **Layer assignment.** `fidelity/<id>/layer-review.csv` holds 40 sampled file-to-layer assignments per project for human review. The assignments were recovered with the instrument's own `annotateNodes`, and the harness reported no inconsistencies.

## 5. Limitations

- **One author for selection and specs.** The selection and the specs were made by one agent, which is a Claude-family model. The *code* is human-written and pre-2023, but the *layer mapping* is an AI judgement.
  - The rationale makes each judgement inspectable. A blind, human-written spec for the same pins would remove this residual same-vendor influence.
  - Some findings depend directly on mapping judgements (§3), for example the ring position of `main` and the single-context DDD declaration of event-sourcing-ddd.
- **Same-vendor runs avoided, not eliminated.** The judge rules were not run. Every other result here is symbolic and deterministic.
- **Pre-2023 is a proxy, not proof.** Copilot existed from mid-2021 (§1). Commit dates are committer-asserted.
- **Small and template-heavy.** The projects are small (19 to 248 files), and several are boilerplates or teaching projects rather than products. That is intentional, since the task preferred well-known reference implementations.
  - Results do not generalise to large production systems.
  - Only neoteric-nestjs-auth and zeldaplay-api are products.
- **No `node_modules`.** Package types are unresolved. Base types that come from packages (`IDomainEvent` from `types-ddd` in finance-project-ddd, for example) are not in the graph, so FF-DT05 cannot see those events.
- **Two weak style claims.** Talento90 and nest-products-hexagonal claim their style through folder structure only (§1).
- **Validator limitation, not fixed.** `firewall validate` reports `LAYER_DIR_NOT_FOUND` for mid-path globs and for preset directories a project lacks. Evaluation does not use that check (§2 of `spec-rationale.md`).
- **No labels yet.** The sheet is unlabelled, so no precision, recall or meaningfulness can be stated. The counts in §3 are candidates.
- **One run per project, recorded.** The instrument is deterministic. A repeat run was not made.
- **conduit-ports-adapters is kept, with the highest AI-assistance risk in the set.** Its app commits (2022-05-31 to 2022-06-29) straddle Copilot GA (§1). The author's construct decision D-a (delegated 2026-10-16, `Docs/v1.3/decision-chronology.md`) keeps it in the external set. Read its single blocking finding (FF-S01, from a test file, §2 errata 3) with that caveat; dropping it changes the set to 14 projects, 10 fail and 4 pass.
