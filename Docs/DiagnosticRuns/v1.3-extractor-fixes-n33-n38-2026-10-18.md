# v1.3 extractor fixes: N33 (and N32) and N38 — 2026-10-18

Branch `fix/extractor-n33-n38`, base `origin/main` at `6abc8f0a`. This covers gap-closing items G04 (N33) and G05 (N38). It is a bug fix in `src/apg-extractor/`. Both fixes sit behind new extractor options, which are **OFF in the frozen v1.2E options and ON in the v1.3 defaults**, following the F-P01-ALIAS pattern (`aliasDeclarationPackages`). No rule, tier, preset or spec changed. No model or API call was made, and Neo4j was not used.

## Summary

| Gap | Root cause | Fix (option) | Before | After |
|---|---|---|---|---|
| **N33** msc29-clean `domain/*` | `domain` is a Node built-in. The resolver classified `domain/...` as the built-in **before** it ran TypeScript resolution, so the import became an edge to built-in Package `domain`. tsc applies `paths`/`baseUrl` first. | `aliasShadowsBuiltins` | fixture: `domain/...` → `Package:domain` | fixture: `domain/...` → `src/domain/...` file, as tsc does |
| **N32** felixle-node-core (same cause) | the same: all 106 missing edges are `domain/...` bare imports under `baseUrl: ./src` | same option | fixture: Package | fixture: file |

## 1. N33: path aliases that shadow a Node built-in name

**Where.** `src/apg-extractor/import-resolver.ts`, `resolveModuleSilently`. The first step is `if (cls === 'node-builtin') return builtin Package`. `classifySpecifier` calls `isBuiltinSpecifier`, which is true when the **first segment** is in the pinned built-in list (`package-node-factory.ts`). `domain` is on that list (`node:domain`).

**Why only `domain/*` failed in msc29.** `application/...` is not a built-in name, so it reached `ts.resolveModuleName` and the `paths` rule. `domain/...` never got there.

**Correction to the earlier write-up.** `v1.3-external-set-3-2026-10-16.md:246-251` and N33 say that the gap is "not silent", and that the `domain/...` imports are counted as unresolved. That is not quite right. msc29's report shows `importResolution` `{resolvedInternal: 50, external: 53, unresolved: 93}`. The 49 `domain/...` imports are in **external** (49 + the 4 externals tsc also reports), as edges to built-in Package `domain`. The 93 unresolved are the 38 `adapters/...` imports plus bare npm imports, which the `"*": ["src/*"]` rule makes look like project aliases when nothing is installed. So the N33 gap is silent in the same way as N32.

**N32 has the same root cause.** I scanned every committed fidelity CSV (`results/**/fidelity/**/projects/*.csv`) for tsc edges whose specifier begins with a built-in name. There are exactly two projects. msc29-clean has 49 `domain/...` edges, all missing. felixle-node-core has 106 in-scope `domain/...` edges, all missing. Those 106 are exactly N32's 106 "`baseUrl` bare imports". No other project in waves 1–3, the wild set or the other fidelity runs has such an edge.

**Fix.** A new helper, `builtinShadowedByAlias`, runs before the built-in branch. It applies only when all of these hold:
- the specifier has no `node:` prefix;
- a `paths` rule matches, or `baseUrl` is set;
- `ts.resolveModuleName` resolves it to a file under the project root that is not a declaration file and not under `node_modules`.

When they hold, the import is that project file, as tsc resolves it. In every other case the specifier stays the built-in Package. `node:fs`, `fs`, `events` and a bare `domain` with no local `index.ts` stay built-in, and the tests pin all of these.

**Re-check on the real repositories: not possible offline.** Neither msc29-clean nor felixle-node-core is cloned locally. A local copy of felixle's source has 4 files and no tsconfig. The task forbids network access, so I did not re-run `graph-fidelity.ts` on them. The fixtures reproduce both tsconfig shapes:
- msc29: `baseUrl: "."`, `paths` with `"*"`, `"domain/*"` and `"application/*"`;
- felixle: `baseUrl: ./src` with no `paths`.

**What the committed data says about the expected effect** (from the fidelity CSVs, not a re-run):
- **Edges.** All 49 (msc29) and 106 (felixle) missing edges target `src/domain`. They are named imports of concrete files, not barrels.
  - The v1.3 literal view should go from 50/99 to 99/99 on msc29 and from 778/884 to 884/884 on felixle.
  - The "apg-v12e-default" view is extracted with `V12E_DEFAULT_OPTIONS` and does not change.
- **Cycles.** Adding the missing edges creates **no new strongly connected component** in either project: msc29 has none before or after, and felixle has the same two 2-cycles. FF-S02 rows should not change.
- **Direction.** Domain is the innermost layer in both specs, so every added edge points inward. FF-S01, FF-S03 and FF-S04 should not change, and **neither verdict should change**: msc29 stays pass and felixle stays fail.
- **Metrics.** Coupling, instability and other metric rows (advisory) will change. They now see edges into `domain`.
- These are expectations. The real numbers need the re-run commands in §6.

## 2. N38: optional constructor parameters under strictNullChecks

**Where.** `src/apg-extractor/edge-extractor.ts`, the CONSTRUCTOR_INJECTS loop: `param.getType().getSymbol() ?? param.getType().getAliasSymbol()`. Under `strictNullChecks`, the type of `x?: T` (or `x: T | null`) is a union, and a union has no symbol, so the loop `continue`s silently. With null checks off, the union collapses to `T`. This matches the diagnosis in `v1.3-operators-hexddd-2026-10-16.md:86-97`.

**Fix.** `injectedType()` removes `null` and `undefined` from a union. If exactly one member remains, that member is the injected type. This is the rule `field-state.ts` (`resolveHeldTargets`) already uses for HOLDS_STATE_OF. A union of two classes (`Repo | Other`) is still skipped. With null checks off, the edges are the same as before.

**Re-check.** The DDH base is not available offline: it needs a clone plus `npm install`, and the operator runner evaluates against Neo4j. `scripts/v1.3/extractor-fixes-n38-check.ts` reuses the runner's own pieces instead: `copyProject`, `typecheck`, `contextOf`, `templateIds`, `MO_H06`, `expectedKeys` and `matchesKey`. It runs them on the strict (`strict: true`) reference hexagonal base. Every eligible MO-H06 site is applied in the catalogued form and again forced to the `optional` form (the form of all ten DDH misses). Each copy is type-checked and then evaluated with `evaluate --symbolic-only --engine cypher-interp`, in process.

| Form (40 eligible sites) | Extractor without the fix | With the fix |
|---|---|---|
| `default-new` (`x: T = new T()`) | 40/40 | 40/40 |
| `optional` (`x?: T`) | **0/40**; FF-P06 miss 40/40, FF-S01 hit 40/40, FF-S04 hit 40/40 | **40/40** |

"Without the fix" means the same code with `nullableInjects` off. The miss pattern is exactly the DDH pattern: FF-S01 and FF-S04 fire, FF-P06 does not. Every copy type-checked, and the baseline had 36 violations.

**Expected effect on the registered operator figures** (development data, `v1.3-operators-hexddd`; not re-run):
- MO-H06 real recall: 18/28 → 28/28 expected, because all 10 misses are this shape.
- Pooled blocking recall: 431/441 → 441/441 expected; on real projects only, 312/322 → 322/322.
- Twins (MO-H06n) inject interfaces from the core. Under strict mode, their optional form now also writes CONSTRUCTOR_INJECTS. FF-P06 reads only domain → infrastructure, so a core-to-core edge is not a finding. The twin false-fire rate should stay 0, but only a re-run confirms it.

## 3. The 4 AP-FRAMEWORK-LEAK seeds both arms missed (NS-01 §3)

These do **not** have the N38 root cause.
- **What the seed is.** AP-FRAMEWORK-LEAK adds `request?: Request` to a public **method** of an application-layer service, not to a constructor, and adds `import { Request } from 'express'` (`scripts/lib/mutation/antipatterns/ap-framework-leak.ts:1-17`).
- **What the graph has.** A method parameter never produces CONSTRUCTOR_INJECTS. The seed shows up as an IMPORTS edge to Package `express`. That edge exists with or without strict null checks, and before and after this fix; a test pins it.
- **Why no rule fires.** The seeds are blind because FF-P01 forbids `express` only in the domain, and the operator declares `expectedTemplates: []`.
- **Conclusion.** This is a rule-scope matter (NS-01 K0), not an extractor gap, and this change does not affect it.

## 5. What the fix does not cover

- **MCP tools.** `src/mcp-server/import-check.ts` and `src/mcp-server/project-files.ts` still classify a built-in-named specifier as a built-in before anything else. They are not part of the evaluation graph.
- **Built-in names outside the project.** A built-in-named alias that resolves to a declaration file, into `node_modules`, or outside the root stays the built-in Package. A `node:` specifier is always the built-in.
- **Real-repository re-runs.** The N33/N32 fixes were not re-run on msc29-clean or felixle-node-core, and N38 was not re-run on DDH, because none is available offline (see §1 and §2). All numbers marked "expected" need those re-runs.
- **Other unions.** A union of several classes, an intersection, or a generic wrapper (`Promise<T>`, `Array<T>`) on a constructor parameter still writes no edge.
- **FLOWS_TO.** FLOWS_TO still skips every union value type by design (Q9 A, `flows-to-deriver.ts`). For example, `this.f = maybe` with `maybe: T | undefined` writes no edge. That is a construct decision, not this defect.
- **What counts as an injection.** Like any other interface-typed constructor parameter, an optional options bag (khusenov's `options?: SemanticErrorOptions`) now counts as an injection under strict mode, as it already did with null checks off. Whether option-bag parameters should count is a construct question and is not changed here.
- **AP-FRAMEWORK-LEAK.** §3: a rule-scope question, not touched.
