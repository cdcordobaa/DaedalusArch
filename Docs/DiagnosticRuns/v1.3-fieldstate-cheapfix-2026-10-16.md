## Part A. Field-level state facts for FF-P06

### A.0 What was built

- **Extractor option `fieldState`.** It is OFF in `V12E_DEFAULT_OPTIONS` and OFF in `V13_DEFAULT_OPTIONS`. It is ON in the new `V13_FIELD_STATE_OPTIONS`. The v1.3 default graph that every existing template, metric and report reads is unchanged.
- **Edge.** `Class -[:HOLDS_STATE_OF {field, source, line, sources, fields}]-> Class | Interface` (`src/apg-extractor/field-state.ts`). There is one edge per target. `source` is the kind of the first candidate by (line, field), and `sources` lists every kind seen for that target. The kinds are:
  - `declared-type`: the field's type annotation;
  - `property-injection`: the same, on a property with an injection decorator (`@Inject`, `@InjectRepository`, `@Autowired`, …);
  - `initializer`: `f = new X()`;
  - `constructor-new`: `this.f = new X()` in the constructor;
  - `constructor-param`: `this.f = p` in the constructor, where `p` is a constructor parameter typed `X`.
- **What the edge leaves out.** Constructor parameter properties give no edge. They are CONSTRUCTOR_INJECTS, the other FF-P06 half, and a second edge would count them twice. Static fields, self-loops and unextracted targets give no edge either.
- **Type handling:**
  - `T | null`, `T | undefined` and optional fields unwrap to `T`;
  - built-in containers (`T[]`, `Array`, `ReadonlyArray`, `Promise`, `Set`, `Map`/`ReadonlyMap` values, `WeakRef`) are followed to what they hold;
  - other unions and intersections are skipped;
  - a local generic `Repository<Order>` holds `Repository`, not `Order`;
  - an external generic (TypeORM's `Repository<T>`) is not extracted, so it gives no edge.
- **FLOWS_TO is not changed.** The new edge is written after each class's FLOWS_TO edges. A new enumeration, `FIELD_STATE_EDGE_TYPES`, keeps it out of `EDGE_TYPES` and `V13_EDGE_TYPES`. Ingestion writes the new edge type only when it is present.
- **FF-P06 field-half variant.** There is no construct-switch file on `v1.3`, so the variant sits behind a v1.3 compile option, `CompileOptions.fieldState`. It is OFF in `V13_COMPILE_OPTIONS` because Q8 is still unanswered.
  - The construct-switch file (`src/shared/construct-switches.ts`, PR #124) landed on `v1.3` after this branch was cut, and was merged in. Its Q8 options (A, B) decide how FLOWS_TO rows are *scored*, not which fact feeds the field half. So `fieldState` stays a separate compile option, and the switch is untouched. Wiring it in as a Q8 option would change the switch catalogue, which is the author's decision.
  - When it is on, `applyFieldState` (`v13-rewrites.ts`) rewrites `domain-state-purity`'s match from `FLOWS_TO|CONSTRUCTOR_INJECTS` to `HOLDS_STATE_OF|CONSTRUCTOR_INJECTS`. Nothing else in the text changes.
  - Field rows keep `relType = HOLDS_STATE_OF`. `rule-tiers.ts` now lists `naRelTypes: ['FLOWS_TO', 'HOLDS_STATE_OF']` for FF-P06, so these rows stay in the sealed **N/A** half with their denominator.
  - The field half becomes measurable without moving the tier. That would need an ADR.
- **In-memory mirror.** `v13DomainStatePurity` (`v13-in-memory-baselines.ts`) returns the Cypher's columns and order, with the field half read from `FLOWS_TO` or from `HOLDS_STATE_OF`.
- **Byte identity.** `tests/unit/apg-extractor/v12e-byte-identity.test.ts` passes. No fixture project was added; the new tests use in-memory and temp projects.
- **Tests.** `tests/unit/apg-extractor/v13-field-state.test.ts` has 14 tests:
  - option defaults;
  - the rest of the graph identical with the option on;
  - declared type;
  - initialiser;
  - constructor `new` and constructor parameter;
  - parameter property, which gives no edge;
  - property injection;
  - an interface-typed field with a concrete initialiser, which gives two edges, one per target;
  - generic wrappers, local and external;
  - optional fields, `T | null`, unions, primitives, statics and self-references;
  - the rewrite;
  - the N/A split;
  - an in-memory FF-P06 run, where an interface-typed domain field is not a violation and an optional concrete infrastructure field is.

## Part B. Cheap-proxy duplicate fixes

### B.1 Guard exclusion rule (fixed before any evaluation run)

A **guard** is a top-level `if` of a method, accessor, constructor or top-level function body that meets three conditions:
- it has no `else`;
- its `then` is a `throw`, or a block holding exactly one `throw`;
- it is not already a fragment unit.

Its clone key is:

> normalised condition | thrown error type | message template

(`src/apg-enrich/cheap/guards.ts`). In the condition:
- local names become `$v`;
- property names and called function names are kept;
- literals are kept by value.

The message template keeps every string-like argument, with `${}` for each substitution. Guard units pair only with guard units, on an equal key. There is no token minimum.

**A guard is excluded** (not a clone unit) when its condition, after removing parentheses, is a trivial null check:
- the forms are `!p`, `p == null`, `p === null`, `p == undefined`, `p === undefined`, and `typeof p === 'undefined'`, in either operand order;
- an `||` disjunction of only such terms is also excluded;
- every `p` must be a bare identifier naming either a parameter of the enclosing function-like node or a variable declared in its body.

The guard is kept when its condition has a property access (`!req.customerId`), a call (`!isOrderStatus(s)`), a value comparison (`qty <= 0`), a conjunction, or a module-level or imported name.

The local-variable half covers lookup results such as `if (!order) throw new NotFound(...)`. It was added before any run, after an existing unit test (`clones.test.ts`, "ignores bare existence guards") showed that a `x === undefined` lookup check on a local would otherwise pair across components.

### B.2 Same-component duplicates

`CheapOptions.cloneSameComponentFlags` flags a same-component clone pair (body, fragment or guard) as the separate kind `same-component-<type>`, next to the existing `cross-component-<type>`. It is advisory: a consumer can weigh the two kinds apart. Both new options default ON. With both OFF, the proxy is the previous one: same units, edges, flags and summary keys (`--before` in `cheap-semantics-eval.ts`). The frozen operators and `cheap-semantics-v2-eval.ts` are untouched.

Tests:
- `tests/unit/apg-enrich/cheap/guards.test.ts`, 20 tests:
  - guard key and normalisation;
  - non-guards;
  - 7 excluded and 6 kept conditions;
  - a same- and cross-component guard catch;
  - a different message is not a pair;
  - repeated trivial checks give no pair;
  - the options off;
  - constructor invariants.
- `clones.test.ts`: the old "same-component not flagged" test now runs with the option off, and one test was added for the new kind.

- **Guard units add no false flag.**
  - Over the 5 clean projects: 25 guard units, **0 guard pairs**, and 15 trivial checks excluded.
  - The near-miss variants show the same pattern: each has the flags of its clean project. `nestjs/n03` has 4 before and 4 after.
- **All new clean false flags are same-component whole-body clones.** They are look-up-or-throw or delegate bodies in the same layer: two controllers, two service getters, two invoice sums.
  - These are real Type-2 clones, but not duplicated business rules.
  - Treating them as advisory is what the separate kind is for.
  - A consumer that wants the duplicated-rule signal only can read `same-component-guard` and `same-component-exact-structural` at fragment granularity, or ignore same-component body pairs.
  - This was not tuned after the run. A consumer-side filter is a design choice to make before the hold-out.
- **Violation variants.** One new flag appears against the clean base: `nestjs/v09-controller-returns-entity`, `clones:same-component-near` on `workshops.service.ts`. The variant's edit creates a second near-identical body in the same component.
- **Before/after flag totals, near-misses included.** On the 19 clean and near-miss projects in the precision table, `clones` flags go from 36 to 66. Every added flag is `same-component-*`, and none is a guard.

### B.5 Reading

- **Guard units fix the 5 bare-guard misses.** On the evidence available here they do it without a precision cost: 0 guard pairs on 5 clean projects and 14 near-misses. The exclusion rule removed 15 trivial checks there.
- **Same-component flags fix the 3 "edge but no flag" misses.** They cost 8 flags (4 pairs) on the 5 clean projects, all body-level. That is the price of the kind, and it is why it is advisory and separate.
- **What is still open:**
  - the E1 confirmation (§B.3);
  - the AP-DUP-RULE judge confound of the v2 run (the foreign method), which this does not address.
