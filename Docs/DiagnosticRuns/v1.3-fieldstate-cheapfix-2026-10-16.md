## B.1 Guard exclusion rule (fixed before any evaluation run)

A guard is a top-level `if` of a method, accessor, constructor or top-level function body, with no `else`, whose `then` is a `throw` or a block holding exactly one `throw`. Its clone key is: normalised condition | thrown error type | message template (`src/apg-enrich/cheap/guards.ts`).

A guard is **excluded** (not a clone unit) when its condition, after removing parentheses, is a trivial null check: one of `!p`, `p == null`, `p === null`, `p == undefined`, `p === undefined`, `typeof p === 'undefined'` (either operand order), or an `||` disjunction of only such terms, where every `p` is a bare identifier naming a parameter of the enclosing function-like node or a variable declared in its body. A property access (`!req.customerId`), a call (`!isOrderStatus(s)`), a value comparison (`qty <= 0`), a conjunction, or a module-level or imported name keeps the guard.

The local-variable half (lookup results such as `if (!order) throw new NotFound(...)`) was added before any run, after an existing unit test (`clones.test.ts`, "ignores bare existence guards") showed a `x === undefined` lookup check on a local would otherwise pair across components.
