# v1.3 fixture-comment leakage census and scrubbed copies (V11, threats register V13-TV-I4)

Development set only. Exploratory tooling, not validity evidence. Nothing under `../daedalus-sealed/` was read, listed,
hashed or copied; the hold-out was not touched.

## 1. Fixed before any count (committed first)

**Pattern set.** `scripts/v1.3/lib/leakage-terms.ts`, matched against comment text only (TypeScript scanner comment
ranges, as `scripts/v1.3/lib/labelling/excerpt-scrub.ts`): `violation`, `allowed`, rule ids (`FF-…`, `AP-…`), the
frozen list of rule and template names, `planted`, `seed`, `anti-pattern`, `blocking`, `advisory`, `near-miss`, and
"construct denial" (`Not a repository`, `Not an adapter`, …).

**Sets scanned.**

| Set | Root | What a reader of a variant sees |
|---|---|---|
| reference (per style) | `tests/fixtures/v1.3-reference/<style>` | the clean project, plus each variant's patch or overlay |
| judge-catch bases | `fixtures/unit/antipattern-nest` | the base of the fixture-stratum judge seeds (TUNE and CHECK) |
| judge-catch seeds | `results/v1.3-judge-catch/{,round2/,duprule-v2/}diffs/*.diff`, split by `results/v1.3-judge-v2/split.json` | the seed's added lines |

"Hold-out-shaped": the hold-out uses the reference formats (`validate-reference --root`). The only tree in those
formats outside the sealed directory is the reference root itself, so the reference rows are the hold-out-shaped rows.

**Units.** A *comment line* is a source line that a comment touches. A comment line is a *hit* when it matches at least
one pattern. For a variant, a hit is *variant-introduced* when its line text does not occur in the same file of the
clean project (overlay files and patched files alike). Files: `.ts`, `.tsx`, `.js`, `.mjs`, `.cjs`.

**Scrubbed copy.** `scrub-fixtures.ts <src> <dst>` removes every comment (not only hits: a regex set can miss a
paraphrase), with line breaks kept so line n stays line n. Patch files are rewritten hunk by hunk from the scrubbed
clean file and the scrubbed patched file, so hunk headers do not change.

**Pass criterion.** (a) the census table is committed; (b) `validate-reference --check --root <scrubbed>` type-checks
every one of the 71 variants; (c) `ue-baseline-live --engine cypher-interp --root <scrubbed>` gives `raw/`,
`report.json` and `report.md` byte-identical to the same run on the unscrubbed root (only `elapsedMs` in `evidence/`
may differ), i.e. comment removal does not change the graph or the findings; (d) the scrubbed copy contains zero
comment lines; (e) the sealed directory is never touched. A failure of (b) or (c) is reported, not fixed by editing a
fixture.

## 3. Scrubbed copies: verification

`npx tsx scripts/v1.3/scrub-fixtures.ts tests/fixtures/v1.3-reference <dst>`: 169 source files (65 had comments), 52
patches (13 rewritten), 109 other files copied. Copy digest (sha256 over sorted `sha256sum` lines):
`efbce562bfc5ba0595b97136e587808cf32077a080ac4d6aa82014f23a56afcb`. Running it twice gives identical trees.

| Criterion | Result |
|---|---|
| (a) census committed | yes, §2 and `results/v1.3-fixture-leakage/` |
| (b) `validate-reference --check --root <scrubbed>` | **71/71 variants compile**, exit 0 |
| (c) `ue-baseline-live --engine cypher-interp --root <scrubbed>` vs `results/v1.3-reference/after-member-facts` | `raw/` (80 files), `report.json`, `report.md` **byte-identical**; the 71 `evidence/` files differ only in `elapsedMs` |
| (c') same run on the unscrubbed root (rule 3 baseline) | byte-identical, same comparison |
| (d) comment lines left in the copy | **0** in source files and in patch bodies (85 and 56 in the original) |
| (e) sealed directory | never read; the CLI refuses any path containing `daedalus-sealed` |

So comment removal does not change the graph or a single finding on the development set: a blind reader can be given
the scrubbed copy at no cost to the tool's figures.

Not done: variant directory names (`v05-use-case-injects-concrete-repository`) and the manifests still name the plant.
The copy keeps them because the runners key on them; a blind harness must hand over materialised project directories
under opaque ids (register mitigation 3), which this job does not build.

## 4. For the author: which past model runs saw unscrubbed fixtures (residual, no fix claimed)

The blind-manifest writer of the reference baseline (`v1.3-reference-baseline-2026-10-15.md`; the inputs in
`validation-protocol.md` §1 are "the project source") has no record of comment stripping, and no script in the
repository strips comments for it, so the census numbers above are what it could have read: every DDD variant names its
construct, and 8 of 52 patch variants explain theirs. The DDD blind agreement (9/9) and the blind-expanded patch-style
figures should carry "possibly leaked". No judge-catch or judge v2 script (TUNE and CHECK) calls a comment stripper
(`grep stripComments` finds only the labelling and wild sheets); their seeds add no comment, but two CHECK items sit on the `nestjs/n02-domain-port-named-dot-repository`
base, whose added comment explains the near-miss, and every reference-base item could see the clean projects' ordinary
comments. The labelling run used scrubbed excerpts (`excerpt-scrub.ts`) and produced no labels; the human and Gemini
sheets are scrubbed. None of this can be undone for runs already made; future blind writers, judges and raters can read
the scrubbed copy.
