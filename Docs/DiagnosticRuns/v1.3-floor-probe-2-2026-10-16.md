## 1. Question and design

#161 found 0/14 hexagonal `none`-arm steps with a blocking finding with the folder sentence given. This probe asks
whether the floor lifts when the layout sentence is dropped (C2) or when both sentences are replaced by "Follow the
architecture spec at spec.yaml" with the pilot spec copied in (C3).

- **Tasks.** `shelter-adoptions` (hexagonal, `presets/hexagonal.yaml`) and `market-vendors` (Clean,
  `specs/clean-arch.yaml`), both pilot tasks verbatim (byte-identical to #161's `tasks.json`). **Option taken under
  delegation:** the backlog asked for "one clean task from #161's new tasks", but none of #161's new tasks is Clean;
  `market-vendors` is the pilot's Clean task (which #161 restyled to Layered) and is used here in its pilot style.
- **Frames.** The loop's styled frame rendered by hand (`scripts/frames.py`; C1 checked byte-identical to
  `stepPrompt()`), with only the architecture lines changed per condition (plan §3). Rendered prompts in `prompts/`.
- **Procedure.** Seeded order (seed 20261017): shelter/C2, market/C3, market/C2, market/C1, shelter/C1, shelter/C3. Each
  step written from its prompt only, type-checked with the pinned skeleton (`typescript 5.9.3`, `express 5.2.1`), then
  committed to a git store outside the project directory. **All 24 steps were committed (04:27–04:43 UTC,
  `step-commit-times.txt`) before the first evaluation ran.** Then `bin/firewall.ts evaluate --symbolic-only --engine
  cypher-interp --scoring v1.3` on every snapshot against the task's pilot spec, and `check-correct.ts --tiers blocking`
  on every blocking finding.
- **Outcomes.** Blocking findings per step, new identities at steps ≥ 2 (pilot memo §3 identity rule), layer coverage
  (`layerAnnotation.unmapped`), rules hit, advisory counts. All 24 steps type-check with 0 errors.

## 2. Results

Per-step table: `results/v1.3-floor-probe-2/summary.md`.

### 2.1 Blocking findings

One blocking finding in 24 steps: **FF-S02 no-cyclic-deps, market-vendors / C1, step 4** (audit log). `application/
audit.ts` imports the `Clock`/`IdSource` interfaces from `application/market-service.ts`, which imports `Auditing` from
`audit.ts`. `check-correct.ts`: `correct` ("every step of the 2-file cycle is an import that resolves to the next file").
It is new at step 4 and so counts under the pilot memo's erosion rule. It is an intra-layer cycle produced by the
"across every layer" step, not a layer violation, and it appeared in the condition that gives the most guidance. No
FF-S01, S03, S04, P01, P03 or P06 finding in any snapshot of either style.

### 2.2 Layer coverage: C2's zero is partly invisibility

| Trajectory | Folder layout the agent chose | Unmapped at step 4 |
|---|---|---|
| shelter / C1 | `src/{domain,application,adapters/inbound,adapters/outbound,config}` (as told) | 0 / 19 |
| shelter / C2 | `src/{domain,ports/in,ports/out,application,adapters/http,adapters/persistence,adapters/mail,adapters/sms}`, `src/main.ts` | **19 / 28** |
| shelter / C3 | the spec's five folders (read from `spec.yaml`) | 0 / 16 |
| market / C1 | `src/{domain,application,infrastructure}` (as told; composition root in `infrastructure/main.ts`) | 0 / 10 |
| market / C2 | `src/{domain,application,infrastructure,interface/http}`, `src/main.ts` | 2 / 21 |
| market / C3 | the spec's three folders, `src/main.ts` | 1 / 19 |

Without the layout sentence the hexagonal agent used a common ports-and-adapters layout whose folders
(`ports/`, `adapters/<tech>/`) match none of the preset's globs (`src/adapters/inbound/**`, `src/adapters/outbound/**`).
Two thirds of its files carry no layer, so no layer rule can fire on them. A by-hand listing of the folder-level import
edges of shelter / C2 step 4 (not a score) shows that every edge points inward anyway: adapters → ports, application or
domain; application → ports or domain; ports → domain; only `main.ts` imports adapters. So the zero would most likely
remain under any natural mapping, but the instrument did not measure it. In Clean, C2 left only the composition root
and the `interface/http` controller unmapped.

C3 behaved like C1: given the spec file, the agent read its layer globs and used exactly those folders. The spec
carries the layout, so "spec only" is not a no-layout condition.

### 2.3 Advisory counts

Advisory counts follow coverage: shelter / C2 has the fewest at every step (4, 8, 11, 15 vs C1 12, 15, 21, 28), because
the unmapped files escape the layer-bound advisory rules too. FF-CV05 dominates every count, as in #161. Advisory counts
therefore cannot be compared across conditions with different coverage.

## 3. What this means for Study 2

1. **The layout sentence is not the floor's cause in this probe.** With or without it, and with only the spec, this
   agent wrote no layer-direction violation in hexagonal or Clean across the four pilot pressures. The one finding is a
   cycle created by the audit step in the most guided condition.
2. **Dropping the layout sentence costs instrument coverage.** A `none` arm without it would need either a layout-
   agnostic mapping or a coverage guard (share of unmapped files, already a pilot guard) that is reported beside every
   count; otherwise a zero can mean "outside the globs".
3. **"Spec only" is a layout hint.** If Study 2 hands the agent a spec, the spec's globs act like the layout sentence.
4. **Recommendation (pre-stated rule):** keep the frame (S5 stays "frame with layout sentence") and put the lever into
   task design (W3-3): steps that make the cheapest path a blocking-tier edge (#161 §5.2), e.g. a use case reaching a
   concrete adapter, domain code needing request data, or shared code across use cases that invites a cycle (the one
   finding here).

## 4. Limits

- **One agent, Opus, by hand; n = 24 steps; 2 tasks.** No replicate, no second model, no harness confinement, no
  headless CLI, no acceptance checks (type-check only). Nothing here is a rate.
- **The agent knew the instrument.** It had read the plan, the presets' headings and (for C3, by design) the spec, and
  #161's report, though not #161's code. That biases toward clean code, i.e. toward the floor, in every condition.
- **Order and carry-over.** The same session wrote all three conditions of each task (seeded order, not removed).
  Market C2 and C1 came after market C3; shelter C1 and C3 after shelter C2. Habits (audit wrapper, unit of work,
  in-memory rollback) recur across trajectories.
- **The C2 layout is one agent's habit.** Another agent might choose folders that happen to match the globs.
- **Task-design caveat.** No task step here targets a blocking-tier edge on purpose; the result says the frame lever is
  weak, not that the floor is unbreakable.
- Both tasks are pilot tasks, which the author already checked against the sealed domains for the pilot; this probe
  does not feed Study 2.
