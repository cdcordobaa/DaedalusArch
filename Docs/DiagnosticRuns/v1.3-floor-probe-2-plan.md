## 4. Procedure

1. Order of the 6 trajectories from the committed seed `20261017` (`frames.py`):
   shelter/C2, market/C3, market/C2, market/C1, shelter/C1, shelter/C3.
2. For each trajectory: a fresh project (pinned skeleton `scripts/generator/skeleton/`, harness tsconfig options), the
   agent writes step s from the rendered prompt only, type-checks, and the tree is committed into a git store **outside
   the project directory** (`--git-dir` in the scratchpad). The agent does not read #161's snapshot code.
3. **All 24 steps are written before any step is scored.** No firewall, `check_*` tool or evaluator runs on probe code
   until the last trajectory is committed.
4. Then every snapshot is scored with `bin/firewall.ts evaluate --symbolic-only --engine cypher-interp --scoring v1.3`
   against the task's pilot spec (same spec for all three conditions), and every blocking finding goes through
   `scripts/v1.3/check-correct.ts --tiers blocking`.

## 5. Outcomes and identity rule

- Per step: blocking findings (rules blocking in `Docs/v1.3/rule-tiers.md` for the style, as the evaluator's v1.3
  tiers report them), advisory count, files, LOC, type-check errors.
- **New blocking identity** (pilot memo §3, copied): "It is **new** at step s (s = 2, 3 or 4) if no snapshot from an
  earlier step of the same run holds a finding with the same identity. Identity is the rule id, the template, the file
  and the target; for a cycle, it is the set of files. Line numbers are ignored, because they move between steps." A
  new finding counts only if `check-correct.ts` labels it `correct`.
- **Layer coverage**: share of `src/**/*.ts` files that match no layer glob of the spec, per step and condition (C2 and
  C3 may produce unmapped files instead of violations; an unmapped file cannot be a layer violation).
- Rules hit, per condition and style.
