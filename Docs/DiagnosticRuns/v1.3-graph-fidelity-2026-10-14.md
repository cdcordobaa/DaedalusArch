# v1.3 graph fidelity, first result (FR-V2, link 1), 2026-10-14

Harness: `scripts/v1.3/graph-fidelity.ts` (pure part `scripts/v1.3/lib/`, tests `tests/unit/scripts/v1.3/`). Outputs: `results/v1.3-fidelity/{e1,so4}/` (`projects/<id>.json` and `.csv` per project, `aggregate.json`, `adjudication.csv`, `layer-review.csv`, `run.log`) and `results/v1.3-fidelity/manifest.json` (versions, commits, seeds). No Neo4j and no LLM are used. The projects are only read. A full E1 rerun gave byte-identical outputs. An earlier SO4 rerun did too, before a metadata-only change.

## What is compared

The harness builds three file-to-file internal import edge sets for each project:

- **APG**: `extractAPG`, using the File→File `IMPORTS` ∪ `RE_EXPORTS` edges. It runs in two variants. `apg-v12e-default` uses the v1.2E `DEFAULT_OPTIONS` plus the spec's `default_exclude_paths`, as the pipeline does. `apg-v13-dynamicImports` is the same plus `dynamicImports: true`, taken from `v1.3-extractor-fixes` @ `f44e102`.
- **dependency-cruiser** 18.4.0, the pinned install of `experiments/tool-comparison/depcruise`. The config has options only: `tsPreCompilationDeps: true`, node_modules excluded, and the project tsconfig.
- **tsc**: every import, export-from, import-equals, `require()`, `import()` and `import('x').T` specifier, resolved with `ts.resolveModuleName` and the project's compilerOptions (TypeScript 5.9.3).

dependency-cruiser and tsc are **second extractors, not ground truth**. So every figure below is *agreement*, not precision or recall:

- `refCoveredByApg` = |A∩R|/|R|
- `apgConfirmedByRef` = |A∩R|/|A|
- Jaccard

Only the adjudicated figure (from `adjudication.csv` once a human has checked it) may be called precision. **Scoped** means both endpoints are APG File nodes. **Raw** means all internal edges.

Corpora:

- **E1**: all 72 cells of `experiments/e1-grid/plan.json`. 65 of them were judged (`accepted`). The other 7 are `generation-failed`, but they still have a `src/` and were measured. Each cell uses the pinned per-run tsconfig of `Docs/generator-protocol.md` §3 (ADR-032) and the spec `specs/clean-arch.yaml`.
- **SO4**: the 7 held-out bases in `../daedalus-so4/bases`, with the tsconfig and spec recorded there. Base dirs were read as they are, without overlays. realworld-test's `src/config.ts` overlay was not applied.

**None found.** The adjudication sheet backs this up:

## Barrel routing: by design, but it changes the graph

The extractor routes each named import through barrels to the file that declares the name (BR-U2-24). It then drops the edge to the barrel itself unless something is declared there. Two examples:

- `claude-opus-5-5/order-fulfilment/full-aac/run-1`: `src/infrastructure/persistence/InMemoryOrderRepository.ts` imports from `../../application/ports/persistence`, which re-exports domain types. The APG has only infrastructure→domain edges, to `domain/entities/Order.ts`, `domain/repositories/OrderRepository.ts` and `domain/value-objects/OrderStatus.ts`. The infrastructure→application edge is missing.
- `claude-opus-5-5/task-management/none/run-1`: imports of `../domain` and `../application` (`index.ts` barrels) become 23 edges to declaring files, and the 9 edges to the barrels disappear. In the APG, the `index.ts` barrels have no incoming IMPORTS edge.

Layer rules over IMPORTS see the declaration-level dependency, not the module the code actually imports. That can hide or move an edge between layers, and it can make a barrel look unused.

## Where dependency-cruiser cannot see an edge (its silence is not counted against the APG)

- **Re-export chains.** It records only the module-level edge to the barrel. This is the 80 + 138 barrel rows in SO4, and the same holds for tsc.
- **Type-only imports.** It drops them unless `tsPreCompilationDeps` is on. The harness turns it on, which is why the E1 type-only edges agree. Any run with the default config is blind here.
- **Dynamic `import()` / `require()`.** A non-literal specifier is invisible to all three tools. Literal ones were not exercised in this run.
- **`${configDir}` in tsconfig `paths`** (TypeScript 5.5+). The ghostfolio base's generated `tsconfig.monorepo.json` maps `@ghostfolio/api/*` to `${configDir}/src/*`. Every one of the 829 `@ghostfolio/api/*` edges is missing from dependency-cruiser, while tsc resolves them all. We infer that its resolver does not expand `${configDir}`. That is why ghostfolio confirms only 0.1896 against dependency-cruiser. tsc is the better primary reference for this corpus.

## File-to-layer assignment

The layer of each file comes from the instrument's own `annotateNodes`. The glob that matched is recovered separately, and it disagrees with `annotateNodes` for 0 files.

- **E1**: 1319 of 1332 files assigned (0.990240). The lowest project is 0.75 (`claude-haiku-4-5/task-management/none/run-0`, 3 of 4 files). All 13 unassigned files are top-level entry files outside the three layer folders: 12 are `src/index.ts` and 1 is `src/server.ts`.
- **SO4**: 602 of 833 files assigned (0.722689). The lowest project is 0.549618 (truthy-demo, 72 of 131). Unassigned files include migrations, exceptions, config and `libs/ddd` interfaces. This reflects how much of each project the spec covers, not a resolution fault.
- **Review sheets**: `layer-review.csv` holds 40 assignments per corpus (seed 20261015) for human checking. The E1 and SO4 projects have no expected layer map, so accuracy against one (target ≥ 0.95 on reference projects) is not measured yet.

## What to fix

1. **Barrel semantics** (the only in-scope disagreement). Choose one of these and log it as a v1.3 ADR:
   - (a) also emit the module-level edge to the barrel, marked `viaBarrel`, next to the routed edge; or
   - (b) keep the routing, and add a declaration-level tsc reference to the harness (follow names with the checker) so link 1 compares like with like.
   
   Option (a) matters for layer rules whenever the barrel and the declaring file sit in different layers, as in opus order-fulfilment/full-aac/run-1.
2. **Out-of-root monorepo code** (ghostfolio `libs/common`, 329 tsc edges) is modelled as Package nodes, so cross-library architecture rules cannot see it. This is by design, but it blocks brownfield use (ISE). Consider letting a spec declare extra roots.
3. **dynamicImports is untested.** The FR-V3 reference projects need literal `import()` and `require()` of TS modules. The current corpora contain none.
4. **Harness reference choice.** Report tsc as the primary reference, with dependency-cruiser as a secondary check. dependency-cruiser misses `${configDir}` paths.
5. **Adjudication.** A human should fill in `human_verdict` in `results/v1.3-fidelity/{e1,so4}/adjudication.csv`, starting with the 39 E1 rows and the 218 SO4 barrel rows. Only after that can a precision figure be reported.
