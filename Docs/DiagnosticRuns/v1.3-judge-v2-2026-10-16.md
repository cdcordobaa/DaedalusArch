## 0. What was built

**Judge v2, selectable, v1 frozen and default.**
- `src/llm-critic/judge-v2.ts` holds the v2 rubric (FF-N01, FF-N02), persona and instructions, with its own revision label and hash anchor (`JUDGE_V2_SHA256`, recomputed by a test). Nothing of v2 enters `FROZEN_VALUES`: `FROZEN_SHA256` is still `f8b2dabb…`, and `Docs/judge-preregistration.md` and `rubric.ts` are untouched.
- Selection: `--judge-version v1|v2` on `firewall evaluate` (default `v1`) → `JudgeRunSettings.judgeVersion` → `NeuronalRunOptions.judgeVersion`. A v1 run builds exactly the v1 request (same prompt, persona and keys). A v2 report carries `judge.judgeVersion: "v2"` and `judgeRevision`; a v1 report has no new field.
- **Structured output unchanged**: v2 uses `VERDICT_JSON_SCHEMA`.
- v2 prompt (`src/llm-critic/context-v2.ts`):
  - v1's sections in v1's order, with the v2 rubric;
  - `## Neighbourhood` in place of the JSON graph excerpt: per unit file, its imports (files with layer and layer kind, packages by name), who imports it, and the injection, extension and implementation edges. These are the same literal-view edges as the v1 excerpt, read from the same Neo4j graph view;
  - `## Candidate flags`: the cheap-proxy flags on the unit's files (`src/apg-enrich/cheap`, computed once per run with `extractAndEnrich`), headed "Candidates proposed by deterministic checks; verify, don't trust". Communities flags are left out (a diagnostic, design note §9). The persona and instructions say a flag the source does not support must not count, and a violation no flag names counts as much.
- Probe independence (BR-U4-RUB-01) holds for v2 too: the test asserts that no v2 text uses `PROBE_CONSTRUCTION_VOCABULARY`.

**Filter-and-explain (FR-V8, never built before).** `src/llm-critic/filter-explain.ts`:
- One call per symbolic finding. The prompt holds the finding (rule, rule intent, type, severity and tier, file, target, lines, message, discriminator, evidence), the layer model and the cited files **with line numbers**.
- The answer (`FE_SCHEMA`) is `decision` (confirm or dismiss), a one-paragraph `explanation`, a `fix` suggestion and `citations` (file and line range).
- **Grounding check** (`checkGrounding`): there must be at least one citation, and every citation must name a shown file and lines that exist. Every `file:line` and every bare `line N` in the explanation or the fix must exist too. An ungrounded answer is `rejected`: the finding is kept and the explanation is dropped. Only a grounded `dismiss` removes a finding.
- The same isolated CLI route and cassette decorator as the judge, with its own persona and schema in the request key, and its own interpreter.
