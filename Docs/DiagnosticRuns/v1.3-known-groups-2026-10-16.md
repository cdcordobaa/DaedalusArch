# v1.3 known-groups and discriminant validity on committed real-world data (2026-10-16)

> **Development-set, exploratory.** n = 15 (external) and n = 14 (wild); groups from repository names; no causal
> reading; status-quo scoring only (no construct switch). Nothing here claims validity on its own.

Night backlog job #12 (K1), objective SO4. The plan was committed and pushed before any findings file was opened
(`Docs/DiagnosticRuns/v1.3-known-groups-plan.md`, commit 994efebc); every test, threshold and reading below is the one
fixed there. Script: `scripts/v1.3/known-groups.ts` (helpers in `scripts/v1.3/lib/known-groups.ts`, unit tests in
`tests/unit/scripts/v1.3/known-groups.test.ts`). Outputs: `results/v1.3-known-groups/` (`sizes.json`,
`analysis.json`, `per-repo.csv`, nine `scatter-*.svg`).

Data: the external set (PR #133) is **not merged** into `v1.3`; it was read from `origin/v1.3-external-set`
(b8492a7a) with `git show`, never merged. The wild set (PR #114) is on `origin/v1.3`. Sizes come from fresh
blobless, sparse clones of the 29 pinned SHAs (every checked-out HEAD equals its pin). The blocking total recomputed
from the reports is 283, matching the external set's own count.

## 1. Known groups: does blocking density separate showcase from application repos?

Hypothesis (one-sided): blocking per KLOC is lower in showcase repos (boilerplates, templates, samples) than in
application repos.

| Test | Groups (app / showcase) | Mean app | Mean showcase | Median app | Median showcase | Cliff's δ (app vs showcase) | Exact one-sided p | Labelings | Reading |
|---|---|---|---|---|---|---|---|---|---|
| K-1 external, B/KLOC, name rule | 10 / 5 | 4.94 | 8.13 | 4.13 | 5.20 | −0.18 | 0.811 | 3003 | **not supported** |
| K-2 same, permuted within style | 10 / 5 | | | | | | 0.889 | 243 | (secondary) |
| K-3 external, description rule | 6 / 9 | 5.14 | 6.58 | 4.13 | 5.20 | −0.11 | 0.651 | 5005 | not supported |
| K-4 wild, G/KLOC (APG v2, not tiers), name rule | 11 / 3 | 6.25 | 12.85 | 6.82 | 13.67 | −0.58 | 0.951 | 364 | not supported (exploratory) |
| K-4 wild, description rule | 10 / 4 | 6.81 | 9.80 | 7.25 | 8.77 | −0.15 | 0.799 | 1001 | not supported (exploratory) |

**Null result.** In neither set do showcase repos have lower finding density; the point estimates go the other way
(showcases denser), most clearly in the wild set's exploratory APG v2 measure. Per style (external, one showcase and
two application repos each; no per-style p, the minimum attainable is 1/3), the showcase is the densest of its style in
ddd and layered, the middle one in clean-architecture and nestjs, and the least dense in hexagonal
(`analysis.json` → `K2perStyle`).

Reading this null honestly: the name rule is crude by design, and the external set was *selected* for repos that claim
a style, so most "application" repos there are themselves teaching references (`pvarentsov-clean`, `ddd-forum`,
`finance-project-ddd`). The contrast the test needs (curated exemplar vs product code) is weak in these samples. A null
here does not show that the instrument cannot separate known groups; it shows that this name-based split does not.

## 2. Discriminant: is the blocking count a size proxy?

Spearman ρ with 95% percentile bootstrap CI (10,000 resamples of repos, seeds 20261016 + k; no resample skipped).

External (n = 15):

| Measure | ρ vs LOC [95% CI] | ρ vs files [95% CI] |
|---|---|---|
| B (blocking count) | 0.68 [0.19, 0.96] | 0.69 [0.22, 0.94] |
| B/KLOC | 0.39 [−0.19, 0.85] | 0.41 [−0.15, 0.82] |
| C (FF-C01..C06 count) | 0.30 [−0.32, 0.95] | 0.29 [−0.34, 0.91] |
| C/KLOC | 0.01 [−0.54, 0.63] | 0.04 [−0.53, 0.66] |
| FF-CV05 count | 0.25 [−0.36, 0.87] | 0.32 [−0.30, 0.94] |

Wild (n = 14, exploratory, different instrument):

| Measure | ρ vs LOC [95% CI] | ρ vs files [95% CI] |
|---|---|---|
| G (APG v2 total) | 0.85 [0.53, 0.97] | 0.74 [0.38, 0.89] |
| G/KLOC | 0.00 [−0.58, 0.58] | −0.08 [−0.62, 0.54] |
| P (cheap-proxy flags) | 0.66 [0.08, 0.99] | 0.60 [0.09, 0.88] |
| P/KLOC | 0.00 [−0.56, 0.57] | 0.05 [−0.53, 0.62] |

Readings, as pre-stated:

- **B/KLOC: density still size-related** (|ρ| = 0.39 and 0.41 > 0.3). The CIs are wide and include zero, so this is
  a weak signal at n = 15, not an established dependence. Normalising by KLOC roughly halves the size association
  (0.68 → 0.39) but does not remove it.
- **B (count): positive with size**, as expected for a raw count; not a failure.
- **Advisory metric family: the expected contrast is reversed.** The plan expected ρ(C, LOC) ≥ 0.5; it is 0.30, while
  the blocking count tracks size more closely (0.68). One visible contributor, stated as an observation and not
  re-analysed: the three DDD repos have C = 0 (no FF-C* finding in their reports), and two of them are the largest and
  third-largest external repos by LOC, so the advisory metric family is not uniformly present across styles in this set.
- **Wild (exploratory):** the APG v2 density G/KLOC shows no size association (ρ ≈ 0), while its raw count does.
  This is a different instrument (inferred specs, no tiers) and does not transfer to the v1.3 blocking verdict.

## 3. Checks and deviations

- The name-rule groups computed by code equal the lists written in the plan; the script stops otherwise.
- The description rule moves four external repos into the showcase group (bulletproof-nodejs, conduit-ports-adapters,
  neoteric-nestjs-auth, nest-products-hexagonal) and one wild repo (bitloops-ddd-backend). Both rules give the same
  reading.
- File count matches the external selection's `srcTsFiles` for 14 of 15 repos; `conduit-ports-adapters` has 36, not
  35 (reported, not changed; the sizes used are the measured ones).
- Additional descriptive number not in the plan (labelled as such in `analysis.json`): Cliff's δ of C/KLOC,
  application vs showcase, external = −0.32. No test was run on it.
- No deviation from the plan's tests or thresholds.

## 4. Limits

Small n; groups from names, with known misclassification (several "application" repos are teaching references);
all external specs were written by one session (the K2 job measures that); wild specs are inferred and its measure is
not the v1.3 verdict; the two sets differ in instrument, era (pre-2023 pins vs current heads) and selection rule and
were not pooled; LOC counts only `<root>/src/**/*.ts`, while each report's evaluated scope follows its spec;
the per-style rule sets differ (for example the absence of FF-C* findings in the DDD reports), so cross-style density
comparisons mix rule families. No causal claim is made.
