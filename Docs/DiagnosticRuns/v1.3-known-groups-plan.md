## 2. Group rule (known groups)

A repository is **showcase** when any of the fields below, lower-cased, contains one of the substrings
`boilerplate`, `template`, `sample`, `example`, `starter`, `showcase`. Otherwise it is **application**.

- **Primary (name rule):** fields `id`, `repo`, `url` only (both sets). Neither selection file has a repository-owned
  description field.
- **Sensitivity (description rule):** primary fields plus the description-like field each selection carries:
  `styleClaim` (external) and `ownDescription` (wild). Both were written by the selecting session (they paraphrase or
  quote the README), so they are a sensitivity check, not the primary rule.

Applying the primary rule to the selection files (names only, no findings) gives:

- External, showcase (5): `luizomf-clean-api` (…-api-boilerplate), `w3tec-express-boilerplate`,
  `vivify-nestjs-boilerplate`, `ddialar-hexagonal-boilerplate` (typescript.service.boilerplate),
  `event-sourcing-ddd` (…-sample-app). Application (10): the other ten.
- Wild, showcase (3): `awesome-nest-boilerplate`, `ts-express-starter-prisma`, `mikro-orm-realworld`
  (…-realworld-example-app). Application (11): the other eleven.

The assignment is computed by code (`groupOf` in `scripts/v1.3/lib/known-groups.ts`) and the script fails if it
differs from the lists above. Known misclassification risk, stated now: several "application" repos by name are in fact
style showcases (for example `pvarentsov-clean`, `clean-ts-api`, `domain-driven-hexagon`); the name rule is crude by
design so that it cannot be tuned to the result.

## 3. Size measures

Computed from fresh blobless clones of the pinned SHAs in a scratch directory (never committed):

- **files**: `.ts` files under `<root>/src/`, excluding `*.d.ts`, `*.spec.ts`, `*.test.ts` and any path segment
  `__tests__`, `test` or `tests` (the `srcTsFiles` filter of the external selection).
- **LOC**: non-blank lines of those files. **KLOC** = LOC / 1000.

The committed per-repo sizes go to `results/v1.3-known-groups/sizes.json` with the SHA they were measured at.
For the external set, `files` is cross-checked against `selection.json` `srcTsFiles`; a mismatch is reported, not fixed.

## 4. Outcome measures

External (per report, tier taken from the report itself, exactly as `external-sheet.ts` does):

- **B** = number of violations whose rule is in `tiers.blocking.rules`; **B/KLOC**.
- **C** = number of violations of FF-C01..FF-C06 (advisory metric rules); **C/KLOC**.
- **CV05** = number of FF-CV05 violations.
- **A** = all advisory violations (secondary, descriptive).

Wild (no tiers exist; exploratory only, never called "blocking"):

- **G** = total APG v2 template findings (sum of `counts` over the nine templates in `apg2.json`); **G/KLOC**.
- **P** = total cheap-proxy flags (sum of `counts` in `cheap.json`); reported for the discriminant check only.

## 5. Tests

All seeds: 20261016. Exact tests by full enumeration.

**K-1 Known groups (primary, external, B/KLOC).** Statistic T = mean(application) − mean(showcase) of B/KLOC.
One-sided exact permutation p = #{labelings with T* ≥ T} / C(15,5) over all 3003 labelings with 5 showcase repos.
Effect: Cliff's δ(application, showcase). Also the medians per group.

**K-2 Known groups, stratified by style (secondary, external).** Same statistic, labels permuted only within style
(each style has exactly one showcase and two application repos under the primary rule): 3^5 = 243 labelings, exact.
Per-style values are tabulated; no per-style p (minimum attainable 1/3).

**K-3 Sensitivity (external).** K-1 under the description rule, if its assignment differs from the primary one.

**K-4 Wild (exploratory).** K-1 on G/KLOC with 3 showcase vs 11 application: C(14,3) = 364 labelings, exact.
Same under the description rule if it differs.

**D-1 Discriminant (external).** Spearman ρ (average ranks for ties) of each of B, B/KLOC, C, C/KLOC, CV05 with LOC and
with files. 95% percentile bootstrap CI: 10,000 resamples of repos with replacement (a resample whose measure or size
is constant is skipped and counted). One scatter (SVG) per measure against LOC.

**D-2 Discriminant (wild, exploratory).** Same for G, G/KLOC, P, P/KLOC.

## 6. Pre-stated readings

- **K-1:** known-groups validity is *supported* when p ≤ 0.05 and δ ≥ 0.33; *direction only* when δ > 0 but either
  condition fails; *not supported* when δ ≤ 0. Same reading words for K-3 and K-4 (K-4 is exploratory regardless).
- **D-1, blocking density:** B/KLOC is *not a size proxy* when |ρ| ≤ 0.3 against both LOC and files. If the 95% CI of
  either ρ extends beyond ±0.3, the reading is qualified "consistent with, not established" (n = 15).
  |ρ| > 0.3 against either size measure reads *density still size-related*.
- **D-1, counts:** B is expected to correlate positively with size (a raw count); that is not a failure. The
  expectation for the advisory metric family is ρ(C, LOC) ≥ 0.5 ("advisory metrics track size"). If C does *not*
  track size while B does, the contrast the job asks about is reversed and is reported as such.
- Null results are reported. No causal language. Every number in the report carries the development-set banner.

## 7. Limits stated in advance

Small n (15 and 14); groups from names; the external specs were all authored by one session; the wild specs are
inferred and its measure is not the v1.3 blocking verdict; the two sets differ in instrument, era (pre-2023 pins vs
current heads) and selection rule; no construct switch is applied (status-quo scoring only).
