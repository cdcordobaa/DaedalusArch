### Incorrect findings, and the one checker fix

**Final run: none.** No tool-defect candidate was found.

The first reference pass flagged 2 findings, both FF-DT03 `value-object-immutability`. **Both were checker defects, not tool defects:**

| Project | File | Tool's claim | First-pass checker reason |
|---|---|---|---|
| ddd/g01-value-object-setter-accessor | src/ordering/domain/value-objects/Quantity.ts | mutable through `Quantity.value (set accessor)` | "Quantity declares no non-static method value (set accessor)" |
| ddd/v03-mutable-value-object | src/ordering/domain/value-objects/Quantity.ts | mutable through `Quantity.value (public mutable field), Quantity.setValue (mutator method)` | "Quantity declares no non-static method setValue (mutator method)" |

**Why the checker failed.** It was written for the frozen setter-name proxy, whose discriminator is `Quantity.setValue`. It could not parse the clause list of the v1.3 member-fact template from #90.

**The tool's claims are true in the code.** g01 has `set value(v)`. v03 has the constructor parameter property `public value: number`, which is not readonly, and `setValue()`, which assigns `this.value`.

**The fix.** `correctness.ts` now checks each listed member against its clause, read independently with the TypeScript compiler API (`source-facts.ts` `MemberFacts`):
- (a) a public, non-readonly, non-static field or parameter property;
- (b) a non-static `set` accessor;
- (c) a public non-static method or arrow-function property that assigns `this.<field>`.

The old proxy form is still accepted. A new test confirms both rows and turns them incorrect when a clause is swapped or a member is invented.
