# v1.3 options effects: each overnight extractor and noise option, alone and combined (2026-10-16)

> **DEVELOPMENT-SET AND UNLABELLED NUMBERS.** The 71 reference variants are the cases the v1.3 changes were made
> against, so their figures are not validity estimates. The external and wild projects carry no labels: their counts
> say how much the tool reports, not how much of it is right. **Nothing was tuned.** No rule, tier, preset, Cypher
> template or option default was changed.

Branch `v1.3-options-effects`, cut from `origin/v1.3` at `9768def4`. Engine: `--engine cypher-interp` for every
`evaluate` run. No Neo4j, no LLM, no `.env`.

**Construct switches are left out on purpose** (`src/construct-switches`). The author has not answered the
score-free answer sheet yet, so no switch was applied and no switch effect is computed or shown here. Every figure
is the status quo construct reading, as committed. That includes the FF-P06 FLOWS_TO rows: removing them is a
switch, so it was not done.

## Summary

1. **Only one of the three overnight units added options.**
   - `v1.3-blind-misses` (already in `v1.3`) added **no extractor option**. Its report found no extractor gap; every
     miss maps to a construct switch, and those are out of scope here.
   - `v1.3-default-view-coverage` added **no option**. The two extractor settings it is about, `reExportEdges: 'both'`
     and `dynamicImports`, are already **on** in `V13_DEFAULT_OPTIONS`, which `evaluate` uses.
   - `v1.3-advisory-noise` added **9 advisory post-filters**, all off by default. These are the options measured here:
     each alone, all 9 together (`all`), and that report's six-option `proposed` set.
2. **No option changes blind-key recall or precision, and none can.**
   - Under every option set, blocking results are identical to the baseline on 71/71 variants, and on all 15
     external projects (verdicts included).
   - Every rule the filters touch is **outside the scored rule set of all five styles**: FF-CV05, FF-C02, FF-C03,
     FF-C04, FF-SO01 and FF-SO02. So the author key and the blind key cannot see these options at all.
   - Blind blocking stays at 53/67 recall [0.68, 0.87] and 53/57 precision [0.83, 0.97] under every set. Author
     blocking stays at 57/57, 57/57.
3. **No option changes graph coverage, and none can.** The filters run after the report is built and never touch
   the graph.
   - External set: the v1.3 literal view covers tsc at 3,717/3,717 (1.000 / 1.000) under every set.
   - Wild set: it covers tsc at 9,946/9,946 (1.000 / 1.000) under every set.
   - Both reproduce the committed figures exactly, project by project.
4. **What the options do change is warning volume on human-written code.** On the 15 external projects:
   - the 955 warning rows fall to 527 under `proposed` (−45%) and to 379 under `all` (−60%);
   - the 283 defining (blocking) rows stay the same.
5. **The live pipeline reproduces the advisory-noise offline measurement exactly.** On the dev set, every per-option
   suppressed count (373, 678, 77, 93, 15, 0, 0, 0, 1,116; `proposed` 524) equals the "Dev advisory" drop in
   `v1.3-advisory-noise-2026-10-16.md` §4. That report had no end-to-end run; this is the first one.
6. **One new effect on human code: `c02-size-scaled`.** It removed nothing on the dev set or E1, where every project
   is under 40 files. On the external set it removes 13 of the 14 FF-C02 rows, in 5 projects over 40 files. These rows
   are unlabelled, so whether that is a gain is not known.

## 5. Which options do what

**Q1. Which options improve blind-key recall without hurting precision?**
- **None.** No overnight option can change blind-key recall.
  - The blind-misses unit made no extractor option. All 14 of its misses map to construct switches, which this run
    leaves out by instruction.
  - The default-view-coverage unit made no option either.
  - The 9 advisory filters act only on rules no key scores.
- The only lever left for blind-key recall is the construct answers. That waits on the author's score-free sheet.

**Q2. Which options raise coverage on human code?**
- **None.** No overnight option touches the graph.
- Coverage of the v1.3 literal view is already 1.000 on both the external and the wild set. It needs no option,
  because `reExportEdges: 'both'` and `dynamicImports` are already v1.3 defaults.

## 6. Recommendation, and the decision for the author

**AUTHOR DECISION (open): which options become default at the freeze.** This run makes no default change. Its
recommendation:

1. **No option should become default on recall grounds.** None of them moves the blind key, and none touches the
   graph.
2. **For warning noise, if the author wants a default-on profile:**
   - **`cv05-no-logic` + `composition-roots`** are the candidates with the cleanest evidence:
     - neither removes a judge-confirmed or manifest-true row on the dev set;
     - neither changes a defining row anywhere;
     - on human code they remove 258 and 36 warnings alone. The pair was not run together, so 294 of 955 is an upper
       bound.
   - **`c03-core-only`** is the next candidate. It removes most FF-C03 rows on human code (166 → 14). It also removes
     one judge-confirmed dev row, but the defect on that file stays reported by a blocking rule. Making it default
     reads FF-C03 differently, so consider pairing it with the ADR on FF-C03 that advisory-noise suggests.
   - **Keep off:**
     - `cv05-no-branching`: it removes domain behaviour;
     - `cv05-rollup`: a presentation choice;
     - `c02-size-scaled`: a new effect on human code (13 rows) with no labels behind it;
     - `c02-abstract-imports`, `c04-entry-points` and `so-framework-members`: no effect on human code.
3. **Before any filter becomes default, label the external warnings.** The 30-row advisory sample in
   `results/v1.3-external/labelling-sheet.csv` is unlabelled. That is the only out-of-sample check these filters
   could get before the freeze.

The questions for the author:
- **D1.** Ship v1.3 with every advisory filter off (as now), or turn on a profile: (a) `cv05-no-logic` +
  `composition-roots`; (b) (a) + `c03-core-only`; (c) the advisory-noise `proposed` set?
- **D2.** Is `c02-size-scaled` kept, given its first effect is on unlabelled human code?
- **D3.** Is `cv05-rollup` a report presentation default (one row per untested project), independent of D1?

## 7. Limits

- **Development set.** The 71 variants are the tuning set. Every rule the filters act on is outside every style's
  scored rules, so the reference keys only show that the filters break nothing scored.
- **No labels on human code.** External and wild figures are counts. The only relevance evidence for the filters is
  one judge run on the dev set (advisory-noise), in-sample.
- **Wild projects: coverage only**, as the task asks. No hand-written spec exists for them, so no warning counts are
  reported.
- **Construct switches** are not applied, computed or shown, by instruction.
