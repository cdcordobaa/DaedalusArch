### 5.3 The real regression: FE grounding rejects 3 true rows

**Which numbers.** All five are in `Docs/DiagnosticRuns/v1.3-judge-v2-2026-10-16.md`. The cassette replay with the
current default code gives:

| line | stated | reproduced |
|---|---|---|
| 133 | 65/66 confirmed | 62/66 = 0.94 [0.85, 0.98] |
| 133 | 0 rejected | 3 rejected |
| 146 | "The other 65 true rows" | 62 |
| 146 | 52/52 blocking | 50/52 |
| 157 | 114/114 distinct answers (309/309 rows) grounded | 111/114 (306/309) |

**What stayed the same.** The plan (`plan.json`) was regenerated byte-identical, and the cassette answers are the
committed ones. The `kept` summary (tp1 65) is unchanged too, because a rejected row is kept.

**Cause.**

- `src/llm-critic/filter-explain.ts:293` checks a bare `line N` against `options.bareLines ?? 'attributed'`.
- That default is R20, "the shown file named last before it in its sentence, else the first shown file"
  (`attributedFile`, `:315`). It came from `533e8780` (neural arm agent tools) and is "v1.3's rule" per
  `scripts/v1.3/filter-explain-run.ts:26`.
- The committed figures used the pre-R20 heuristic, `longest`.
- **Confirmed:** `filter-explain-run.ts score --bare-lines longest` on the same replayed answers gives exactly 65/66
  and 114/114.

**Are the rejections right?** No. All three are false "ungrounded" rejections. In each case the bare line refers to a
file that is not named in its sentence, so R20 falls back to the finding's own file:

| row | explanation | rejected as |
|---|---|---|
| `layered/v05-business-model-cycle` | "…except `customer.id` (line 23)", which is in Order.ts | "line 23 of Customer.ts beyond 18" |
| `hexagonal/v06-outbound-adapter-uses-cli-formatter` | "The same file also holds the BookingCli driving adapter (lines 9-20)" | checked against OutboxNotificationAdapter.ts, 16 lines |
| `ddd/v02-repository-for-inner-entity` | "…`increase`, lines 12-14", which is in Order.ts | checked against OrderLineRepository.ts, 7 lines |

**Consequences.**

- Under the current default, a judge-v2 / FE run reports lower grounding and a lower confirm rate than the committed
  report.
- MT7 noted that D-b keeps #159's R20 opt-in. v1.3's own R20 'attributed' default, from the neural-arm PR, was already
  on, and the merge kept it.

**Not changed.** This changes tool output, so it is left for the author. The options are:

- keep 'attributed' and correct the doc with the new figures;
- make 'longest' the default again;
- improve the attribution, for example with "the same file", or a line number beyond the finding's file but within
  another shown file.
