## Runs and isolation

- **Lock.** Both live runs held the new cross-process Neo4j lock for the whole run (mode `owned`, file `~/.daedalus/locks/neo4j-127.0.0.1_7693.lock`). The `firewall evaluate` children found their ancestor's lock and did not wait. The lock is described in §3, fix 1.
- **Determinism.**
  - `run1` (01:53:57Z to 01:55:44Z) and `run2` (01:56:04Z to 01:57:42Z) produced **byte-identical** `raw/` (71 files), `report.md` and `report.json`.
  - The evidence violations are identical for 71/71 (only `elapsedMs` differs).
  - Scored the same way, `scores.json` and `adjudication.csv` are byte-identical.
  - `validate-reference.ts --from-raw` reproduces `report.md`.
- **Admission bypass.** The heavy-command hook blocked on swap (10.8 to 11.0 of 16 GB) while `memory_pressure` reported 37 to 42% free. The live runs, the graph extraction, `npm ci`, `tsc`, `eslint` and the jest runs were each run with `HEAVY_ADMISSION_BYPASS=1`, one at a time.
- **Blind manifests.** They were read only through `scripts/v1.3/ue-score.ts --blind <daedalus-sealed/v1.3-blind>`, unchanged from the baseline. Nothing else under `daedalus-sealed/` was opened.

## 3. Each fix and its effect

The tool's row changes were attributed by diffing `raw/` between the barrels-only run and this run, variant by variant. They are the complete diff:

| Change in `raw/` | Count | Caused by |
|---|---|---|
| FF-P06 rows removed in layered (all 13 variants; 4 per variant, plus `SalesReportService -> Database` on n02) | −53 | fix 3 |
| FF-P03 `CsvReportWriter.ts` removed (clean n02) | −1 | fix 4 |
| FF-P03 `GatewayRetryPolicy.ts` removed (hexagonal n03) | −1 | fix 4 |
| FF-DS02 `billing/api/InvoiceController.ts -> ordering/application/GetOrderSummary.ts` added (ddd g03) | +1 | fix 6 |
| any other row, in any of the 71 variants | 0 | |

1. **Neo4j isolation (fix 1).**
   - **Mechanism.** `src/shared/process/neo4j-lock.ts`:
     - a lock file per `host:port` in `~/.daedalus/locks/`, created with `O_EXCL`, holding pid, host, label and token;
     - stale when the pid is dead, broken under a breaker file and only if the token still matches;
     - re-entrant for the holder's descendants;
     - released by token or by an exit handler.
   - **Who holds it.**
     - The pipeline's repository, from the first query (the wipe) until `cleanup()`. This covers every `evaluate`, batch, drift and MCP run.
     - `validate-reference` live mode, for the whole run.
     - Every jest suite that can reach Neo4j, from `beforeAll` to `afterAll` (`tests/setup/neo4j-lock.setup.ts`, in every jest config).
   - **Tests.** `neo4j-lock.test.ts` checks that two concurrent processes never overlap. A manual check: a jest Neo4j suite started while a fixture process held the lock printed `waiting for the Neo4j lock …`, then ran once the holder released it.
   - **Effect.** Both runs were isolated, and run1 equals run2.
2. **Cycle matching (fix 2, scoring code).**
   - **Change.** `compare.ts` matches FF-S02 on the set of files in the cycle.
   - **Effect.** The runner's 5 FF-S02 misses and 5 FF-S02 false positives became 5 matches: clean v03, layered v05 and v06, nestjs v04, hexagonal v11. The runner's `report.md` now equals the `author-cycle-normalised` view, which `ue-score.ts` already reported. No tool row changed.
3. **FF-P06 not applicable in `layered` (fix 3, ADR-V13-02 draft).**
   - **Effect.**
     - 53 rows removed, the layered clean variant passes, and layered's three near-misses are silent.
     - Layered blocking precision: 11/64 → 11/11 (author) and 7/64 → 7/11 (blind).
     - No recall was lost: no manifest expects FF-P06 in layered.
   - **Side effect.** `validate` on `presets/layered.yaml` now prints `compiled 17, disabled 10`, with FF-P06's reason (was 18/9). `cli-validate.test.ts` was updated with that reason.
4. **Role tokens (fix 4).**
   - **Effect.** The two FF-P03 rows were removed, so clean and hexagonal blocking precision reached 13/13, and their near-misses n02 and n03 are silent. No other FF-P03, FF-P04 or FF-P05 row changed.
   - **Remaining misses.** The FF-P05 misses on clean v07 and nestjs v09 (entities with no role suffix, TDC-1, advisory) remain, as expected: suffix matching does not invent a suffix.
   - **FF-P02 sibling injection.** Checked and **not changed**. The rule is not name-based; the n03 row is a correct reading of its ratio condition; and whether DIP excludes a same-layer concretion is RDQ-3, an open author decision. The row is advisory.
5. **Edge views for the other IMPORTS readers (fix 5).**
   - **Change.** The universal metrics (in the v1.3 scoring mode), the drift detector, the judge's graph view and the report graph read the literal view (`Docs/v1.3/edge-views.md`, addendum 2026-10-15).
   - **Effect.** No finding changed, as expected: these readers do not feed the templates.
   - **Check on Neo4j.** The literal metric queries run without `METRIC_001`. On a v1.2E graph they equal the frozen ones (`v13-edge-views-neo4j.test.ts`).
6. **DDD context-isolation reads the literal barrel edge (fix 6).**
   - **Effect.** g03's deep import is found, so M2 is closed: DDD blocking recall 7/9 → 8/9, and the planted rule is detected in 11/12. The import through the barrel (g02), n01 and the clean variant stay silent. DDD precision stays 1.00.
   - **Remaining miss.** FF-DT03 on g01 (M3, a `set value` accessor). It needs member facts from the extractor.
