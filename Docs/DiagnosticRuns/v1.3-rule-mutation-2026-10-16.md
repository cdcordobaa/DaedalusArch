# v1.3 rule mutation analysis, 2026-10-16

**Question.** If a rule's Cypher were subtly wrong, would the validation set notice? The validation set has three parts: the 71-case reference set (author key and blind key), the second development set devset-b (PR #137, 207 − 71 = 136 cases), and the unit tests.

**Harness.** `scripts/v1.3/rule-mutation.ts`. **Results.** `results/v1.3-rule-mutation/rule-mutation-2026-10-16.json`: every mutant with its edit, status per key, killing cases, unit-test failures, and the controls. Branch `v1.3-rule-mutation` from `origin/v1.3` at `50a32841`. Nothing is merged.

## 1. Answer in one paragraph

On the 22 scored rules there are 290 mutants; 273 can be measured on the interpreter (FF-P05 cannot, §4.1). The reference set and devset-b together change an expected-violation result for **90 of the 273 (33%)**. That reading is strict: some expected finding flips between matched and missed. Counting mutants that only add or remove false positives on clean or near-miss cases, the figure is **130 (48%)**.

The operators split cleanly:
- **Caught almost always:** a flipped comparison (28/29), a removed NOT (20/21), a swapped layer parameter (9/9). These invert the rule, so every planted violation flips.
- **Rarely caught:** dropping a WHERE conjunct (9/67 strict, 41/67 with false positives), widening or narrowing a label or type (22/80), and changing a variable-length bound (2/6).
- **Never caught:** ORDER BY (0/59) and DISTINCT (0/2).

Most of the misses are equivalent mutants (§6 groups B and C). The real blind spots are fewer and specific (§6 group A, 14 items). Most concern edges of the rule the set never exercises: re-export-only violations, the cycle-length bound, role-named classes outside their layer, events reached by inheritance, and adapters that use a port without implementing it.

The unit tests fail on 116 of the 273 measured in-scope mutants, plus 13 of the 17 unmeasurable FF-P05 mutants (129 of all 290 in-scope). Every such failure comes from a test that **asserts on the template text**, or that runs the evaluator over a stub repository returning canned rows. No unit test in this container runs a template against a graph (the Neo4j-gated suites skip without a database). So unit tests notice an edit, but they cannot tell a wrong edit from a correct one. Mutants that survive both the sets and the unit tests: **106 of 273**. Of these, 34 are ORDER BY, 23 are noticed through false positives only, and 49 are listed in §6.

## 2. Method

**Mutants.** The harness generates one mutant per site, for each catalogue entry the v1.3 compile can read: `CYPHER_TEMPLATES`, `HEXAGONAL_TEMPLATES`, `DDD_TEMPLATES`, `DDD_LITERAL_VIEW_TEMPLATES`, `DDD_MEMBER_FACT_TEMPLATES`, `V13_CYPHER_TEMPLATES`, `APG2_TEMPLATES` and `CHEAP2_TEMPLATES`. String literals and comments are masked before scanning. The eight operators:

| Operator | Edit |
|---|---|
| flip-comparison | `= <> < <= > >=` to its negation |
| drop-conjunct | one top-level `AND` term of a WHERE, or the whole WHERE when it has a single predicate |
| label-rel | drop one node label (widen); drop a relationship type list (widen); drop one alternative of `A\|B` (narrow) |
| var-length | the min or max of `*a..b` by ±1, or bound an open range |
| remove-not | delete one `NOT`; `IS NOT NULL` becomes `IS NULL` |
| swap-layer-param | swap two layer or role parameters, or one occurrence of one |
| remove-distinct | delete one `DISTINCT` |
| order-by | reverse the keys, drop the first key, or make the first key DESC |

The run produced 795 texts. 32 do not parse under the interpreter's grammar and are recorded as stillborn: mostly `any()` / `none()` without WHERE after a dropped predicate, which Neo4j rejects too. Each entry also gets two controls, which are not scored:
- `canary`: the MATCH is replaced by a pattern that matches nothing. This checks that the entry is the text the compile reads.
- `whitespace`: a trailing newline. A unit test that fails on it pins the text, not the behaviour.

The DDD entries `context-isolation` and `value-object-immutability` are shadowed under `V13_COMPILE_OPTIONS`: the compile reads the literal-view and member-fact texts instead. Their effective texts are mutated, not the shadowed ones.

**Isolation.** No template file is edited. Each mutant replaces one Map entry in memory, inside a worker process. For jest, a setup file generated in the scratch work directory does the same in the test's module registry, through the `RULE_MUTANT_FILE` environment variable. `git status` shows the templates and tiers untouched. The branch diff adds only the harness, the results JSON and this report.

**Engine and run.** The pipeline is the one `firewall evaluate --symbolic-only --engine cypher-interp` builds: scoring v1.3, instrument v2 and `V13_COMPILE_OPTIONS`, run in process.
- Every case is materialised once.
- Each mutant runs only the styles whose compile reads the entry. This is recorded from the catalogue `.get` calls during the baseline; a style that never reads the entry cannot see its mutant.
- The APG extraction is template-independent, so it is cached per project in each worker. The baseline checks that a cached pass equals an uncached one, case for case, and it does.
- Two workers ran, with a 300 s per-mutant watchdog. None timed out or crashed.

**Keys and the kill rule.**
- *Author key*: each variant's `expected-findings.json`, in the reference set and in devset-b.
- *Blind key*: the blind manifests are sealed outside the repository (`daedalus-sealed/`, absent here). The harness rebuilds the **blind-expanded** key from the committed U-E adjudication sheet (`results/v1.3-reference/baseline-pre-barrel/adjudication.csv`). It takes the pre-barrel tool rows in scope, removes those adjudicated `blind = none`, and adds the scored `blind = finding` rows where the tool was silent. Scored against the pre-barrel rows, the rebuild reproduces the committed `scores.json` blind-expanded TP/FN/FP **exactly for all five styles** (clean-architecture 15/5/1, layered 7/3/57, nestjs 12/5/2, hexagonal 14/9/3, DDD 10/2/0). The check is stored in `blindKeyCheck`.
- *Killed (strict, the headline)*: on some case of some key, an expected finding changes between matched and missed. Matching is `compareVariant` from `scripts/v1.3/lib/compare.ts`, so FF-S02 is matched on its file set, as in the reference runner.
- *Killed incl. FP-only*: also counts a change in the in-scope unexpected rows (false positives appearing or disappearing).
- *Unit killed*: a test in the catalogue's suite fails under the mutant but passes unmutated. The suite is every `tests/unit` file that imports the catalogue file. Tests that also fail under the whitespace control are text pins and are not counted. Jest ran with `--maxWorkers=2` and `--runTestsByPath`.

**Equivalence probe (not a key).** Each surviving mutant also ran on the five golden fixtures (`fixtures/correct-reference`, `variant-a..d`) under `specs/clean-arch.yaml`. A survivor that changes their rows is not equivalent: the behaviour differs on real code and the set misses it. The probe covers only the `cypher` catalogue templates compiled for clean-architecture.

## 4. Findings beyond the score

### 4.1 FF-P05 `controller-no-entity` cannot be mutation-tested on the interpreter, and finds nothing on Neo4j either

Under `V13_COMPILE_OPTIONS.signatureTypes`, the compiled FF-P05 query wraps the frozen branch and the SIGNATURE_USES branch in `CALL { … UNION … }`. The interpreter rejects this (`unsupported: clause subqueryClause`), and the pipeline logs EVAL_001 and drops the rule's rows. That happens on all 80 clean-architecture and nestjs cases and on the 5 golden fixtures.

The committed Neo4j run has **no FF-P05 row on any of the 71 cases** either; v07 and v09 are recorded misses. That is why the interpreter still agrees 71/71. The "byte-identical on the 71 cases" claim for the interpreter (night plan, #128) is therefore silent on FF-P05: both engines return nothing, for different reasons. Its 17 mutants are reported as `unmeasurable-on-interp`. Measuring them needs the Neo4j engine (not run here: no database, and `.env` was not read).

### 4.2 Eighteen of the compiled templates are invisible to the reference set by design

- 15 `cypher` templates are compiled for every style but appear in no style's `scopeRules`, so their rows are never scored: the metric, naming and proxy rules (abstraction-ratio, component-instability, domain-stability, inheritance-depth, interface-segregation-proxy, max-fan-in, module-fan-out, naming-*, no-index-logic, no-orphan-files, single-responsibility-proxy, test-file-pairing). 0 of their 175 measurable mutants are killed by any key. Yet **30** of those survivors change rows on the golden fixtures, so these mutants change what the tool reports and nothing scores it.
- The 16 `apg2` / `cheap2` / `v13` templates are never compiled under the reference specs (they need extractor options the specs do not set). All 190 of their mutants are `not-exercised`.

For all of these, the unit tests are the only detector, and they catch 107 of 365, all by text.

### 4.3 The unit tests are syntactic

The tests that fail under mutants are listed in the JSON (`behaviouralFailures`). The ones that fail most often:
- `k7-order-by` (57 mutants)
- `v13-edge-views` (50)
- `v13-fix-round` (26)
- `apg2-templates` (26)
- `k8-exclude-anchors` (24)
- `k12-re-exports` (23)
- `apg2-scope` (20)
- `metric-filters` (19)
- `k10-fr12-columns` (18)
- `k6-cycle-query` (14)

They assert on the template text: regexes for the bound, the anchors, the ORDER BY keys and the edge types. Some run `evaluateSymbolic` over a stub `GraphRepository` that returns canned rows. None of the tests that failed runs the Cypher against a graph.

Eight tests are text pins: they fail on the trailing-newline control, because they compare the text byte for byte (`domain-purity` / `domain-state-purity` §2.1/§2.2 exact, `k10` cycle grouping, `k13`, and the v13 compiled-text tests). These kill every mutant of their template, so they are excluded from the unit score (`unit text-pin only`: 32).

Consequence: a unit test kills a mutant whenever the mutated text breaks one of its assertions, however equivalent the mutant is. And a *correct* refactor of a template fails the same tests. The unit-test score here measures how tightly the text is pinned, not whether the rule is right. The behavioural tests that could tell the difference (`ddd-neo4j`, the golden suites, the Neo4j-gated K-tests: 32 skipped) need Neo4j. They were not run.

### 4.4 Eleven kills come from a loud failure, not a wrong answer

11 of the 90 strict kills are mutants for which the tool fails instead of returning different rows.
- **Compile-time guard (5).** The v1.3 role-token rewrite (`v13-role-names.ts`) throws "role names: <template> no longer contains …" when the text it rewrites has changed. Mutants: `repository-pattern/drop-conjunct/2`, `use-case-isolation/drop-conjunct/2`, `port-adapter-pattern/drop-conjunct/2`, `port-adapter-pattern/swap-layer-param/1` and `/3`. The compile then fails for the whole style, every expected finding is missed, and the mutant counts as killed. This is a defence in the compiler, not in the validation set. Any edit to those role-name clauses is caught, right or wrong.
- **Runtime type errors (6).** A scalar layer parameter swapped into a list position (`IN $applicationLayers`, `IN $forbiddenImports`, `IN $adapterRoles`), or `(t OR …)` after a label was dropped from a WHERE label test. The query fails with EVAL_001 and the rule's rows vanish. Neo4j would raise the same type errors.

The JSON keeps the error text of each under `reference.errors`.

## 6. Surviving mutants of the scored rules: blind spots and the minimal killer for each

Survivors are grouped by what they show: 

- **A. Real blind spots.** The mutant changes the rule, and some code would tell the difference. No case in the validation set has that code.
- **B. Equivalent on the extractor's graph schema.** A label or type is widened, but the APG has no other node or edge of that shape, so no project can tell the difference today. This is a gap in the unit tests, not in the reference set.
- **C. Logically equivalent.** A redundant guard or a downstream canonicaliser makes the mutant equivalent. No variant or test can kill it, and none is proposed.

The proposals are **not** added (task rule); each is the smallest change that should flip a result. "Variant" is a new reference-style variant: a patch plus `expected-findings.json`, written before any tool run, as the README requires. "Test" is a unit test on a hand-built `MemoryGraphRepository` graph, the pattern the cypher-interp suites already use.

### B. Equivalent on today's graph schema (unit test, not a variant)

Widening `(src:File)` / `(tgt:File)` / `(p:Package)` / `(c:Class)` / `(m:Method)`, or dropping the relationship type in a `File->File` / `Class->Class` pattern, survives for every rule (dependency-direction, no-layer-skip, no-domain-outward-dep, domain-purity, no-cyclic-deps, domain-state-purity, dependency-inversion, repository-pattern, use-case-isolation, the five hexagonal templates, aggregate-boundary, repository-aggregate-root, context-isolation, application-service-thin, value-object-immutability, bounded-context-modules). Only IMPORTS/RE_EXPORTS connect two files, and only classes carry CONSTRUCTOR_INJECTS. No source project can kill these mutants. If a later extractor option adds an edge of the same shape (APG v2 SIGNATURE_USES, MODULE_IMPORTS, HOLDS_STATE_OF), they turn into live bugs.

**Minimal killer:** one table-driven unit test per catalogue. It builds a `MemoryGraphRepository` with one decoy per pattern: a `File->File` edge of another type, and a node without the label but with the same properties. It then asserts each template returns no row for the decoy. One test kills every B mutant of that catalogue.

`hexagonal/dependency-direction-graph/drop-conjunct/4` (drop `NOT (src>tgt) IN $allowedDependencies`) belongs here too. It differs only when both `a>b` and `b>a` are allowed, which no preset does. **Killer:** a unit test with a symmetric `allowedDependencies` pair that expects no row.

### C. Equivalent (no killer proposed)

- **Null guards** made redundant by a later conjunct: `src.layer IS NOT NULL` and `tgt.layer IS NOT NULL` in dependency-direction, no-layer-skip, the hexagonal layer templates and core-isolation; `dep.layer IS NOT NULL` in use-case-isolation. `apoc.coll.indexOf(…, null) = -1` fails `>= 0`, and `null + '>'` is null, so the `IN` test is null.
- **Implied conjuncts:** `src.layer <> tgt.layer` in dependency-direction (`srcIdx < tgtIdx` implies it); `srcIdx >= 0` / `tgtIdx >= 0`; `totalDeps > 0` in both dependency-inversion templates (the MATCH guarantees one dependency); `size(srcCtx) > 0` / `size(tgtCtx) > 0` in context-isolation (`srcCtx[0] <> tgtCtx[0]` is null on an empty list).
- **The rotation filter** `ALL(n.filePath >= f.filePath)` in no-cyclic-deps: the evaluator's cycle canonicaliser deduplicates rotations downstream.
- **ORDER BY (all 62 in-scope order-by mutants):** the evaluator and the scorer treat rows as a set. The only `LIMIT` is the cycle cap (101 rows), which no project reaches. An order-sensitive test would kill these only if row order is meant to be part of the contract (BR-U1-28: truncation keeps the first 100 by `ORDER BY cycle`). If it is, the killer is a unit test with 101+ cycles that asserts which 100 survive.
- **`(t:Class OR t:Interface)`** in domain-state-purity: FLOWS_TO and CONSTRUCTOR_INJECTS end only on types.

## 7. Limits

- **Engine.** The interpreter, not Neo4j. It agrees with the committed Neo4j outputs on all 71 cases, but FF-P05 is unmeasurable (§4.1). Parity on each mutated text is assumed, not checked: a mutant could hit an interpreter gap that Neo4j would not. No mutant ended with only an error and unchanged rows.
- **Operator sites are syntactic.** The swap-layer operator only swaps parameters that appear in the same template, so a template with one layer parameter gets no swap mutant. The label-rel operator does not touch label predicates in WHERE (`x:Interface`); those are reached through flip and remove-not only where they sit next to a comparison.
- **Blind key.** The blind key is the rebuilt blind-expanded view. The blind-primary view needs the sealed manifests.
- **Probe.** The equivalence probe covers only the clean-architecture `cypher` templates. Hexagonal and DDD survivors are classified by reading the template (§6 B and C), not by a probe.
- **Tests not run.** The Neo4j-gated unit tests did not run (32 skipped).
- **AI-DLC audit.** No AI-DLC gate was run interactively: the request came from a scheduled task with no one present, and its rule allows committing only the harness and the results (plus this report). `aidlc-docs/audit.md` is not updated on this branch.
