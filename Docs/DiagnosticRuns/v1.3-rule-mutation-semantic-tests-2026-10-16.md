# v1.3 rule mutation, after semantic tests, 2026-10-16

**Question.** The first mutation run (`v1.3-rule-mutation-2026-10-16.md`, PR #190) found 14 real blind spots, and found that no unit test runs a rule's Cypher against a graph. If the scored rules get semantic tests (the real compiled query, run on small hand-built graphs), which mutants do they kill, and what still survives?

**Branch** `v1.3-mutation-tests`, from `v1.3-rule-mutation` at `39a84bd4`. **Suite** `tests/unit/semantic-rules/`. **Results** `results/v1.3-rule-mutation/after-semantic-tests/rule-mutation-semantic-2026-10-16.json`. No template, tier, spec or fixture is changed. The Cypher is unchanged and canonical; this branch adds tests, two harness steps, the results and this report.

## 1. Answer

On the 273 measurable in-scope mutants, the strict kill-rate goes from **90 (33%) to 164 (60%)**. "Strict" means a behavioural kill: an expected finding of the reference set or devset-b flips, or a semantic test fails. The text-asserting unit tests are left out of this figure.

The other **109 are equivalent**, and each is marked in the JSON (`after.equivalent`) with its reason:
- **76 logically equivalent (group C).** 58 are ORDER BY. The others are redundant null guards, implied conjuncts, and duplicates that the evaluator removes downstream.
- **33 equivalent on today's graph schema or configuration (group B).** No project can tell these apart today. A new extractor edge or a new preset could.

So **no non-equivalent in-scope mutant survives**. All 14 blind spots are covered:
- 12 by a killed mutant.
- 2 (the DISTINCT halves of A10 and A11) turn out to be logically equivalent. They are reported as such, not killed by fiat.

Treat the 100% with caution: I wrote the equivalence table after seeing the survivors (see §5).

## 2. The suite

`tests/unit/semantic-rules/`:
- `semantic-harness.ts` has the graph builder and the runner. It writes the hand-built APG through the real ingestion statements (`ingestNodes` / `ingestEdges`) into `MemoryGraphRepository` (cypher-interp). It compiles the style's reference spec with the v1.3 pipeline options (`V13_COMPILE_OPTIONS`, instrument v2), then runs the rule's compiled query through `evaluateSymbolic`. Edge views, role-token rewrites, the cycle canonicaliser and `mergeById` all run as in the pipeline.
- `cases.ts` holds 123 cases for the 22 scored rules across the five reference styles (clean-architecture, layered, nestjs, hexagonal, DDD). Each case is a violating, clean or near-miss graph with its exact expected finding set.
- `semantic-rules.test.ts` runs the cases. It also checks the table itself: every (style, rule) has a violating case and a clean or near-miss case, and A1–A14 are all covered.

Run time is about 5 s. No Neo4j, network or LLM. Findings are compared as sets. The one exception is the cycle cap: BR-U1-28 says it keeps the first 100 cycles by `ORDER BY cycle`, and a 101-cycle case pins that.

The expectations encode what the frozen text says. Where that is a definitional choice rather than an endorsement, the case's `why` says so:
- A2: an 11-file cycle is not a finding.
- A3: a self-import is not a cycle.
- A12: implementing an abstract class is not implementing an Interface.

**FF-P05.** Under `signatureTypes` its query is `CALL { … UNION … }`, which the interpreter rejects (first report §4.1). Its cases therefore compile with `signatureTypes: false`. They test the frozen catalogue branch, not the SIGNATURE_USES branch.

## 3. Method

The harness `scripts/v1.3/rule-mutation.ts` has two new steps:
- `--only semantic` runs the semantic suite under every valid mutant and control: 763 jest runs, `--maxWorkers=2`, 2 jobs, about 12 min. It uses the same generated in-memory setup file as the first run's `jest` step.
- `--only score-semantic` merges those results with the committed first-run JSON. That JSON supplies the reference/devset outcome and the earlier unit-suite outcome per mutant.

The mutant plan was regenerated: the same 795 texts, with ids and descriptions identical to the committed JSON. The interpreter baseline was re-run and again agrees with the committed Neo4j outputs on 71/71 cases.

**What was not re-run.** The reference/devset mutant step and the earlier unit suites were not re-run (about 3 h). Their inputs are unchanged (the templates, fixtures and those test files are untouched, and the semantic files do not match the harness's per-catalogue suite selection), and both steps are deterministic. A full `--only jest` re-run would therefore give the same unit results. I did not verify that by running it.

**Controls:**
- Unmutated, the semantic suite passes: 126/126.
- The trailing-newline control fails no semantic test, so there are no text pins.
- The canary (the rule's MATCH replaced by one that matches nothing) is killed for every in-scope entry, which shows the suite reads the entry the compile reads.
- No out-of-scope mutant or canary is killed: the suite targets the scored rules only.

## 4. Kill rates per operator (in-scope, measurable: 273; FF-P05 separately)

- **The 40 false-positive-only mutants.** All 40 that the first run caught only through new false positives on clean or near-miss cases are now killed strictly.
- **The earlier text-asserting tests still add kills: 201 vs 164.** All 37 they add are mutants classified equivalent here: 24 ORDER BY, 10 label-rel, 2 drop-conjunct and 1 DISTINCT. That is the first report's point: a text test also fails on a correct refactor.
- **FF-P05 (17 mutants, unmeasurable on the sets).** The semantic suite kills 12 through the frozen branch; one of those is a loud kill. The other 5 are equivalent: 3 ORDER BY, plus 2 schema mutants (`label-rel/1`, `label-rel/4`). The v1.3 UNION query itself is still not measured on the interpreter.

**Loud kills.** 11 semantic kills are a failure rather than a wrong finding set:
- 5 through the v1.3 role-name compile guard, which throws for the whole style.
- 6 through type errors from a scalar parameter swapped into a list position or a label test turned into a node.

The kill counts include them, and the JSON marks them `killed-loud`.

## 5. What is still not killed, and why

**The 14 blind spots:**

| # | Mutant(s) | Semantic case | Result |
|---|---|---|---|
| A1 | no-cyclic-deps `*2..9` | `layered-s02-ten-file-cycle` | killed |
| A2 | no-cyclic-deps `*2..11` | `layered-s02-eleven-file-cycle` | killed |
| A3 | no-cyclic-deps `*1..10` | `ca-s02-self-import` | killed |
| A4 | no-cyclic-deps simple-path guard | `nestjs-s02-figure-eight` | killed |
| A5 | drop `\|RE_EXPORTS` (no-cyclic-deps, layer-skip-graph, core-isolation, repository-aggregate-root; also dependency-direction) | re-export-only cases per rule | killed (all 5) |
| A6 | repository-pattern drop `c.layer = $infraLayer` | `ca-p03-repository-outside-infrastructure` | killed |
| A7 | port-adapter-pattern drop `c.layer = $infraLayer` | `hex-p03-adapter-name-outside-adapters` | killed |
| A8 | use-case-isolation drop `uc.layer IN …` | `ca-p04-use-case-name-outside-application` | killed |
| A9 | value-object-immutability drop `NOT f IN staticFields` | `ddd-dt03-static-fields` | killed |
| A10 | domain-event-placement drop `\|EXTENDS`, `*1..2` | `ddd-dt05-event-by-inheritance` | killed |
| A10 | domain-event-placement remove DISTINCT | same case (a class with two paths) | **equivalent**: the duplicate rows have the same violation id and `mergeById` merges them |
| A11 | no-cyclic-deps remove DISTINCT | `ca-s02-cycle-closed-by-reexport` (parallel IMPORTS and RE_EXPORTS) | **equivalent**: the next `WITH cycle, min(firstLine)` groups by cycle anyway |
| A12 | widen `(:Interface)` (repository-pattern, port-adapter-pattern) | `*-implements-abstract-*` | killed. The expectation (an abstract base is a finding) is the frozen text's; the author may want to revisit it |
| A13 | port-adapter-pattern drop `:IMPLEMENTS` | `hex-p03-injects-port-without-implementing` | killed |
| A14 | domain-state-purity drop the edge types | `ca-p06-extends-infrastructure-base` | killed |

**Survivors marked equivalent: 109 measurable, plus 5 FF-P05.**

*Group C, logically equivalent (76):*
- ORDER BY: 58, plus 3 FF-P05.
- Null guards (`*.layer IS NOT NULL`): 10.
- Implied conjuncts: 5. These are `src.layer <> tgt.layer` given `srcIdx < tgtIdx`, `totalDeps > 0` ×2, and `size(ctx) > 0` ×2.
- Downstream deduplication: 3. These are the two DISTINCTs and the `(f:File)` widening in bounded-context-modules, where a Class row has its File's filePath and merges into it.

*Group B, schema or config (33):*
- 29 schema mutants:
  - 20 `:File` widenings or relationship-type changes on File patterns (only Files carry IMPORTS/RE_EXPORTS);
  - 3 `:Class` widenings where only classes carry CONSTRUCTOR_INJECTS;
  - 2 in domain-state-purity (FLOWS_TO/CONSTRUCTOR_INJECTS start at classes and end on types);
  - 2 in application-service-thin (`:Method` / `:CONTAINS`);
  - 1 `:Package` widening (a file name is never a package specifier);
  - 1 member-fact `:Class` widening.
- 4 config conjuncts. `$layerOrder` is the spec's whole layer list (×2). No preset allows a symmetric pair, or a layer to itself.

These would become live bugs if the extractor gained an edge of the same shape (for example APG v2 SIGNATURE_USES or MODULE_IMPORTS) or a preset allowed a symmetric pair.

**One finding from group B.** The `IMPORTS` alternative in FF-P05's frozen branch, `(ctrl:Class)-[:IMPORTS|CONSTRUCTOR_INJECTS*1..2]->(entity:Class)`, is dead code on the APG schema. IMPORTS starts at a File and never connects two classes, so dropping it changes nothing. The frozen FF-P05 can only find controllers that reach an entity through injection.

**Caveats:**
1. **The equivalence table was written after seeing the survivors**, by reading each template. A mutant I called equivalent might be killable by a graph I did not think of. The table is in the harness (`EQUIVALENT`), and `score-semantic` fails if a listed mutant is killed behaviourally or an in-scope survivor is unlisted. It cannot check that the reasons are right.
2. **"Killed" means "differs from my expected set".** The semantic cases encode the frozen text's behaviour. They show that a mutant changes behaviour, not that the frozen behaviour is the right design (A2, A3, A12).
3. **Hand-built graphs, not extractor output.** The cases assume these graph properties:
   - `viaReExport` / `reExportHop` on IMPORTS edges;
   - member-fact property names;
   - FLOWS_TO only from classes;
   - Method nodes taking their file's layer.

   I took these from the extractor and annotator code. If the extractor drifts, a case can stay green while describing a graph no project produces.
4. **Interpreter, not Neo4j.** Parity on each mutated text is assumed, as in the first run.
5. **Out of scope.** The 365 mutants of the unscored and never-compiled templates (metrics, naming, apg2, cheap2, v13 module wiring) are untouched by this suite: 0 killed. Their only detector is still the text-asserting unit tests.
6. **AI-DLC.** No AI-DLC gate was run interactively. The request came from a scheduled task with no one present. `aidlc-docs/audit.md` is not updated on this branch.

## 6. Reproduce

```
npx jest --maxWorkers=2 tests/unit/semantic-rules
npx tsx scripts/v1.3/rule-mutation.ts --work <scratch> --only plan
npx tsx scripts/v1.3/rule-mutation.ts --work <scratch> --only semantic --jobs 2        # ~12 min, 763 jest runs
npx tsx scripts/v1.3/rule-mutation.ts --work <scratch> --only score-semantic           # --before defaults to the committed first-run JSON
```

`--only plan` also runs the interpreter baseline the first time. Without `--devset` that baseline covers the reference set only, which is enough for these steps.
