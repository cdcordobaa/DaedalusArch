# v1.3 K2: spec-author reliability on the external set (plan, blinding and pass criterion)

Status: committed BEFORE any second-author spec is written and before anything of #133 other than
`results/v1.3-external/selection.json` is read. Development-set / exploratory: nothing here claims validity on its own.

## Question

How much do the external set's results (#133, branch `v1.3-external-set`) depend on who wrote the spec? A second
spec author (spec set **B**, this session) writes one spec per repo for the same 15 repos; the first author's
specs (set **A**, #133) are then compared file by file and verdict by verdict.

## Blinding (what author B saw)

- Read from `origin/v1.3-external-set`: ONLY `results/v1.3-external/selection.json` (id, URL, pinned SHA, claimed
  style, analysis root, tsconfig, style claim, why, notes, provenance; the `rejected` list).
- NOT opened before the B-spec commit: `results/v1.3-external/specs/`, `spec-rationale.md`, `findings/`,
  `summary.json`, any report or PR text of #133, and any other file on that branch.
- Known to B anyway (cannot be unread, stated for honesty): the night backlog's one-line summary that "10 of 15
  human-written repos fail" and that the set has "283 blocking findings". No per-repo number is known to B.
- Inputs B uses per repo: the cloned tree at the pin, its README, and the preset of its claimed style
  (`presets/<style>.yaml`). Nothing else.
- Proof of order: the commit adding `results/v1.3-spec-author-b/specs/` is pushed before any commit that reads A;
  its commit time and the order of commits on `v1.3-spec-author-reliability` are the blinding record.

## B's authoring protocol (fixed before writing)

1. Start from the claimed style's preset, copied verbatim.
2. Author choices are limited to: layer `directories` (and `file_patterns` if needed), layer names only when the
   preset's names are kept (B keeps them), `allowed_dependencies` only for the layers the preset already has,
   and `default_exclude_paths` (B adds only test, mock, fixture, migration/seed and build-output folders found in
   the tree). Fitness-function blocks, thresholds and weights stay exactly as in the preset.
3. One mapping rationale per repo (`results/v1.3-spec-author-b/spec-rationale.md`).
4. Every B spec must pass `firewall validate` against its repo root.

## Measures (computed only after the B commit)

Unit of agreement: every `.ts` file tracked by git under the repo's analysis root at the pin, excluding
`node_modules/`, `dist/` and `*.d.ts`. Each file gets one label per spec set:

- the layer name it resolves to (`resolveLayer`, the same picomatch first-match rule as the graph's layer annotator),
- `excluded` if it matches that spec's `default_exclude_paths`,
- `unmapped` otherwise.

1. **File-to-layer κ (primary).** Cohen's κ over files per repo, labels as above with layer *name*; when A and B
   use different layer-name sets for a repo, the label is the layer's resolved `kind` instead (and this is said).
   Secondary: κ on resolved `kind` for every repo, and κ restricted to files both sets map to a layer.
   When expected agreement is 1 (one label only), κ is undefined; report raw agreement.
2. **Disagreements.** Every file mapped differently, grouped by reason class: `directory-choice` (both map, to
   different layers), `mapped-vs-unmapped`, `excluded-vs-included`, `role-naming` (same directory, a different
   layer owing to a file-pattern/role rule).
3. **Blocking counts.** All 15 repos under both spec sets with
   `firewall evaluate --symbolic-only --engine cypher-interp --scoring v1.3` at ONE tool commit (this branch's
   base `origin/v1.3`; the commit A was evaluated at is recorded and, if different, A is re-run here at this
   commit too so both sides share the tool commit). Per repo: blocking count, blocking per rule, pass/fail verdict.
4. **Count agreement.** Spearman ρ over the 15 repos (A vs B blocking count); Bland–Altman table (difference
   B − A per repo, mean difference, SD, 95 % limits of agreement).
5. **Verdict agreement.** Number of repos with the same pass/fail verdict, and Cohen's κ on the verdict.

## Pass criterion (pre-stated)

- Per repo: **reliable mapping** iff primary file-to-layer κ ≥ 0.80.
- Instrument-level: the mapping step is called **reliable** iff the pooled κ (all files of all 15 repos, primary
  labels) ≥ 0.80 **and** at least 12 of 15 repos are individually reliable. Otherwise it is reported as **not
  reliable at this threshold**, with the disagreement classes that drive it.
- Count and verdict agreement are reported descriptively; no threshold is set for them.
- The result is reported whatever it is.

## What this cannot show

- Both authors are Claude sessions (same vendor; V10). Agreement may be inflated by a shared prior, so this is an
  upper bound on cross-human agreement, not an estimate of it.
- 15 repos; κ per repo on small trees (19–25 files) is noisy.
- B's protocol fixes fitness functions to the preset; any difference A made in rule blocks is reported as a
  difference but is not part of the mapping κ.
- No construct switch is computed (rule 5); status-quo scoring only. Nothing touches the hold-out.
