> - It does not replace or re-test any Study 1 (v1.2E) number. The registered tables in `results/e1-grid/agg*/` and `results/so4-heldout/` stay frozen, and so does their write-up (`Docs/DiagnosticRuns/e1-size-analysis-2026-10-10.md`).

Branch `v1.3-rerun-study1`, cut from `origin/v1.3` @ `22b2741`. The measured code is that commit plus one new script: `scripts/v1.3/study1-rerun.ts`, a driver that calls the unchanged CLI. Outputs are in `results/v1.3-study1-rerun/{e1,so4}/`.

## Instrument and procedure

**Every evaluation** is the plain CLI: `bin/firewall.ts evaluate --symbolic-only --format json`. It uses the v1.3 defaults:
- scoring `v1.3`, with the verdict rule "any blocking violation";
- the v1.3 extractor options: `reExportEdges: 'both'` (barrels), `dynamicImports` and `moduleWiring`;
- `V13_COMPILE_OPTIONS`: edge views, style applicability (FF-P06 not applicable in `layered`) and role tokens;
- instrument v2, as in Study 1.

No judge was called. Study 1's E1 ran in full mode, so its `ahsCombined` includes the judge. The comparisons below therefore use Study 1's **symbolic** (deterministic) findings, plus its registered `ahsCombined` where it is quoted.

**E1** covers the 72 coordinates of `experiments/e1-grid/plan.json`.
- **Copies.** Each cell was copied, read-only from `../daedalus-e1-outcomes`, to a temp directory outside the repo, with symlinks kept (`node_modules` → the skeleton install).
- **Pinned tsconfig.** Each copy was extracted with the per-run tsconfig of `Docs/generator-protocol.md` §3 (ADR-032), with `<cwd>` set to the copy. This is the same text as `e1PinnedTsconfig` in the E1 harness.
- **Spec.** Each cell used its plan spec, `specs/clean-arch.yaml` for every cell, as in Study 1.
- **Cells.** All 72 have a `src/` and were evaluated. The aggregates use the **65 cells Study 1 accepted**: 47 Claude and 18 Codex. The 7 `GEN-TYPECHECK` cells (Haiku) are listed separately.
- **Sizes.** Files and LOC (`sourceFilePaths` / `treeLoc`, the registered definitions) equal Study 1's `so5_grid.csv` for all 72 cells.

**SO4** covers the 163 entries of `experiments/so4-heldout/plan.json`: 7 held-out bases and 156 seeded copies, the same list Study 1 ran.
- **Gate.** The registration machinery (`run-experiment` with its prereg gate) was **not** used and not bypassed. The CLI was run directly on each base and seeded copy, with the registered spec and each project's own tsconfig.
- **Read-only check.** After every run, the driver checked the tree (excluding `node_modules` and `.git`) for files modified during the run. There were none in 163/163. The CLI writes nothing into the project.
- **Scoring.** The reports were assembled into a scoring case with the Study 1 instrument-v2 case's `manifest.json` and `case-rows.json` (`results/so4-heldout/v2/case`). They were scored with the unchanged `scripts/score-golden-cli.ts`, under the registered matching rule.
- **Scorer check.** On the frozen v2 case, the same scorer reproduces `results/so4-heldout/v2/score.json` byte for byte.

**Neo4j.** The runs used the shared `daedalus-neo4j-bt` on bolt 7693. Credentials came from `~/.daedalus-bt.env` and were never printed. Every run held the cross-process lock in `~/.daedalus/locks`; the first cells waited on another agent's run.

**Normalised fields.** The reports are stored with their volatile fields fixed, so that two runs can be compared byte for byte:
- `runId` = the Study 1 run id;
- `durationMs`, the `timings` and `executionTimeMs` = 0;
- `projectPath` = the Study 1 relative path, which also replaces the temp copy's absolute path inside warning messages.

**Resources.**
- Cells ran one at a time, and no jest suite was run.
- The heavy-command hook blocked on swap while `memory_pressure` reported 34–35% free. `npm ci`, the four E1 passes, the two SO4 passes and the scorer were each run with `HEAVY_ADMISSION_BYPASS=1`, one at a time.

**Incident.** The session's shared scratchpad lost a sibling agent's `work/` directory during the first E1 pass (cell 33). The pass was restarted in a uniquely named directory. Then, after the path normalisation was added to the driver, both E1 passes were redone from scratch. The committed reports all come from that final pass.

### How the spec-level picture changes

- **No blocking finding in any cell.**
  - The count is 0 of 65 accepted cells, and 0 of all 72. Every cell passes the v1.3 verdict with blocking AHS 1.000.
  - So the v1.3 blocking view has **no spec-level and no model difference** at all. Blocking findings per file are 0 at every level.
  - The Study 1 "reverse" spec-level direction (Claude `none` 0.951 > `full-aac` 0.920 > `minimal-prose` 0.887 on `ahsCombined`) has nothing to act on in the blocking view.
- **The direction lives entirely in the advisory tier.**
  - Study 1's size analysis split the AHS gap by function. It came from FF-C02 module-fan-out and FF-P02 dependency-inversion, then FF-C06 and FF-C03 (`e1-size-analysis-2026-10-10.md` §5).
  - All four are **advisory** in v1.3 (`rule-tiers.md`: metric thresholds; P02 is "a ratio with a threshold, so a proxy").
  - The advisory findings themselves are unchanged (below). Their spec-level pattern is the one Study 1 described: C02 fires in 0/15 `none` cells and 15/16 `minimal-prose` cells. It is now reported outside the verdict.
- **The blocking rules never fired in Study 1 either.** Study 1 had zero dependency-direction, cycle, domain-purity, repository or domain-outward findings in every cell ("AVR structural is 0 in every cell"). The `v12e_share_cells_any_v13_blocking_rule` column is 0 everywhere. So v1.3 is not hiding a blocking signal that v1.2E saw. The generated projects simply never break the defining Clean-Architecture constraints that the blocking rules check.
- **The size explanation.** Study 1's reading was that a spec prompt makes larger projects with more modules and layers, which gives the coupling and DIP rules more sites, while findings *per file* do not differ by level. Under v1.3:
  - The size gradient is the same data: Claude files 9.1 / 27.4 / 29.6.
  - It produces no blocking difference, because no blocking rule fires at any size.
  - Symbolic findings per file are still flat across levels: Claude 1.165 / 1.155 / 1.152, against Study 1's 1.142 / 1.155 / 1.152. The `none` row differs only through the one barrel cell below.
  - So the size explanation still accounts for the advisory pattern, and the blocking view adds nothing that size would need to explain.
- **FF-CV05's share.**
  - FF-CV05 (test-file pairing) is still most of the symbolic output. There are 1 184 of 1 428 findings over the 65 cells (0.829), against 1 184 of 1 423 in Study 1 (0.832). On the Claude arm it is 1 003 of 1 213 (0.827), against 0.830.
  - It is advisory, so in v1.3 it no longer costs every cell 0.0125 of AHS. It is reported as a count. Its share moved only through the 5 net extra FF-C03 findings below.

## 3. Limits

- **Descriptive only.** There are no hypothesis tests, no CIs and no comparison with a registered threshold. The v1.3 instrument is still in development, and its validity figures come from the sealed hold-out set, not from this page.
- **E1 is not a validity test of v1.3.** It contains no planted violation. A uniform 0 blocking says that these 65 projects do not break the six blocking constraints as the v1.3 templates read them. It is not a recall figure.
- **SO4 is a development reading.** The SO4 bases and operators were known while v1.3 was built: MO-X01 motivated `dynamicImports`. So the 73/73 is not a held-out estimate for v1.3.
- **Scoring.** The SO4 scoring reuses the Study 1 manifest's expected keys, which were computed for the v1.2E instrument. A v1.3 finding is matched only if it hits those keys, so collateral and FP-strict use the v1.2E key semantics.
