# v1.3 convergent validity: our verdicts against three independent tools (2026-10-16)

Branch `v1.3-validity-convergent`, cut from `origin/v1.3` at `f57a4918`. This is an exploratory evidence unit, like the external-set and wild units: it adds no AI-DLC workflow and no pre-registration, and `aidlc-docs/` is untouched. No Cypher template was edited (`git diff origin/v1.3 -- src/` is empty). No LLM was called.

**Question.** On every rule that an established, independent tool can also express, does our tool give the same verdicts?

Study 1 compared the v1.2E instrument with dependency-cruiser (ADR-030, `tool-comparison-real-pairs-2026-10-10.md`). This run extends that comparison in three ways:

- it adds **eslint-plugin-boundaries** and **ArchUnitTS** (npm `archunit`);
- it reruns **dependency-cruiser** at the **v1.3 rule set**: the v1.3 compile, edge views, and the hexagonal and DDD libraries;
- it covers **three corpora**: the 71 reference variants, the 15 external human-written projects (PR #133) and the 14 wild projects (PR #114).

## 2. Translation

### 2.1 How the rules were translated

`scripts/v1.3/lib/convergent.ts` builds a tool-neutral IR from the queries our v1.3 compiler emits (`compileFunctions(…, V13_COMPILE_OPTIONS)`). It reads each query's template name and **bound parameters**:

- `layerOrder`, `allowedTransitions`, `allowedDependencies`, `domainLayer`, `forbiddenImports`;
- the DDD contexts, public APIs, ACLs, aggregates and repositories;
- `excludePatterns`.

So each tool gets the rule as our Cypher reads it, not as a reader re-derives it. Layer membership is emitted in our annotator's precedence: the first layer by `directories`, else the first layer by `file_patterns`. Each tool receives the same globs.

**Expressibility policy.** A rule counts as expressible only through a tool's declarative rule vocabulary. Escape hatches that run arbitrary code are not counted: ArchUnitTS `adhereTo` and custom metrics, a hand-written ESLint rule, and dependency-cruiser's API. With them, any rule is "expressible" by re-implementing it, and agreement would then be agreement with ourselves.

**Per-tool notes**, each a translation decision recorded before scoring:

- **dependency-cruiser.**
  - It uses the T1 path selectors of ADR-030 (`globRegex`), with re-exports and type-only imports counted (`tsPreCompilationDeps`).
  - A negated extglob segment (`dir/**/!(*.module).ts`, used by 3 external specs) is translated as a negative lookahead. dependency-cruiser refuses picomatch's own regex as unsafe. The new form is checked against picomatch in the unit tests.
  - Cycles are keyed as the edges of each reported cycle path.
  - Fan-in is a module rule, `numberOfDependentsMoreThan`.
- **eslint-plugin-boundaries.**
  - **One ESLint run per rule.** An import gets a single report, from the last policy that matches it. FF-S01 and FF-S04 on the same domain-to-application import could therefore not share a run (found in the smoke test).
  - **`mode: "full"` element descriptors.** This mode is deprecated in v7 but supported. `partialMatch: false` never matches a single file such as `src/main.ts` (found in the smoke test).
  - **`checkAllOrigins: true`.** Without it, external modules are never checked.
  - Targets come from the policy message (`{{to.file.path}}`, `{{to.module.source}}`).
- **ArchUnitTS.**
  - Each forbidden pair is one `projectFiles(tsconfig).inPath(re).shouldNot().dependOnFiles().inPath(re)` check. The regexes are picomatch's, with negative lookaheads for the earlier layers and for the extractor excludes.
  - Cycles use `haveNoCycles()`; DS01 uses `should().beInPath()`.
  - One child process runs per project, bounded at 600 s. On timeout, the run is repeated without the cycle check.

## 3. Method

**Keys.** Every finding becomes a key `(rule, file, target)`:

- an edge rule: target = imported file;
- a package rule: target = base package name (`@nestjs/common/x` → `@nestjs/common`);
- a cycle rule: one key per edge of each reported cycle;
- a file rule (FF-C04, FF-C05, FF-DS01): target empty.

**Scope.** The scope is the tsconfig program's files minus the extractor excludes (`DEFAULT_EXCLUDE_PATTERNS` and the spec's `default_exclude_paths`).

- That is the same file set our extractor reads: our File-node count equals it on 98/100 projects; the 2 exceptions are §1.3.
- A key whose file is out of scope, or whose file target is out of scope, is dropped for every tool alike.

**Item universe for κ.** For each project and rule, the universe holds every item the two raters could have flagged:

- edge rules: every file-to-file dependency of dependency-cruiser's module graph within scope;
- package rules: every (file, package) dependency;
- file rules: every program file;
- plus any flagged key.

The 2×2 tables are pooled over the projects of a corpus. Most items are negatives, so the observed agreement is near 1 by construction. The report therefore gives **Cohen's κ** and **positive agreement** (2·both / (2·both + only_a + only_b)).

**Not computed.** A rule that an engine failed to compute on a project is left out of that engine's pairs on that project; it is never counted as a disagreement. Examples: a query that timed out, or a check that threw.

**Disagreement classes.** Every key in the symmetric difference between our tool and a tool is classified by rules in `convergent-score.ts` (`classify`). The rules were written **after reading the rows (POST-HOC)**, and each states its mechanical test:

- **translation gap**: the two rule definitions differ by construction.
  - Orphans where the file imports packages only, or only files outside scope.
  - dependency-cruiser cycles longer than our bound of 10.
- **barrel or alias resolution**: the external tool's graph lacks the edge.
  - ArchUnitTS and `export … from`: a cycle whose every occurrence needs a re-export edge, tested by Tarjan's algorithm on the literal graph without re-export edges.
  - An import the external resolver left unresolved.
- **their bug**: eslint-plugin-boundaries on files matched by a negated-extglob layer glob (§4).
- **view choice**: a resolved-view rule (FF-P01/DT04, DT01, DT02) where our key runs through a barrel and the tool's ends at the barrel.
- **our bug**: none was found among the disagreements.
- **unclassified**: anything left over, to be read by hand. Nothing was left over.

**Manifests.** On the reference set, every engine is scored against both manifests, on the same keys and on the rules that engine can express. FF-S02 is cycle-normalised as in `ue-score.ts`.

- The **author** manifest is the `expectedFindings` of each variant.
- The **blind** manifest is rebuilt from the committed adjudication sheet of the last scored run (`results/v1.3-reference/after-member-facts/adjudication.csv`).
  - That sheet lists every scored key on which our tool, the author manifest and the blind manifest do not all agree. So blind = (rows with blind = finding) ∪ (author keys with no row).
  - The sealed blind files are not in this repository and were not read.
  - The rebuild was checked: our tool's blind-expanded and author counts recomputed from it equal the committed `scores.json` on **48/48** (style, rule) cells.

## 8. Limits

- **Agreement is not correctness.** Four tools agreeing on an import edge says the edge exists and the rule was translated faithfully. It does not say the finding is an architectural defect; labels are still needed (`Docs/v1.3/human-labelling-protocol.md`).
- **The translation was written by the author of the tool under test** (TV-104). Mitigations:
  - it reads our compiler's bound parameters rather than a re-derivation;
  - each tool's emitter is unit-tested;
  - each smoke-test fix is recorded in §2.1.

  An independent translator could still choose differently, for example a coarser boundaries element for a whole layer.
- **The disagreement classes are post hoc.** Each class is a mechanical test written after reading the rows it covers. All 253 rows fall in a class, so none was decided by hand, but the tests were designed to explain what was seen.
- **Most items are negatives**, so observed agreement is near 1 by construction. Read κ and positive agreement, and the "only" columns.
- **The wild specs are ISE specs.** A wrong layer mapping is the same wrong mapping for every tool; this run measures agreement under the mapping, not the mapping's quality.
- **The reference set is development data**, and blind is rebuilt from the adjudication sheet (§3, verified 48/48).
