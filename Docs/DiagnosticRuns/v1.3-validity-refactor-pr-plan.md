# v1.3 validity from declared architecture refactors: plan and decision rule (fixed before any data)

Branch `v1.3-validity-refactor-pr`, cut from `origin/v1.3` at `e9fd61b7`. Written, committed and pushed on 2026-10-16
**before** any commit message of a pool repository was searched and before any tool run on a pool repository. The
report will be `Docs/DiagnosticRuns/v1.3-validity-refactor-pr-2026-10-16.md`; anything it does that this plan does not
fix is labelled post hoc there.

Status: exploratory evidence unit, no human raters, **no LLM labelling** (every classification below is a fixed regular
expression or a git/tool count). No Cypher template, tier or `src/` file is changed.

## 1. Why a different design

- PR #168 (`v1.3-validity-fixes-mined`) asked whether maintainers delete the exact edges the tool flags. One commit
  (amplication "Lint Imports") carried the pooled ratio; without it there was no signal, and only FF-S02 cycles beat the
  unflagged-edge baseline.
- PR #198 (known groups) was also null.

Both designs wait for developers to remove *a finding*. This one starts from the other end: changes whose own authors
**say** they are architecture or layering refactors. If the tool measures architecture, its blocking count should fall
more across those changes than across ordinary changes of the same size in the same repository. The unit is a
**declared refactor commit**, not a finding, so a single sweeping commit can contribute one data point, not 48.

## 2. Deviation from the task wording, recorded before the search

The task asks for the GitHub PR search API (`gh`, `is:pr is:merged language:TypeScript`). From this session:

- `gh auth status`: the token in `GH_TOKEN` is invalid;
- unauthenticated `GET https://api.github.com/search/issues?...` returns **403** through the session proxy;
- the GitHub MCP tools are scoped to `cdcordobaa/daedalusarch`; the session rules forbid using them to search other
  repositories.

`git clone` of public repositories works. So the ground truth is taken from **git history**, which carries the same
text for merged PRs:

- a GitHub merge commit (`Merge pull request #N from …`) has the PR title as its body;
- a squash merge has the PR title with `(#N)` as its subject and, by GitHub's default, the PR body or the squashed
  commit list as its body.

Linked issues cannot be read offline and are not used. Commits pushed directly (no PR number) are kept and reported as
a separate subgroup, as the task allows "merged PRs or commits".

## 4. Ground truth: declared architecture refactors

**Universe per repository.** `git rev-list --first-parent <pin> -- <historyPath>`: first-parent commits that change
the analysis root, each with a parent. Removed: bot authors (`isBotAuthor` of PR #168), and subjects starting with
`Revert` / `revert`.

**Text searched.** Subject and body. Removed before matching: the `Merge pull request #N from <owner>/<branch>` line
(branch names are not statements), and trailer lines (`Co-authored-by:`, `Signed-off-by:`, `Reviewed-by:`,
`Change-Id:`).

**Refactor statement** (case-insensitive). A commit is a *declared architecture refactor* if its text matches at
least one family below. Families A–D are intrinsically refactor statements; E–G need a refactor verb `V` in the same
message.

| family | pattern (regex sketch, `\W+` between words, up to 3 filler words where `…`) |
|---|---|
| A cycles | `(remove|fix|break|resolve|eliminat|avoid|get rid of|untangl|prevent|solv)\w* … (circular|cyclic) (dep|depend\w*|import\w*|reference\w*)` or the same with `(dependency|import) cycle\w*`; also `circular dep\w* (fix|removal)` |
| B decoupling | `decoupl\w*`, `untangl\w*`, `disentangl\w*` |
| C logic placement | `(move|moved|moving|extract\w*|pull\w*|lift\w*) … (logic|code|queries|query|calls?|db access|database access|persistence) … (out of|from) … (the )?(controller|route|router|resolver|handler|model|entit|view|component)\w*`, or `(thin|thinner|slim)\w* (controller|route|resolver|handler)s?` |
| D boundaries / layering | `(layer|module|package|domain|context|architectur\w*) boundar(y|ies)`, `layer(ing)? violation\w*`, `dependency (rule|direction|inversion)`, `inversion of control`, `separation of concerns`, `(hexagonal|onion|clean) architecture`, `ports? (and|&) adapters?` |
| E layers | `(service|domain|application|infrastructure|persistence|data[- ]access|repository|presentation|business) layer\w*` + `V` |
| F patterns | `(repository|adapter|port) pattern`, `(introduce|add|extract)\w* (a |an )?(repository|repositories|port|ports|adapter|adapters|use[- ]?case\w*|service layer)` + `V` |
| G architecture | `architect\w*`, `restructur\w*`, `reorganiz\w*`, `re-organi[sz]\w*` + `V` |

`V` = `refactor\w*|restructur\w*|reorgani[sz]\w*|move[ds]?|moving|extract\w*|split\w*|separat\w*|isolat\w*|decoupl\w*|clean\w*[- ]?up|remov\w*|enforc\w*|introduc\w*`
(E–G additionally reject a message whose only `V` is inside the matched phrase itself, so "restructure" alone does not
satisfy G twice).

The exact regular expressions are implemented in `scripts/v1.3/lib/refactor-pr.ts` with unit tests whose examples are
**invented strings**, not pool commits. The implementation may fix a regex that does not do what the table says (to be
stated in the report); it may not add or drop words after the search has run.

**Cap.** At most 10 declared refactors per repository: if more qualify, the 10 evenly spaced in first-parent order
(index `round(i*(N-1)/9)`). This bounds one repository's weight and the runtime.

**Controls.** For each repository, the control pool is the universe minus every commit whose text matches any family
A–G **or** the loose word list `refactor*|restructur*|reorgani*|architect*|layer*|decoupl*|circular|cycl*|boundar*|
dependenc*|port(s)|adapter*|domain*|module*` (so controls are ordinary feature, fix and chore changes, not undeclared
refactors). For each refactor R, in first-parent order, pick up to **K = 3** controls by nearest size:

- size of a commit = (files changed under the analysis root, lines added + deleted under the root), from
  `git diff --numstat P C -- <root>` (binary files count as a file with 0 lines);
- distance = `|ln(1+f_R) − ln(1+f_C)| + |ln(1+l_R) − ln(1+l_C)|`; caliper **1.5**; ties broken by smaller distance in
  commit date;
- a control is used once per repository (greedy, refactors in chronological order).

A refactor with no control inside the caliper is **unmatched**: excluded from the primary analysis, listed in the
report.

## 5. Measurement

**Tool run.** Each commit C and its first parent P is checked out (sparse, the analysis root) and evaluated with
the in-process pipeline that `firewall evaluate --symbolic-only --engine cypher-interp` runs: `evaluationMode:
symbolic-only`, `graphEngine: cypher-interp`, `scoringMode: v1.3` (tiers of `Docs/v1.3/rule-tiers.md`), instrument v2,
the frozen spec, the harness tsconfig flattened from the project's own chain (`src/` production code, tests excluded),
no dependencies installed. As in PR #168, the two variable-length cycle query texts are answered by
`FastCycleRepository` (`scripts/v1.3/lib/fast-cycles.ts`), whose parity with the interpreter is checked live on every
snapshot of at most 100 files; every other query goes to the interpreter. **CLI cross-check:** the first 10 refactor
parent snapshots (pool order) with at most 300 files are also run through `firewall evaluate --engine cypher-interp
--symbolic-only --format json`; their blocking counts must equal the in-process counts (a mismatch is reported and
the cause investigated before any statistic is read).

**Snapshot validity.** A snapshot fails if the root is absent, the program has no source file, or the pipeline
errors. A commit is **valid** if both P and C succeed and at least 20% of P's program files fall in a declared layer
(the frozen spec describes the code at that point). A refactor needs to be valid and keep at least one valid control.

**Outcome.** `B(x)` = number of distinct blocking-tier symbolic findings (identity = PR #168 `violationKey`) at
snapshot x. `Δ = B(C) − B(P)`. FF-S02 truncation: if P or C has 100 FF-S02 rows (the template cap), FF-S02 is dropped
from both counts of that commit.

**Matched difference.** For refactor i with controls j = 1..k_i: `d_i = Δ_R,i − mean_j Δ_C,ij`. Negative = the
refactor lowered the blocking count more than ordinary changes of the same size.

## 6. Statistics

- **Effect size:** mean and median of `d_i`, each with a 95% **repository-cluster bootstrap** CI (10,000 resamples of
  repositories, seed 20261016). Also the share of refactors with `d_i < 0` among non-zero `d_i` (Wilson 95%).
- **Sign test:** exact two-sided binomial test on the signs of `d_i` (zeros dropped).
- **Leave-one-repository-out (LORO):** mean d, median d, the sign split and the sign-test p with each repository
  removed in turn; the report gives the range and every repository whose removal flips a conclusion.
- **One-commit guard:** the sign test and the bootstrap CI of the mean recomputed without the refactor of largest
  `|d_i|`.
- **Descriptive only (no decision):** per family (A cycles vs. B–G), PR vs. direct-commit subgroups, Δ without FF-S02,
  Δ per blocking rule, Δ per 100 files at P, advisory Δ, the raw Δ_R and Δ_C distributions, and refactors with Δ_R ≠ 0
  listed with their subject lines.

## 7. Decision rule (fixed)

Let n = number of matched, valid refactors.

- **SUPPORTED** iff all of:
  1. n ≥ 30;
  2. sign test p < 0.05 with more negative than positive `d_i`;
  3. the cluster-bootstrap 95% CI of mean d lies entirely below 0;
  4. every LORO keeps mean d < 0 and more negative than positive `d_i`;
  5. condition 2 and 3 still hold under the one-commit guard.
- **NOT ROBUST** if 2 and 3 hold but 4 or 5 fails (reported as not supported).
- **CONTRADICTED** if the sign test has p < 0.05 with more *positive* `d_i` and the CI of mean d lies entirely above 0.
- **NULL** otherwise (including the case where most `d_i` are 0: the tool does not register the declared refactors).
- If n < 30 after Stage 2, the verdict is reported with the label **UNDERPOWERED**, and can be at most NOT ROBUST.

The FF-S02 subgroup, which PR #168 singled out, is reported but cannot by itself make the verdict SUPPORTED.

## 8. Threats recorded in advance

- **Commit text is not intent.** A message can claim "decouple" for a cosmetic change, and real refactors are often
  undeclared (they then sit outside both groups, since the control filter drops loose architecture words).
- **One frozen spec for the whole history.** Early commits may predate the folder layout the spec maps; the 20%
  layered-files rule removes the worst cases but not all.
- **Shared repositories with PR #168.** The 36 histories are the same; PR #168 sampled 200 commits per repository at
  random positions, so some refactor or control commits may also appear there. This study does not read PR #168's
  per-pair data.
- **Size matching is on diff size only**, not on what the diff touches.
- **Third-party code is never committed**; clones and the snapshot cache live in a scratch directory.
