Branch `v1.3-wild`, base `origin/v1.3` at `96a5e77d`. Node v22.22.0, TypeScript from this repository's lockfile, dependency-cruiser 18.4.0 (`experiments/tool-comparison/depcruise`, `npm ci`). Run on 2026-10-15/16.

**Status: exploratory evidence unit.** No pre-registration, no labels. Every count below is a count of **unlabelled candidates**, not of true findings: nothing here estimates precision or recall. The review sheet (`results/v1.3-wild/review-sheet.md`) is the input for a later human judgement; until it is judged, a count only says how much a detector fires on real code, where it fires, and whether an import graph could have shown the same thing.

Scripts: `scripts/v1.3/wild-run.ts` (prepare, analyse, fidelity), `scripts/v1.3/wild-sheet.ts` (summary and review sheet), pure helpers in `scripts/v1.3/lib/wild.ts` (unit tests: `tests/unit/scripts/v1.3/wild.test.ts`, 25 tests). Outputs: `results/v1.3-wild/`.

## 1. Selection

5. one analysis root per repository.

## 2. Method

**No dependencies installed.** Each repository is cloned at its SHA into a temporary directory (sparse checkout of the analysis root and the root tsconfig files; never committed). The extractors, the TypeScript compiler and dependency-cruiser resolve every internal edge without `node_modules`. Package imports stay unresolved, and package types are `any` to the type checker. This limit matters for the type-reading proxies (§5, §8).

**Harness tsconfig.** `flattenTsconfig` writes one self-contained `tsconfig.wild.json` per root, in the clone:

- it merges the repository's own `extends` chain (relative files, plus a workspace package found in the checkout);
- it keeps only the resolution and language options;
- it drops build, emit and `types` options;
- it includes `src/**/*.ts(x)` (etherpad: `src/node/**/*.ts`);
- it excludes tests (`*.spec.ts`, `*.test.ts`, `__tests__`, `test/`, `tests/`).

The same file feeds all four instruments. One `extends` could not be followed: hedgedoc's `@tsconfig/node24` (target and lib only; no effect on resolution).

**Pipeline per repository.** This is the tool as a newcomer would use it: there is no hand-written spec.

1. **ISE** (`inferSpec`) runs on a snapshot that holds `src/` and the harness tsconfig only (the `src/ise/snapshot.ts` anti-leakage rule). Its output is the style, the confidence and an emitted spec, which is validated.
2. The **emitted spec's layer model** drives the APG v2 extraction (`V13_APG2_OPTIONS`) with these components:
   - the spec's layers and DDD contexts (`componentsFromLayerModel`);
   - one folder component per top-level folder under `src/` (`folderComponents`).

   The nine APG v2 templates then run as their in-memory mirrors (`APG2_IN_MEMORY`, `apg2Params` of the same layer model).
3. The **cheap proxies** (`enrichCheap`, default thresholds) run on the same APG and layer model.
4. **Graph fidelity**: `scripts/v1.3/graph-fidelity.ts project --views` runs unchanged against the TypeScript compiler and dependency-cruiser. It measures three graphs:
   - v1.2E default;
   - v1.3 literal view (no `viaReExport` edges);
   - v1.3 resolved view (no `reExportHop` edges).

**One process per repository and stage**, run in sequence, so the peak RSS is that stage's alone.

**"Import graph sees it".** For each candidate the run records whether a file-level import graph shows the same relation:

- a type-flow row: an import edge between the member's file and the type's file;
- an async row: an import edge between the publisher's file and the subscriber's file;
- an I/O row: the file imports the package named in the API, where a global (`Date.now()`, `process.env`) counts as never;
- a cross-component clone or shared literal: an import edge between the two ends.

It is the `_importGraphSees` field in `apg2.json` and `cheap.json`.

## 7. Notable detections an import graph cannot show

These are concrete candidates, read at the pinned SHA. They are not judged: each says what the tool claims and why no import edge carries it.

1. **Inferred return type crossing a boundary with no import** (immich-server, `src/services/map.service.ts:21`). `MapService.reverseGeocode(dto)` has no return annotation; it returns `this.mapRepository.reverseGeocode(...)` wrapped in an array. The compiler infers `ReverseGeocodeResult[]`, an interface declared in `src/repositories/map.repository.ts`, so the repository's result type becomes part of the service's public surface. `map.service.ts` never imports `map.repository.ts` (the repository arrives through `BaseService`), so no import edge exists.

   77 of immich's 191 type-flow rows are of this kind (`_importGraphSees: false`), and 3 of medplum's 8. In medplum, `ServerConfig` in `config/utils.ts` is an alias that resolves to `MedplumServerConfig` in `config/types.ts`, so `initApp`, `initAppServices` and `asyncBatchHandler` carry a type from a file they never import.
2. **Run-time coupling through a command bus** (domain-driven-hexagon, `src/modules/user/commands/create-user/create-user.{http,cli,message}.controller.ts`). Three controllers publish `CreateUserCommand` on `@nestjs/cqrs`'s `CommandBus`, and `CreateUserService` handles it. None of the controllers imports the service, so an import graph shows three controllers and a service with no relation. The APG v2 links them through the channel.

   Whether this is "undeclared" depends on the spec. ISE's nestjs spec has no `allowedDependencies`, so no async pair is allowed and all three are reported. Under the project's own hexagonal reading this edge is the intended one. The catch is real; the verdict is spec-dependent.
3. **Nondeterminism in the domain base classes** (domain-driven-hexagon, `src/libs/ddd/entity.base.ts:33`, `command.base.ts:50`, `domain-event.base.ts:50`). The `Entity`, `Command` and `DomainEvent` base classes call `new Date()` and `Date.now()` directly, and `command.base.ts:46` calls `randomUUID()`. `Date` is a global: no import graph can see a clock read. Across the 14 repositories, 206 of 258 `nondeterminism-in-core` rows are invisible to an import graph (mostly globals such as `Date`, `process.env` and `Math.random`).
4. **Duplicated query logic across feature modules with no import between them** (hedgedoc-backend). `NoteService.getUserNoteIds` (`src/notes/note.service.ts:73`) and `MediaService.getMediaUploadUuidsByUserId`, `…ByNoteId` and `getLinkedNoteIds` (`src/media/media.service.ts:240, 255, 384`) have the same body: a Knex select of one column filtered by one key, then a map. The clone proxy pairs them across the `notes` and `media` components; neither file imports the other.

   Of the 11,721 cross-component clone and shared-literal flags, 11,079 (95%) join files with no import edge between them. The hoppscotch clone explosion (§5) makes up most of that number, so this is a measure of reach, not of value.
5. **A config-folder composition root in a dependency cycle** (ts-express-starter-prisma, `src/config/container.ts:5–16`). The container imports controllers, services, repositories and routes, and those import `config/env`. The folder graph therefore has cycles through `config`: 5 of the repository's 19 ADP rows start at `config`, and 4 more end there; all 6 SDP rows touch `config` (four `config → folder` edges, `utils → config`, and the layer edge `config → application`).

   An import graph does show the edges. What it does not show is the component-level cycle and the Martin metrics. It also shows that the composition-root exemption (by layer or by file name) does not cover a DI container in a folder named `config/`. This is a scope gap worth an ADR note, not a detection.

The cheap proxies are the most expensive stage on medplum (15.4 s; shared-literals takes 9.0 s and clones 3.1 s). Peak memory stayed under 0.85 GB.

## 9. Failures and limits

- **No repository failed.** All 14 extracted, all ISE specs validated, and all fidelity runs exited 0.
- **Not analysed by design:**
  - test files (excluded by the harness);
  - code outside the analysis root: podkrepi's `libs/`, medplum's sibling packages, etherpad's `src/static` (browser code);
  - one unfollowed `extends` (hedgedoc, `@tsconfig/node24`).
- **No dependencies installed.** Package types are `any`. This plausibly explains the zero counts of framework-in-core and repo-bypass, and it limits type flow to project-declared types. A boundary-type-leak through an ORM entity type from a package is invisible here.
- **APG v2 needs a spec.** Every template count depends on the ISE-inferred layer model and on the folder components:
  - a wrong style (domain-driven-hexagon and bitloops as `nestjs`) gives wrong layers;
  - wrong layers make wrong io, nondeterminism and type-flow candidates.

  The counts are those of a newcomer who accepts the inferred spec. They are not the counts the templates would give under a reviewed spec.
- **Async coverage is thin.** Computed event names are skipped (106 sites across immich, medplum and hedgedoc).
- **Selection bias.** The pool was named by hand, not sampled (the search API was unreachable). The 14 repositories lean towards popular references and well-kept products.
- **No precision.** The review sheet has 68 candidates: up to 5 per template or proxy, seeded (20261016), spread over repositories first. Four templates and proxies are absent because they had no rows: deep-import-declared-api, repo-bypass, framework-in-core and vocabulary. undeclared-async-coupling had only 3. Detector ids are hidden in `review-sheet.md` and kept in `review-key.json`.
