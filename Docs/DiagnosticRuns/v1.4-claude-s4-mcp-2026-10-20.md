# Claude S4 confinement probe with the Daedalus MCP server: run of 2026-10-20

**Verdict: FAIL (ADR-029). The `daedalus-mcp` arm is not cleared for Claude, and `mcp@L2` must not run as
templated.** The cause is not a confinement leak. The MCP server never loads: `--safe-mode`, which
`buildGeneratorArgs` always emits, disables the `--mcp-config` server on Claude CLI 2.1.304. A loop `daedalus-mcp`
turn with this argv is a `none` turn plus the tool sentence.

## Diagnostic call (10th call, not a probe result)

The argument set of probe (c), byte for byte, without `--safe-mode`, was run in the same cell with the same MCP
config. The server loaded. `check_file` returned `blockingVerdict: "pass"`, and the call log has one `check_file` line
with no error (`results/v1.4-claude-s4-mcp/diagnostic-no-safe-mode/`). `claude --help` for 2.1.304 lists "MCP servers"
among what `--safe-mode` disables. So the absence is caused by `--safe-mode`, and the server build, `--confine`,
`--strict-mcp-config` and the tool allow rules are not involved.

## Consequence and what is needed (coordinator / author)

1. **Do not run `mcp@L2` with the current argv.** Every `daedalus-mcp` turn would have no tools, and the cell would
   measure the tool sentence, not the tool. The filled plan `plan-mcp-L2.json` was **not** written (step 4 of the
   brief applies only on a pass).
2. **A protocol decision is needed**, because the fix changes the generator argv of the MCP arm. Option A: drop
   `--safe-mode` for `daedalus-mcp` only. `--restricted` already ignores user, project and local settings, and
   `--strict-mcp-config` already excludes other servers. But `--safe-mode` also turns off CLAUDE.md, skills, plugins
   and hooks, and the arms would then differ in more than the tool. Option B: drop it for both arms, so `none` and
   `daedalus-mcp` keep one environment. Stage A ran `none` with `--safe-mode`, so this breaks comparability with
   Stage A. Option C: keep `--safe-mode` and find a CLI-supported way to add one server under it (none is documented
   for 2.1.304).
3. **Then S4 is re-run in full** (9 calls, new count, new approval), with these criteria unchanged. Probe (e) then
   matters more, because without `--safe-mode` the CLAUDE.md and skill paths are open again.

## Run 2 (2026-10-20, after the argv change): PASS

**Verdict: PASS (ADR-029). All 9 MCP-arm probes and the 5 no-MCP probes pass. The `daedalus-mcp` arm is cleared for
Claude, and the filled `mcp@L2` plan is written.** The pass criteria above are unchanged.

**What changed (DELEG3, option D, delegated to the coordinator; `ops/decisions.md`).** Both arms drop `--safe-mode`
and use one explicit flag set (`GENERATOR_CUSTOMIZATIONS_OFF`, `scripts/lib/generators/argv.ts`), in the same argv
position:

```text
--setting-sources ""                                              no user, project or local settings: no CLAUDE.md,
                                                                  CLAUDE.local.md or .claude/rules from them, none of
                                                                  their hooks, enabled plugins, agents, output styles
--settings {"autoMemoryEnabled":false,"disableAllHooks":true}     auto-memory off; no settings or plugin hook
--disable-slash-commands                                          no skill, no slash command
```

MCP still comes only through `--strict-mcp-config`: no server in `none`, exactly `daedalus-arch` (with `--confine`)
in `daedalus-mcp`. Read from `claude --help` and the 2.1.304 binary: `--safe-mode` disables the features `claudeMd`,
`skills`, `plugins`, `agents`, `outputStyles`, `workflows`, `lspServers`, `themes`, `keybindings` and the MCP
families, sets `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`, turns auto-memory and org memory off, keeps only managed hooks,
and drops the built-in `statusline-setup` agent.

**Not reproducible by a flag** (stated, not guessed): the built-in `statusline-setup` agent stays listed (inert: the
Agent tool is not in `--tools`); the managed CLAUDE.md and org memory, which `--safe-mode` skips through
`CLAUDE_CODE_DISABLE_CLAUDE_MDS` and its own switch, have no flag (no managed settings dir exists on the study
machine, and the context size below is unchanged). Themes, keybindings and the status line only matter
interactively.
