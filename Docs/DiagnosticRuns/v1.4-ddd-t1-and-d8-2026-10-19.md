## 3. Method

### 3.1 The Neo4j instance

- **Version.** The repository pins `neo4j:5.26-community@sha256:f663…6435` (`docker-compose.yml`, `.github/workflows/ci.yml`). `Docs/environment.md` records the kernel and APOC as 5.26.24.
- **How it ran.** The docker client is installed, but no docker daemon runs in this sandbox (`/var/run/docker.sock` is missing). So, as in the loop pilot, the official tarball `neo4j-community-5.26.24-unix.tar.gz` was used (sha256 `9e17d344…657c85`) with its bundled `labs/apoc-5.26.24-core.jar` copied to `plugins/` (sha256 `b77fb62b…ec74de`), on OpenJDK 21.
- **Capped settings.** These match the loop pilot's provenance (`Docs/v1.3/floor-escape-design-2026-10-16.md`): heap 512m (initial and max), page cache 256m, listening on 127.0.0.1 only, `apoc.*` unrestricted. One instance. The password was generated into a 0600 scratch env file; it was never printed or committed.
- **Check.** `CALL dbms.components()` gives `Neo4j Kernel 5.26.24 community`, and `RETURN apoc.version()` gives `5.26.24`.

Provenance: `results/v1.4-ddd-t1-d8/run-provenance.json`.

### 3.2 T1

`scripts/v1.4/ddd-b2-t1-rescore.ts --engine neo4j --dest results/v1.4-ddd-t1-d8` was run unchanged. It is the same CLI call as TIER-A3 (`evaluate --symbolic-only --scoring v1.3 --format json`), the same materialisation and the same identity rules, and it holds the cross-process Neo4j lock for the whole run. The 26 new blocking findings went through `scripts/v1.3/check-correct.ts --tiers blocking`.

### 3.3 D8

`scripts/v1.4/ddd-t1-d8-parity.ts` (new, reads stored reports only) does two comparisons.

- **T1 rows.** Each Neo4j row of `rows.json` is compared with the interpreter row for the same subject, run, variant, post-seal setting and step. The fields compared are scored, verdict, blocking AHS, Y, blocking rules run, blocking count per rule and blocking findings. Each `drift.json` row is compared on Y₁, memo D, edge-grain D and the per-step figures.
- **Per snapshot.** For each of the 124 CLI report pairs, the whole result is compared field by field, by the areas of `scripts/v1.3/cypher-interp-compare-runs.ts`: AHS, verdicts, dimension scores, metrics, tiers, function execution and results, disabled functions, graph statistics, violations and warnings. The run-volatile fields are already stripped, and the scratch tree is shown as `<project>`.
- **Per rule.** Every rule with a violation in any tier is compared on three things: the violation count, the identity multiset (rule, file, target, discriminator) and the file set (file, target and any `.ts` evidence; a cycle is compared by its files). A rule that ran with no violations on either side is covered by the `functionResults` area.

`cypher-interp-compare-runs.ts` itself was not run as-is. Its byte rows read a reference set's `raw/`, `report.json` and `report.md`, which this layout does not have. The new script keeps its CLI-area comparison and adds the per-rule rows. A direct `diff -rq` of the two `cli/` trees is the byte-level check.

## 5. What this closes and what it does not

**Closes:**

- **REV-04 P15, the T1 part, on the engine of record.** The 8 kept DDD snapshots score on Neo4j 5.26.24 under all four variants and both post-seal settings, with 0 errors. Y, D, the new findings and their `check-correct` verdicts equal the interpreter's. TIER-A3's B2 table (§3.2–§3.4) therefore holds on Neo4j unchanged.
- **D8 on agent-code snapshots.** The interpreter and Neo4j agree on 124/124 reports, byte for byte: per snapshot, per rule, at identity and file-set grain, across DDD, Layered, Clean and Hexagonal. This extends the reference-set parity (`Docs/DiagnosticRuns/v1.3-default-view-coverage-2026-10-16.md` item 7; `Docs/DiagnosticRuns/v1.3-post-merge-verification-2026-10-16.md`) to the kept agent trees and to the declared-aggregate DDD specs.
- **REV-04 P19, the Neo4j side.** V9's full-evaluation side came from the interpreter reports. Those are now shown identical to Neo4j, so the TIER-A3 V9 agreement (138/138) holds against Neo4j's full evaluation too. The MCP tools were not re-run against Neo4j: their answers do not depend on the full-evaluation engine.

**Does not close:**

- **D15**, and the signature on the aggregate declaration. Both are the author's.
- **The DDD pilot bar.** It is still not met on this evidence (TIER-A3 §3.4). Neo4j changes no number.
- **Neo4j-specific paths the CLI does not take here**: the #188 accelerator on/off split, larger graphs, and other Neo4j versions (see `Docs/DiagnosticRuns/v1.3-neo4j-version-2026-10-16.md` for 2025.12.1).

## 6. Limitations

- **The sample is TIER-A3's.** 38 snapshots, 1 DDD task, k = 4, one generator for DDD and Clean/Hex, and probe 1's by-hand Layered trees. Parity is shown on these graphs (≤ a few hundred nodes), not in general.
- **The tactical DDD rules agree only vacuously.** FF-DT01–FF-DT04 produce no violation on either engine, so their parity on real violations is untested by this set.
- **Tarball, not the pinned image.** The docker image digest could not be run. The tarball is the same kernel and APOC version (5.26.24) that `Docs/environment.md` records, and the same route the loop pilot used. Image-level differences (the entrypoint, the plugin download) are out of scope.
- **Capped memory.** Heap 512m and page cache 256m match the pilot's provenance, not `docker-compose.yml`'s 1G / 512m. On graphs this small, that cannot change a query result, only the timing.
- **The interpreter side was not re-run.** It is the committed TIER-A3 output, on the same `main` the Neo4j run used (`84199f25`).

## 7. Reproduce

From the repository root, with a scratch dir `$W`, the skeleton `node_modules` at `$NM` (TIER-A3 §7), and Neo4j 5.26.24 with APOC listening on bolt `127.0.0.1:7687`, with `NEO4J_URI`, `NEO4J_USER` and `NEO4J_PASSWORD` exported:

```bash
npx tsx scripts/v1.4/ddd-b2-t1-rescore.ts --engine neo4j --work "$W" --node-modules "$NM" --dest results/v1.4-ddd-t1-d8
npx tsx scripts/v1.3/check-correct.ts --jobs "$W/check-correct-jobs-neo4j.json" --tiers blocking --out "$W/cc"
npx tsx scripts/v1.4/ddd-t1-d8-parity.ts
diff -rq results/v1.4-ddd-b2-v9/cypher-interp/cli results/v1.4-ddd-t1-d8/neo4j/cli
```

Outputs in `results/v1.4-ddd-t1-d8/`:

- `neo4j/{rows,drift}.json` and `neo4j/cli/...`: the Neo4j T1 run, in the TIER-A3 layout;
- `neo4j/check-correct-new.json`: the checker rows for the 26 new keys;
- `t1-compare.json`: the row and drift comparison;
- `d8-parity.{json,md}`: per snapshot and per rule;
- `specs/`: the rebuilt variants, identical to TIER-A3's;
- `run-provenance.json`.
