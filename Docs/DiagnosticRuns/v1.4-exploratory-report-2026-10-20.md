## 5. Edge kind and the counted identities (estimands 4 and 9)

**Every counted identity is FF-S03.** There are 16 new identities over the 18 runs, and each one is an edge from a presentation composition root straight to persistence.

| Kind (file-name heuristic) | `none@L2` | `none@L3` | `mcp@L2` |
|---|---|---|---|
| FF-S03 wiring: `src/presentation/{server,app,composition}.ts` → `src/persistence/*` | 9 | 4 | 3 |
| FF-S03 from any other file | 0 | 0 | 0 |
| FF-S01 type-only, FF-S01 other, cycles | 0 | 0 | 0 |

- **The heuristic** (`edgeKind`, `scripts/v1.4/lib/stage-c.ts`) classes an FF-S03 edge as wiring when its source is a composition-root file in the presentation layer. Its first version listed `server`, `app`, `main` and `index`. `composition`, `container` and `bootstrap` were added after the first pass showed `none@L3` hive-health rep 1's `composition.ts`. Under the first version those 2 edges were "other". This is declared, not hidden.
- **The coded table** (cell, block, step, source, target) is in `stage-c/rescore/analysis.json` → `countedIdentities`. It is the SO5 material of estimand 9. The agent's own words around each identity (transcript excerpts) are not added here: deferred.
- **What D measures on this data, then:** whether a new slice's dependencies are constructed in the presentation entry file. It is one construct, one rule and one place in the code.
- **The file name decides it.** Under Q25 = B (at the freeze), a composition root named `main.ts`, `*.module.ts`, `*Container.ts` or under `composition-root/` is exempt from the layer rules (§8). The agents' composition roots here are named `server.ts`, `app.ts` and `composition.ts`, so they are not exempt, and their wiring imports count. The same wiring in a file named `main.ts` would count 0 (§8, the 5 MO-S03 seeds). So on this data, D is sensitive to the name the agent gives its entry file. This is a property of the construct, reported, not changed.

## 13. Limitations

- **One rule fires.** Every counted identity is FF-S03, and every one is the same habit: composition-root wiring. D is a measure of that habit here, not of Layered conformance in general (§5).
- **n = 6 blocks per cell over 3 tasks, one replicate pair per task.** The bootstrap has 3 clusters. The intervals are wide and coarse.
- **One generator** (Claude Sonnet, CLI 2.1.304 under the D1 exploratory allowance), and **one style** (Layered). DDD was deferred (DDD-BETA), and Gemini failed S4 (Amendment 1).
- **The environments differ by arm.** Stage A and the `none` cells ran under `--safe-mode`. `mcp@L2` ran under the explicit flag set (DELEG3), which is shown equivalent for `none`. Per-run HOME isolation was off in all cells (S3).
- **Seen trajectories.** Probe 1 had already run `youth-league` and `hive-health` by hand with Opus (registration §4).
- **Semantic paths and parity were not run** (§9, §10). The edge-kind heuristic was widened once after a first look (§5).
- **Seeded recall** used the final snapshots and the tool's own sampling, not the §9 "≤ 6 per snapshot on the semantic sample" (§8).
- **check-correct found nothing to remove.** All 162 rows were correct. So this study cannot show whether the filter matters on agent code.

## 14. What the confirmatory design should take from this

1. **Variance per cell, for 2b's size.** `none@L2`: mean 1.50, variance 1.10, no overdispersion (θ by moments undefined; a Poisson-like spread). `none@L3`: mean 0.67, variance 1.07, θ ≈ 1.1. `mcp@L2`: mean 0.50, variance 0.70, θ ≈ 1.25. Between-task σ² is 0.33 in `none@L2` and 0 in the treated cells, from 3 tasks. These figures replace the three Opus trajectories (μ 2.67, θ 4.27) in `level-power-sim.ts --outcome drift`. The treated cells are zero-inflated (4 of 6 at D = 0), so a zero-inflated or hurdle model is worth simulating next to NB.
2. **Distributions to pre-register.** Pre-register the whole distribution of D per cell, not only the mean: the share at D = 0 and the counts at 1, 2 and 3 or more. Pre-register Yₖ = 0 at step 5 (0/6, 4/6, 5/6 here) as a named secondary. And pre-register the step of first new identity, which was always 2 or 3.
3. **Repair as a registered secondary.** D counts only new identities, and it misses what the treated cells mostly do: they remove the inherited step-1 edges. Register, per cell:
   - "all inherited identities removed by step 5" (0/6, 5/6, 5/6);
   - Yₖ;
   - D \| R = 0, with the caveat that it keeps one run per treated cell here, so it cannot be the primary;
   - a **moved-violation** count: inherited identity removed, new identity of the same rule from a new composition file (1 run here, `none@L3` hive-health rep 1).
4. **The construct is narrow.** With FF-S03 the only firing rule, and wiring its only kind, the confirmatory tasks should be checked for exposure first. The zero-call exposure count does this (§6). If the sealed tasks give the same picture, the confirmatory claim is about composition-root wiring, and the wording should say so (G12). The Q25 = B composition-root globs decide by file name whether that wiring counts (§5, §8). The confirmatory design should state this sensitivity, and report the entry-file names per cell as a descriptive check. Renaming an entry file to `main.ts` would remove a violation without changing a dependency, so it belongs with the evasion measures.
5. **What is not settled:**
   - the semantic paths (§10) stay a question for the confirmatory design, with C1d's per-snapshot budget re-costed first;
   - seeded recall per cell (§8) feeds the V4 ADR's per-arm miss check;
   - parity on Neo4j is still owed.
