## 4. What broke, and what was done

No code under a frozen path was changed. Every new file is additive: plan templates, two zero-call scripts under `scripts/v1.4/`, one test, two documents.

| # | What broke or was missing | What was done | Blocks 2b? |
|---|---|---|---|
| F1 | **The harness at the tag has no "step 1 only" setting.** So phase (a) cannot be a plan of its own, and (b) cannot be a `sharedStart` from it | (a) and (b) are one `none@L2` plan, steps 1–5, as Stage A did in 2a. Its step 1 is the shared step 1. Adding a stop option would change `scripts/` after the freeze, so it was not added | No. Same cell, same prompts (runbook §1) |
| F2 | **Acceptance can never start a service under the declared start convention.** D12a fixed "the harness default (`npm start` with `{{port}}`)". The skeleton `package.json` has no `start` script, and the harness requires it byte-identical (`checkSkeletonIntact`, `skeleton-tampered`). So without a task `acceptance.startCommand`, every record is `no-start-command` (15/15 here, dry and live). **A zero-call probe** on the live `none@L2` step-5 tree gave `status: ran`, 1 passed, 0 failed, with a start block (`buildCommand`: `tsc` into a scratch `acc-dist/`; `startCommand`: `node acc-dist/presentation/server.js`). The runner works, but only when a start block exists | `study2b-plans.ts` now prints `tasks with acceptance.startCommand: n of N` (a count only). Runbook §3 makes "4 of 4" a gate line. This session cannot see whether the sealed tasks carry start blocks, and did not look | **Possibly.** If the sealed tasks have no start block, D12 (no waiver) is red. Making it green needs one of: a start block in the sealed tasks (changes their hash, a frozen input); a plan-level start command in the harness (a change to `scripts/` after the freeze); or acceptance run after the run, on the stored snapshots, with a start rule fixed in the pre-registration (zero calls, no instrument change). That choice belongs to the author or the coordinator |
| F3 | `loop-telemetry-check.ts` reports the inherited step-1 record of every shared-start `daedalus-mcp` run as "no process block" and "call log missing".
