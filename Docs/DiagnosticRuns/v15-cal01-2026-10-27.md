these cases. Admission to the confirmatory family is decided on CAL-02 (a fresh sealed set), not here. Catalog and
paths: `Docs/v1.5/ddd-detection-paths.md`.

## Set

  format, and none of the rules: equipment rental (K01–K08) and event ticketing (K09–K16).
- Per row: 2 positives, 2 twins (the same feature done correctly) and 1 legitimate look-alike, as overlays on a clean
  base app. That makes 80 cases plus 2 bases, all type-checked under `tsc --strict`.
- Scorer: `experiments/cal-01/score.ts`; record `experiments/cal-01/result.json`.
  - It runs the v1.5 rules and the frozen file rules (`check_diff` on the whole tree, blocking tier).
  - A positive passes when a rule mapped to its row fires in the labelled file. A clean case passes when no mapped
    rule fires.

## Rule revisions (CN-01), each principled, none per-case

| Row | Change |
|---|---|
| K06 | A function of the composition root other than the wiring itself (an app-facade member, or a function declared inside `createApp`) is a command. A facade member whose write sites are exactly one ordinary command's reports at that command (no double report) |
| K07 | An in-tree transaction or lock mechanism (owner named like one) that takes a callback is a scope. A call to an outbound port named like a remote system (Gateway, Client, Provider, …) whose methods do not take or return aggregate roots is a remote call, even when its in-tree implementation is a fake |
| K09 | An equality on an aggregate's state against a literal that the aggregate's own guard also compares with is a duplicated rule |
| K10 | Owner-first: a guard in the owner module of any invariant it matches is the owner enforcing it, so it is not reported. Only the best-matching invariant is reported. A rejection may return or skip instead of throwing |
| K11 | R-LOCK (new): a lock primitive, named by the callee or by its owner type, in application, adapter or composition code whose footprint writes an aggregate |
| K12 | R-D3 (new): arithmetic over an aggregate's state in an application unit whose result is handed back to the aggregate |
| K13 | An application interface implemented by an infrastructure adapter is a port, wherever it lives |
| K16 | R-REF (new): an aggregate root's property or parameter property whose type is another declared root. Declared roots only: with inferred roots an inner entity can be taken for a root (precision fixtures p05, p10) |

## Case and label defects found (not rule failures)

- **K04 positives conflict with ruling B1.** `saveBoth` is declared on the port and adapter but never called. Under B1
  (P1-SG1-c), an unused multi-root write is clean, so these positives are mislabelled by our own construct. CAL-02's
  K04 positives must call the method.
- **K03 twin2** calls two single-save commands in one synchronous flow. Under the D4 construct ("one command changes
  and saves one aggregate") that is the violation, so the label is disputed. The case author also marked it as a weak
  twin.
- **K08 legit** is a whole-number check on a value handed to the aggregate. R-D5 deliberately counts `Number.*`
  tests. Format check versus business rule is a construct edge, reported and not changed.
- **The events base app** saves two aggregates in one command (`sellSeat`). The base is not clean, so R-D4 is right
  there. Its findings are excluded from the events rows by the mapping.

## Instrument defects found

1. **Silent DDD switch-off in the frozen rules.** When the frozen DDD binder rejects a spec (here an inner entity
   given as a class name instead of a path), every frozen DDD rule is skipped without a message. Before the study,
   every spec must pass the frozen binder (a zero-call check).
2. **Spec schema gap.** A spec that satisfies the v1.5 reader can fail the frozen schema (`scoring`,
   `confidence_thresholds`, layer `roles`). The study specs must satisfy both.
