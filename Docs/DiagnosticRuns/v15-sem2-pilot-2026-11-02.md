## Reading

The mechanism works in an agent loop: the deferred judge ran inside the hub and kept push checks far under the 5 s
limit, and delivery matched scoring. The pilot does not say whether the semantic layer changes agent behaviour, because
no agent in either arm ended with the renamed-copy shortcut, so there was nothing to prevent. With 4 sessions per arm, a
true shortcut rate up to about 60 % per arm is still compatible with 0 / 4.

Status of the semantic thread after this pilot: SEM-GATE-2 shows the rule detects form-A copies with no false positives
on fixtures (11 / 11, 0 / 42); SEM-2 shows the judge runs in the loop at acceptable latency; agent-level effect: not
measured (the tasks did not draw the shape out). A follow-up would need tasks that do (a different frame or seed), which
is a new exploratory design and is not started here.

## Correction (2026-11-03): G4 red was a measurement miss

A hand read of the eight final-step trees (`sessions/c00N/snap/step-03`) found the renamed-copy shortcut in a form that
neither the task oracle nor R-MIRROR-SEM v1.5.9 recognised ("form C"): a lookup object in the core service whose keys
are the vendor's states, indexed with the vendor text the `JobLookup` / readings port carries, with no declared type.

| Arm | Shortcut at the final step (hand read) | Sessions |
|---|---|---|
| none | 3 / 4 | c001, c006, c008 |
| combined | 1 / 4 | c005 |

c002, c003, c004 and c007 map the vendor states in the adapter. So the statements above that no agent ended with the
shortcut, and the Reading section, are superseded: G4 was red because the oracle missed the shortcut, not because the
agents avoided it. Four sessions per arm support no claim about an effect.
