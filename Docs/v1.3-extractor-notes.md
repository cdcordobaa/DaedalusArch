# v1.3 extractor notes: dynamic imports and NestJS module wiring

Status: **implemented, OFF by default, not part of the v1.2E instrument.** Branch `v1.3-extractor-fixes` (from `v1.3-mcp-prototype`). Both features close gaps found by the dependency-cruiser comparison (`Docs/DiagnosticRuns/tool-comparison-real-pairs-2026-10-10.md`): RC-DYNAMIC-IMPORT (MO-X01: dependency-cruiser 6 of 6, DaedalusArch 0 of 6) and "no rule of either tool reads module wiring" (p5).

## Default-off guarantee

Nothing in the registered artefact set (`REGISTERED_ARTEFACTS`, `scripts/lib/prereg.ts`) is edited, and `--check-prereg` passes on every `experiments/*/plan.json`. Every v1.2E code path is unchanged unless an option is set:

| Option | Where | Default | Effect |
| --- | --- | --- | --- |
| `ExtractorOptions.dynamicImports` | `src/apg-extractor/types.ts` | `false` | Feature 1 |
| `ExtractorOptions.moduleWiring` | `src/apg-extractor/types.ts` | `false` | Feature 2 |
| `CompileOptions.v13Templates` | `src/fitness-compiler/fitness-compiler.ts` | `false` | Resolves the v1.3 example template |

The frozen catalogue `CYPHER_TEMPLATES` (25 templates), `EDGE_TYPES` (mirrored by the report schema and the SO2 CSV columns) and `GRAPH_MODES` are not touched. The new edge types live in `V13_EDGE_TYPES` (`src/shared/types/enums.ts`), and `APGEdge.type` is widened to `EdgeType | V13EdgeType`. No CLI flag or experiment plan sets the options, so no existing run can change.

## Feature 1: dynamic import edges (`dynamicImports`)

`import('x')` and `require('x')` calls whose first argument is a string literal (or a substitution-free template literal) become `IMPORTS` edges with `dynamic: true`.

- **Resolution** is the static one (`resolveModule`): relative, `paths`/`baseUrl` aliases, built-ins, bare packages (Package nodes). An unresolvable specifier warns `EXTRACTOR_002` and gives no edge, like a static import.
- **Shape**: `importedNames: ['*']` (the whole module, no barrel routing), `line` = the call's line, `isTypeOnly: false`.
- **Merging**: one edge per `(source, target)` as before. If a static import reaches the same target, the merged edge is the static one and has no `dynamic` property (the dependency exists without the call). `dynamic: true` therefore means "this edge exists only because of a dynamic call".
- **Counters**: the statement partition counters (`resolvedInternal`, `external`, ...) are unchanged. With the option on, `unsupportedDynamic` and `EXTRACTOR_009` count only the calls that stay unmodelled (computed specifiers).
- **Graph modes**: `ast-only` keeps IMPORTS, so dynamic edges survive it.

Evidence: `tests/unit/apg-extractor/v13-dynamic-imports.test.ts`. The MO-X01 seed shape (`async load<Name>Module() { return import('<relative>'); }` in a domain class) yields no IMPORTS edge by default and a `dynamic: true` domain to infrastructure edge with the option on.

## Feature 2: NestJS module wiring (`moduleWiring`)

The `@Module({ imports, providers, controllers, exports })` object literal of a class becomes edges between Class nodes:

| Edge | From | To | Properties |
| --- | --- | --- | --- |
| `MODULE_IMPORTS` | module | imported module | `dynamicModule`, `forwardRef`, `line` |
| `MODULE_PROVIDES` | module | provider or controller class | `role` (`provider` or `controller`), `forwardRef`, `line` |
| `MODULE_EXPORTS` | module | exported class or re-exported module | `dynamicModule`, `forwardRef`, `line` |

Read syntactically: `Foo`, `Foo.forRoot(...)` (`dynamicModule: true`), `forwardRef(() => Foo)`, and `{ provide: Token, useClass: Foo }` (target is `useClass`, else `provide`). Aliased imports are followed. One edge per `(type, module, target)`, first kept. An element that is not a class of the extracted set (external module, string token, computed expression) is skipped with warning `EXTRACTOR_010`. Edge order is section order (imports, providers, controllers, exports), then element order, after the file's v1.2E edges. `ast-only` mode drops these edges. The Neo4j ingester writes them (`graph-ingester.ts` appends `V13_EDGE_TYPES`; they occur only with the option on).

Evidence: `tests/unit/apg-extractor/v13-module-wiring.test.ts` (in-memory fixtures, including a check that the v1.2E edges are identical with the option on or off).

### Example fitness function

`module-domain-imports-infrastructure` (`src/fitness-compiler/v13-templates.ts`, registry `V13_CYPHER_TEMPLATES`): a domain-layer module whose `@Module` metadata imports an infrastructure-layer module. It matches `(m:Class)-[:MODULE_IMPORTS]->(t:Class)` with `m.layer = $domainLayer AND t.layer = $infraLayer`, so it sees wiring that no file-level import rule sees. It applies to `clean-architecture` and `nestjs`, needs both layers bound, supports `exclude_paths`, and is reachable only through `compileFunctions(input, { v13Templates: true })`. Tests: `tests/unit/fitness-compiler/v13-templates.test.ts`.

Known limits: `spec-validator` still checks function names against `CYPHER_TEMPLATES` only, so a spec naming the v1.3 template does not validate yet; `compileFunctions` with the flag is the entry point for now. The template has no symbolic-evaluator evidence mapping beyond its `resultMapping`. Neither is wired into the pipeline or CLI, deliberately.

## How a future pre-registered round would evaluate them

Nothing here changes a v1.2E claim; any claim about v1.3 needs its own registration (new prereg version, new plan files, registered artefact hashes including this extractor commit, and the same degradation-ladder and threats-register rules).

1. **Feature 1 (dynamic imports).** Re-run the tool-comparison MO-X01 cell (`FF-S01` seeds, dependency-cruiser as the reference) on the same real-pair corpus with `dynamicImports: true` as a second arm next to the frozen arm. Primary: recall on the 6 MO-X01 seeds (frozen arm 0 of 6; target parity with dependency-cruiser 6 of 6) and the MO-X01n twins as the false-positive control. Secondary: change in findings on the non-seed corpus (a dynamic edge in a domain file is a new true or false finding; each new finding labelled under the existing labeller route). Predeclare the dynamic-edge definition above (string literals only) so computed specifiers cannot be counted as a miss.
2. **Feature 2 (module wiring).** The p5-type pairs (fix changes only NestJS wiring) are the targets: predict, before the run, that the example template fires before the fix and not after on the pairs whose fix moves an infrastructure module out of a domain module's `imports`. Measure per-pair detection against the human-labelled fix direction, plus the rate of `EXTRACTOR_010` skips (extraction coverage of the `@Module` metadata). Also run the seed generator with a registered wiring operator (a new operator-catalogue entry, which is itself a registered artefact) so recall is measured on seeds and not only on pairs.
3. **Both.** Report extraction overhead (nodes, edges, extraction time) per arm and keep the frozen arm byte-identical to the v1.2E result so the two arms are paired on the same inputs. A negative or null result is reported as such.
