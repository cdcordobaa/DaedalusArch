# v1.3 graph adapter: notes

Status: prototype on branch `v1.3-graph-adapter`, cut from `v1.2e`. Draft; not part of the v1.2E instrument.
Nothing here edits a registered artefact (`REGISTERED_ARTEFACTS`, `scripts/lib/prereg.ts`); `--check-prereg` still
passes (v25, 85 artefacts unchanged). New code: `src/graph-adapters/`, `tests/unit/graph-adapters/`,
`tests/fixtures/graph-adapters/`, this file.

**Purpose.** Show that the fitness functions (the compiled Cypher in `src/fitness-compiler/cypher-templates.ts`) do not
depend on DaedalusArch's own extractor: they run over any graph in the APG schema, including graphs built from the
exports of popular agent-context tools. The adapters convert such an export into `APGNode` / `APGEdge`; the existing
layer annotation, ingestion and templates then apply unchanged.

## 1. What each tool exports (TypeScript)

Confidence differs by tool. The three tools document their schemas thinly, so each line is marked **doc** (stated in a
public README or docs page I read), **src** (read from a source file), or **recollection** (not re-verified; confirm
against a real export before the experiment in §4). The fixtures are synthetic and encode exactly what is written here;
they prove the adapter logic, not that a real export has this shape.

### graphify (`safishamsi/graphify`)

- Files: `graphify-out/graph.json`, `GRAPH_REPORT.md`; `to_graphml` writes GraphML. **src** (`export.py`).
- `graph.json` is networkx node-link data with edges under `links` (not `edges`), a `community` field added per node
  (null if none), a top-level `hyperedges` list, and `graph.schema_version` / `graph.graphify_version`. **src, doc**
- Node attributes: `id`, `label`, `file_type`, `source_file`, `source_location` (`"L42"`). **doc** (extraction schema)
- Edge attributes: `source`, `target`, `relation`, `confidence` (`EXTRACTED` / `INFERRED` / `AMBIGUOUS`), and
  `confidence_score` (1.0 / 0.5 / 0.2 derived at export). **doc, src**
- Relations named in the docs: `calls`, `imports`, `inherits`, `mixes_in`, `uses`, `references`, `method`. The list is
  not exhaustive; `imports_from`, `contains` and `defines` are **recollection**.
- GraphML: attributes carried as `<data>`; `community` is `-1` when unset. **src**
- TypeScript: parsed with tree-sitter (about 40 languages). It is generic extraction: **no interface node kind and no
  implements relation** (one `inherits`). Node kind is not a stored attribute: the adapter infers file (label equals the
  file's basename), function / method (label ends in `()`, method when it starts with `.`) and class (everything else
  with a code source file). A producer that adds a `kind` / `node_type` attribute is honoured.

### CodeGraphContext (`CodeGraphContext/CodeGraphContext`)

- Export: a `.cgc` bundle, a ZIP of `metadata.json`, `schema.json`, `nodes.jsonl`, `edges.jsonl`, `stats.json`,
  `README.md`. **doc** (`docs/docs/guides/bundles.md`)
- `nodes.jsonl`: `_id`, `_labels`, `name`, `path`, `line_number`, other properties. `edges.jsonl`: `from`, `to`, `type`,
  `properties`. **doc**
- Labels confirmed by the docs: `Function`, `Class`. Types confirmed: `CALLS`, `INHERITS`. Decorators are stored on
  functions and classes. TypeScript and TSX are supported. **doc**
- `File`, `Module`, `Interface`, `Repository`, `Directory`, `Variable` labels; `CONTAINS`, `IMPORTS` types; methods as
  `Function` nodes with a `class_context` property; absolute `path` values. **recollection**
- Backends: KuzuDB, LadybugDB, FalkorDB, Neo4j. A Neo4j-backed index can be queried directly with Cypher, which is a
  better route than the bundle for the experiment (the APG templates are already Cypher).

### GitNexus (`abhigyanpatwari/GitNexus`)

- Stored in an embedded graph database, not a documented file export. Nodes: File, Folder, Module/Package, Function,
  Class, Method, Interface, Enum, Variable (plus Struct, Trait, Namespace, TypeAlias, Decorator, Constructor for other
  languages), Community, Process. **doc** (docs mirror)
- All edges are `CodeRelation` rows with a `type` of `CONTAINS`, `DEFINES`, `CALLS`, `IMPORTS`, `EXTENDS`,
  `IMPLEMENTS`, `MEMBER_OF`, `STEP_IN_PROCESS`, each with `confidence` and `reason` (1.0 same-file / import-resolved,
  0.85 import-resolved across files, 0.5 and 0.3 fuzzy global). **doc**
- A third-party post lists only four edge types; the docs mirror lists eight. I follow the docs. **conflict**
- Node id format and a class→method edge (`HAS_METHOD`) are not documented. The reader accepts the in-memory shape
  `{ nodes: [{id, label, properties}], relationships: [{sourceId, targetId, type, confidence, reason}] }`, which is an
  **assumption**. Package nodes for external imports are not documented, so they are treated as absent.

## 2. The mapping layer

`adaptExternalGraph(format, input, options)` in `src/graph-adapters/index.ts`. Four formats:
`graphify-json`, `graphify-graphml`, `codegraphcontext` (two JSONL texts; unzip the bundle first), `gitnexus`.

Each reader normalises its tool's graph (`NormalizedGraph`); one shared builder (`apg-builder.ts`) maps it to the APG.
Node ids use the extractor's own `generateNodeId`, so the same declaration gets the same id from an adapter and from
ts-morph. Package nodes use the extractor's `PackageNodeRegistry` and root-naming rules.

| APG element | Rule |
|---|---|
| File | file node with a TypeScript/JavaScript path; other documents dropped and counted |
| Class / Interface / Function | by tool kind; needs a declaring File node |
| Method | `Class.method` qualified name, as the extractor names it; needs an owning class or interface |
| Package | import target that is not a project file; root named by the extractor's rules (`node:fs` → `fs`, `@s/p/x` → `@s/p`) |
| IMPORTS | file→file, file→Package. A symbol-level import is lifted to its file. Module specifiers are resolved against the export's files (relative only, `.js`→`.ts`, `index.ts`); `paths` / `baseUrl` aliases are not resolved and are dropped if not package-shaped |
| DECLARES / CONTAINS | File→Class/Interface/Function, and Class/Interface→Method (also derived from method ownership) |
| EXTENDS / IMPLEMENTS | class→class `inherits` becomes EXTENDS; class→interface `inherits` becomes IMPLEMENTS |
| CALLS | Method→Method only (the extractor's own shape); function-level calls dropped and counted |
| `isBarrel` | no tool exports it: heuristic (`index.*` that imports and declares nothing) |
| `layer` | not set by the adapter; the existing layer annotator sets it from paths, identically for every source |

`AdapterOptions.minConfidence` drops edges scored below a threshold (graphify, GitNexus). Absolute paths (CodeGraphContext)
are made project-relative with `projectRoot`, else the common directory prefix. **Pass `projectRoot`**: the prefix
fallback strips too much when every file sits under one directory, and layer globs depend on the path.

### 2.1 APG edges the adapters cannot produce

| APG edge | graphify (json, graphml) | CodeGraphContext | GitNexus | Why |
|---|---|---|---|---|
| IMPORTS | derived | derived | native | CGC names modules by specifier; resolved here; no `isTypeOnly`, `importedNames`; lines only where exported |
| DECLARES | derived | native | native | |
| CONTAINS | derived | native | derived | ownership is the edge when the tool lists no class→method edge |
| EXTENDS | heuristic | derived | native | graphify: `implements` between class-kind nodes also reads as EXTENDS |
| IMPLEMENTS | **absent** | heuristic | native | graphify has no interface kind; CGC has one INHERITS type |
| CALLS | derived | native | native | Method→Method only; fuzzy matches carry low confidence |
| **CONSTRUCTOR_INJECTS** | **absent** | **absent** | **absent** | needs type resolution of constructor parameters and DI decorators; no tool records it |
| **RE_EXPORTS** | **absent** | **absent** | **absent** | `export … from` is folded into IMPORTS (or lost) by all three |
| **FLOWS_TO** | **absent** | **absent** | **absent** | needs the D8 store analysis (field = `new` / parameter assignment); no tool has it |

Node types: Interface is absent for graphify (and unverified for CGC); Package is absent for GitNexus; Function is
available everywhere. Properties: `decorators` only for CGC (derived); `isBarrel` heuristic everywhere; IMPORTS edges
lose `isTypeOnly`, `importedNames` and (graphify, GitNexus) `line`. A rule that keys on `i.line` or `isTypeOnly` runs, but
its findings carry `line = 0` / `isTypeOnly = false`, which matters for the registered location matching rule
(`Docs/matching-rule.md`): finding-to-seed matching on these graphs would be at file level only.

## 3. Coverage matrix: which fitness functions run on which graph

Computed, not hand-written: `computeCoverageMatrix()` reads the node labels, edge types (and whether each sits in a
plain `MATCH`, an `OPTIONAL MATCH` or a `NOT EXISTS`) and `isBarrel` / `decorators` use from the compiled Cypher, and
compares them with `FORMAT_CAPABILITIES`. A test asserts that an `absent` edge type produces no edge in the fixtures
and that every other type produces at least one.

- **full**: every element the Cypher needs is present; the result should equal the APG's apart from import-resolution
  differences (see the caveat below).
- **partial**: runs; one blind spot (no RE_EXPORTS hops, an empty optional arm, a heuristic `isBarrel`).
- **degraded**: runs on a guessed edge or node kind; results can be wrong in both directions.
- **blocked**: cannot give a meaningful answer. A required pattern with no producible edge passes **vacuously** (no
  rows); a `NOT EXISTS` pattern with none flags **every** candidate (false positives).

| Fitness function | graphify (json / graphml) | CodeGraphContext | GitNexus |
|---|---|---|---|
| `dependency-direction` | partial | partial | partial |
| `no-cyclic-deps` | partial | partial | partial |
| `no-layer-skip` | partial | partial | partial |
| `no-domain-outward-dep` | partial | partial | partial |
| `domain-purity` | partial | partial | **blocked** (no Package nodes) |
| `domain-state-purity` | **blocked** | **blocked** | **blocked** |
| `dependency-inversion` | **blocked** | **blocked** | **blocked** |
| `repository-pattern` | **blocked** (false positives) | degraded | full |
| `use-case-isolation` | **blocked** | **blocked** | **blocked** |
| `controller-no-entity` | partial | partial | partial |
| `domain-stability` | full | full | full |
| `module-fan-out` | full | full | full |
| `component-instability` | full | full | full |
| `no-orphan-files` | partial | partial | partial |
| `max-fan-in` | full | full | full |
| `abstraction-ratio` | **blocked** (ratio 0, always flags) | full | full |
| `single-responsibility-proxy` | partial | partial | partial |
| `interface-segregation-proxy` | **blocked** | degraded | full |
| `inheritance-depth` | degraded | full | full |
| `naming-conventions` | full | full | full |
| `naming-services` | full | full | full |
| `naming-repos` | full | full | full |
| `naming-controllers` | **blocked** (no decorators) | full | **blocked** (no decorators) |
| `test-file-pairing` | partial | partial | partial |
| `no-index-logic` | partial | partial | partial |

Totals over the 25 templates (full / partial / degraded / blocked): graphify 7 / 10 / 1 / 7; CodeGraphContext
10 / 10 / 2 / 3; GitNexus 11 / 9 / 0 / 5.

Reading the matrix:

- The structural and topological core (imports, fan-in/out, instability, cycles, orphan files, naming) runs on every
  graph. That is the claim the prototype supports: those rules depend on the APG schema, not on the extractor.
- The pattern rules that need dependency injection (`dependency-inversion`, `use-case-isolation`, `domain-state-purity`)
  and the controller-injection hop are out of reach for all three tools, because CONSTRUCTOR_INJECTS and FLOWS_TO are
  extractor-specific. They are also the rules where the APG's extra edges matter most.
- "full" means the Cypher has what it needs, not that the numbers match. The import graphs differ in resolution
  (tsconfig `paths`, `baseUrl`, barrels, type-only imports, `import()`), in what counts as a file, and in the
  per-edge line data. Equality of the two import graphs is something to measure (§4), not to assume.
- `repository-pattern` on graphify is the worst case: a missing IMPLEMENTS inside `NOT EXISTS` flags every repository.
  A blocked status is a hazard of false findings, not just missed findings.
- The matrix is static. Whether a given export contains each construct (for example whether graphify emits file→class
  `contains` edges for TypeScript) must be checked on a real export.

## 4. Future experiment: the same rules over the APG and over the graphify graph

Question: how much of the fitness functions' detection power comes from the APG's richer extraction, rather than from
the rules? This extends the SO2 ablation (`apg-ablation`, ADR-021 SO2-5 / X-2): that experiment removes edge types
from the APG itself (`ast-only` keeps IMPORTS, DECLARES, CONTAINS); this one swaps the graph source.

**Arms** (per corpus project, same specs, same layer annotation, same `symbolic-only` evaluation):

| Arm | Graph | Notes |
|---|---|---|
| A | APG `full` | the registered instrument |
| B | APG `ast-only` | already registered; the within-extractor lower bound |
| C | graphify graph, adapted | `minConfidence` 0 and a second sensitivity arm at 0.5 |
| D (optional) | CodeGraphContext / GitNexus, adapted | same adapter; only where the tool indexes the corpus cleanly |

**Procedure.**
1. Index each corpus project with graphify (and optionally the others) at a pinned version; record version, command and
   flags in the run record. Do not hand-edit exports.
2. Adapt with a fixed `projectRoot`; record the adapter report (counts by type, dropped by reason, unmapped relations).
3. **Graph-level agreement first**, before any rule: for each project, IMPORTS file→file edge set precision / recall
   of C against A (A as reference, with the caveat that A is not ground truth either); node counts by type; share of
   imports dropped as alias / unresolved. This separates "the adapter lost edges" from "the rules lost power".
4. Run the 25 templates on A, B and C with identical parameters. Do not run `blocked` cells as detection results: report
   them as "not evaluable" so a vacuous pass is not counted as a pass.
5. Score against the corpus labels with the registered matching rule. File-level matching only for C (no `line`);
   compute A at file level too, so the arms are comparable. Report the registered-location score for A separately.

**Outcomes** (descriptive, as in the SO2 ablation, unless pre-registered otherwise):
- Per fitness function: seeds detected by A, B, C; detections lost going A→B and A→C; false positives gained.
- Decomposition of A→C loss into (i) edge types absent by construction (matrix above), (ii) import-resolution loss
  (step 3), (iii) kind confusion (interfaces as classes). B isolates (i) for the rules that need only IMPORTS /
  DECLARES / CONTAINS; if B and C agree on a function, the rule is import-bound and the extractor adds nothing for it.
- The headline number is the share of seeded violations a rule detects on C relative to A, split by dimension
  (structural, coupling, pattern, solid, convention).

**Hypotheses** (to be registered before running, in the SO2 form):
- H-G1: on structural and coupling functions with a `full` or `partial` cell, C detects at least as many seeds as B and
  no more than A.
- H-G2: on pattern functions that need CONSTRUCTOR_INJECTS or FLOWS_TO, C detects none; the A-minus-C gap there is the
  APG's contribution that no off-the-shelf tool replaces.
- H-G3: the A→C loss on `full` cells is explained by import-resolution differences, not by the rules.

**Threats.** Graphify version drift and LLM-assisted extraction for non-code files (use code-only mode; the TypeScript
path is tree-sitter); the adapter's heuristics (kind inference, `isBarrel`, import resolution without tsconfig) are
part of the arm under test, so a weak adapter understates the tool; the corpus was built around the APG's capabilities
(selection effects favour A); fixtures here are synthetic. Any registered run needs a prereg bump and an ADR; this
branch does not do that.

**Cost.** Indexing plus adapting the nine ablation projects, then running two extra symbolic arms; no LLM calls beyond
what graphify itself makes (none in code-only mode).

## 5. Not done

- No tool was installed or run; no real export was read. All fixtures are synthetic.
- No CLI or `run-experiment` integration (a `graphSource` plan field would touch registered code).
- No Neo4j ingestion test of the adapted graph; the adapted nodes use the `APGNode` / `APGEdge` types the ingester
  takes, but that path was not exercised here.
- Barrel files, `export * from` and type-only imports are not recoverable from any of the three exports.
