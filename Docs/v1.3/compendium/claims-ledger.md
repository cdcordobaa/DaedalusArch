## Method

1. **Scope of a claim.** A claim is any sentence or table row that states a measured or computed result: a count, rate, interval, agreement, κ, p-value, effect size, power, cost, latency or test outcome offered as evidence. Registered Study 2 design parameters are also claims where a protocol document states them. Not claims: dates, PR and commit identifiers, section and line references, version pins, effort estimates, worked examples, and figures about other authors' studies. Large per-item tables (more than about 20 rows) are covered by their total row and the rows the text discusses. Their cell-level numbers are registered one by one in the replication package (5,154 numbers, `replication/v1.3/groups/*.mjs`), and the ledger's `replication` column points to that group.
2. **Verification.** Each claim was traced to its primary report and, where one is committed, to its results file (`results/...`). The replication output (`Docs/v1.3/replication-2/`) and the reproducibility audit were also used. The `verified against` column records which. A secondary document (summary, plan, dashboard, paper) names its primary. A number the primary contradicts is marked **superseded**, and the correct value is given under Conflicts. A number whose primary is not on `v1.3` (open PRs, uncommitted run directories) is marked **exploratory**.
3. **Mechanical check.** `node scripts/v1.3/claims-ledger-check.mjs` re-reads every cited `file:line` in this file and in `claims-ledger/*.md`, and fails if any listed number string is no longer on its line. It also checks the conflicts tables below, where the `numbers` column holds the conflicting value as the source states it. Run it after any edit to a cited document, because a moved line fails the check by design.
4. **Who did it.** AI sessions extracted the claims and checked each batch against the primary sources. No model or Neo4j was called; only committed files were read. No sealed directory, `.env` or secret was read.

## Legend

- **type**: `correctness` (is a reported finding or edge true of the code); `criterion` (agreement with an independent statement of what should be found: expected manifests, seeded recall, blind manifests, known groups, fix mining, erosion); `convergent` (agreement with other tools); `metamorphic`; `mutation`; `reliability` (determinism, re-run identity, inter-rater or inter-model agreement, replication counts, latency stability); `neural` (the LLM judge and its complements); `pilot` (loop pilot, floor and precedent probes, spec ladder, Study 1 spec-level outcomes); `power` (power analyses, simulations, registered design sizes); `descriptive` (corpus sizes, costs, tool and test counts). `descriptive` was added to the eight types of the request, so that such figures are not forced into a validity category.
- **set**: `development` (tuned-on data: the 71-variant reference set, E1/SO4 corpora, fixtures, seeded variants, rehearsal tasks); `external` (the 15 human-written repositories of #133/#181/#232); `wild` (the 14 public backends of #114; the fix-mining corpus of 36 repositories, which adds 15 external and 7 new repositories to the wild 14, is also tagged `wild`); `hold-out` (the sealed v1.3 hold-out: **not run**, so its 8 rows are protocol facts and thresholds, not results); `synthetic` (simulations, generated telemetry, dry runs); `none` (repository facts and design parameters). The last two were added to the four sets of the request.
- **status**: `established` (a measured result on committed data, confirmed in the primary report or its results file, stated within its scope); `exploratory` (post-hoc, unadjudicated, a single probe, a simulation or plan figure, from an unmerged PR, or not confirmable from committed data); `null` (a null or negative result: no effect, target missed, criterion failed, floor); `superseded` (replaced by a later figure, or contradicted by the results file, the replication output or the audit; see Conflicts).
- **replication**: the group id in `replication/v1.3/groups/*.mjs` (run with `node replication/v1.3/run.mjs --group <id>`); `—` if the number is not registered there. Replication part 2 does not cover the documents added after `5ece0526`.

## Conflicts

A conflict, in this register, is a case where a document states a value for a quantity that differs from the value given by the primary report for that quantity, by its committed results file, by the replication output (`Docs/v1.3/replication-2.md` and `Docs/v1.3/replication-2/`) or by the reproducibility audit (`Docs/DiagnosticRuns/v1.3-repro-audit-2026-10-16.md`). The correct value was taken from the primary report, then from its committed results file, then from the replication output; where the primary report is itself wrong, its committed results file prevails. Each row cites one document line that states the conflicting value; when the same value recurs in several documents, each occurrence has its own row. Figures that are correct for a dated run or commit are marked as such rather than treated as errors.
