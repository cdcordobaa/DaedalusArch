## 2. Defect 1: FF-CV03 selects `…Report…` classes as repositories

**Status: the defect is in frozen Cypher template text. It is not fixed here. A proposed diff for the author is in
§2.3.** The construct question is already open in `Docs/v1.3/construct-question-ff-cv03.md` (options A, B, C).

### 2.1 Where the defect is

FF-CV03 (`naming-repos`) has a selection part and a conformance part.

| Part | Location | Text | Defect? |
|---|---|---|---|
| Selection (template) | `src/fitness-compiler/cypher-templates.ts:468` | `WHERE (c.name CONTAINS 'Repository' OR c.name CONTAINS 'Repo')` | **Yes.** `CsvReportWriter`, `SalesReportService` and `DoctorUtilizationReportUseCase` contain `Repo`. |
| Selection (MCP mirror) | `src/mcp-server/file-check.ts:128-129` (`selectedByNaming`) | `cls.name.includes('Repository') \|\| cls.name.includes('Repo')` | Same defect. It copies the template. |
| Conformance (binding) | `src/fitness-compiler/pattern-compiler.ts` (`compilePattern`) | `*Repository\|*Repo` becomes `^(?:.*Repository\|.*Repo)$` | No. It is anchored to the suffix already. |

The TypeScript binding is correct, so the task's condition for a TypeScript fix does not hold. The MCP mirror is
TypeScript, but it must select exactly what the template selects. Changing it alone would make `check_file` disagree
with the scored evaluation, which is the parity the MCP arm depends on (backlog job V1, PR #176). It is therefore
left unchanged too.

### 2.3 Proposed diff (option B, behind a compile option; NOT applied)

This follows the existing `roleTokens` mechanism (`src/fitness-compiler/v13-role-names.ts`). The frozen template text
is not edited. The compiled text is rewritten only when a new, default-off flag is set, so the v1.2E compile output
and the 71 reference results stay byte-identical until the author enables it. The selection keeps every class with
`Repo` or `Repository` as a camel-case token (`OrderRepoImpl2`, `UserRepositoryHelper` are still selected and
checked). It drops a `Repo` that continues in lower case (`Report`, `Reporter`, `Repos`).

```diff
--- a/src/fitness-compiler/v13-role-names.ts
+++ b/src/fitness-compiler/v13-role-names.ts
@@
+/**
+ * Construct switch for FF-CV03 naming-repos (Docs/v1.3/construct-question-ff-cv03.md, option B). The selection keeps
+ * a class whose name has `Repo` or `Repository` as a camel-case token: followed by an upper-case letter, a digit or
+ * the end of the name. `CsvReportWriter` is no longer selected; `OrderRepoImpl2` still is. Applied only when
+ * `CompileOptions.namingRoleTokens` is set; off in V13_COMPILE_OPTIONS until the author answers the question.
+ */
+export const NAMING_REPOS_TOKEN_REWRITE = Object.freeze({
+  from: "(c.name CONTAINS 'Repository' OR c.name CONTAINS 'Repo')",
+  to: "c.name =~ '.*Repo(sitory)?([A-Z0-9].*)?'",
+});
+
+export function applyNamingRoleTokens(templateName: string, cypher: string): string {
+  if (templateName !== 'naming-repos') return cypher;
+  const { from, to } = NAMING_REPOS_TOKEN_REWRITE;
+  if (!cypher.includes(from)) throw new Error(`naming role tokens: naming-repos no longer contains ${JSON.stringify(from)}`);
+  return cypher.split(from).join(to);
+}
```

Plus: the `namingRoleTokens` field (in `file-check.ts`, `options` stands for the server context's compile options,
which `selectedByNaming` would take as a new parameter) on `CompileOptions` (`fitness-compiler.ts:69` area), threaded like `roleTokens`;
the same option on the MCP server context; and a CLI flag if the author wants it on the command line.

**Regression tests to add with it:**
1. Off: the compiled `naming-repos` text equals the frozen text (byte-identical v1.2E compile).
2. On: on an in-process graph (`cypher-interp`) with classes `CsvReportWriter`, `SalesReportService`, `UserRepo`,
   `OrderRepositoryImpl`, `OrderRepoImpl2`, `UserRepos` and `RepoHelperX`, FF-CV03 selects exactly `UserRepo`,
   `OrderRepositoryImpl`, `OrderRepoImpl2` and `RepoHelperX`. Under the spec pattern, it flags `OrderRepositoryImpl`,
   `OrderRepoImpl2` and `RepoHelperX`.
3. Parity: `selectedByNaming` and the compiled query select the same set on that graph, with the option on and off.
4. Reference set with the option on: exactly two FF-CV03 rows fewer (§2.2), no verdict change; with it off,
   byte-identical.

**Note on `=~`.** Cypher's `=~` matches the whole string, so the pattern needs the leading `.*` and has no anchors.
The interpreter's handling of `=~` should be checked against Neo4j for this pattern, as the interpreter docs require
for any new text (`Docs/v1.3/cypher-interpreter.md`).

The same question applies to FF-CV02 `naming-services` (`CONTAINS 'Service'` also selects a class such as
`ServiceabilityReport`, where `Service` continues in lower case). The construct sheet groups the two rules. The diff above covers FF-CV03 only.
