This part covers **every number stated in `Docs/DiagnosticRuns/v1.3-*.md` and `Docs/v1.3/*.md`** (48 docs): the 47 on
`origin/v1.3` at `e46aa6b8`, plus `Docs/v1.3/loop-replay.md`, which landed with PR #142 during this work. For each number it gives the script and committed input that produce it. It regenerates the
number offline where it can and compares it with the stated value.

- **Branch:** `v1.3-replication-2`, from `origin/v1.3` at `e46aa6b8`, with `origin/v1.3` at `a6723c34` (PR #142) merged
  in. The full run was at `8b6c1398`, which differs from `a6723c34` only by the package files.
- **Docs:** not edited. Every mismatch is reported below.

  process.
- **No Neo4j.** Where a doc allows it, the run uses `--engine cypher-interp`.

## 1. How to run

```bash
replication/setup.sh                                   # once: npm ci + pinned dependency-cruiser 18.4.0
npm run replicate:v1.3                                 # all 83 offline groups, then the pass/fail table (80 min here)
npm run replicate:v1.3 -- --fast                       # skip the groups marked slow
node replication/v1.3/run.mjs --list                   # the 91 groups: number count, what each needs, its command
node replication/v1.3/run.mjs --group <group>          # one group; each row below names its group command
node replication/v1.3/run.mjs --number <id>            # the group holding one number, and that row
node replication/v1.3/run.mjs --json rows.json && node replication/v1.3/report.mjs rows.json --dir Docs/v1.3/replication-2
```

- **Code:** `replication/v1.3/run.mjs` (runner), `replication/v1.3/groups/*.mjs` (one module per topic: the
  numbers, their doc file:line, the stated value, and a `run(ctx)` that regenerates them), and
  `replication/v1.3/report.mjs` (the tables of this doc).
- **Where groups run:** a group that runs a script which writes into the repository runs it in a scratch
  `git archive HEAD` export.
- **The slow groups:**
  - `g-aph-seed`, ap-hosts seeding and the sweep of all four hosts: 39 min;
  - `h-pmr-construct`: 8 min;
  - `d-audit-smoke`, the PR #117 smoke run: 4 min;
  - `e-ci-ubl` and `a-ref-amf-interp`, the reference run through the interpreter: about 3.5 min each.

### What a "number" is

Registered: every number that states a fact about a result or about the repository. That covers counts, rates,
intervals, hashes, test counts, timings, sizes, and counts of files, rules, jobs or tools.

- A composite cell such as `12/13 = 0.92 [0.67, 0.99]` is one number, compared as a whole string.
- Each table cell is its own number.
- A claim repeated on another line or in another doc is registered again at each occurrence.

Excluded, and counted per doc by each group author:

- dates;
- version pins;
- section, line, PR and commit references;
- identifiers containing digits (FF-P06, Q8, v1.3);
- literature citations;
- decision parameters and pre-registered thresholds ("we will use n = 40");
- numbers inside quoted plans of future work or routine prompts.

The construct and rule-source docs exclude several hundred tokens each, almost all IDs and page references. The
excluded counts are in the comments of each group module.

### Statuses

| reproduced | meaning |
|---|---|
| **yes** | regenerated, replayed or re-derived offline from committed inputs; equal to the stated value, as a string |
| **no** | reproduced, and **different** from the stated value. The group records the reproduced value and a one-line cause (runner status `KNOWN`); if the reproduced value ever changes, the runner reports `FAIL` instead. |
| **needs-LLM** | needs a live model call that is not in a committed cassette |
| **needs-Neo4j** | needs a Neo4j run with no interpreter equivalent and no committed raw rows |
| **needs-external** | needs an input outside the repository: the sealed blind manifests (`daedalus-sealed/`), `../daedalus-e1-outcomes`, or GitHub state at the time |
| **not-checkable** | no committed output, log or input lies behind the number (e.g. a discarded run, a memory observation, an estimate) |

What "yes" means also depends on the basis, which each group records:

- **regenerated:** the original producing script was re-run. 2,062 of the 4,587 "yes" rows (replayed: 723; re-derived: 1,802).
- **replayed:** rebuilt from committed cassettes or raw rows.
- **re-derived:** recomputed by the group from committed result files, when the producer needs Neo4j, a model or an
  external input.

## 3. Problems with the replication package itself (PR #117)

These are not doc mismatches, but a reviewer will hit them.

1. **`replication/smoke.sh` exits 1 at the v1.3 head.** It no longer reproduces two of its outputs:
   - **ISE measure:** 11 of 22 files DIFF (`measure.json`, `measure.md`, 9 specs), after ISE commit `08c6cd8c`
     ("structure over vocabulary").
   - **Cheap proxies:** 17 of 55 files DIFF (`rows.csv`, `scores.json`, 15 clean-twin `flags/*.json`). The committed
     top-level `results/v1.3-cheap-semantics/` equals `cheapfix-before`. The cheap-fix options now default on, so a
     default `cheap-semantics-eval.ts` run equals `cheapfix-after`.

   `known-divergences.json` covers neither. Its claims are recorded here as mismatches 29 and 30 of §4 (audit doc lines
   167 and 169). The step needs `--before` or a new expected baseline. Under load the run took about 11 minutes, not
   4–5. **Not fixed here.**
2. **One jest test depends on the environment.** `replay-no-binary.test.ts` fails 2 tests (`CASSETTE_MISS`) when jest
   inherits a Claude Code session's environment, even with the API keys removed. It passes under
   `env -i PATH HOME TMPDIR`, so some environment variable leaks into the cassette key. Group `b-jv2-jest` runs jest
   under `env -i`.
3. **The ISO-04 test in `llm-options.test.ts` needs a git work tree** and fails in a `git archive` export. The test
   groups therefore run jest in the repository; they write nothing into it.
4. **`experiments/loop-pilot/plan.json` fails `--check-prereg` with `PLAN_INVALID`.** The reference docs' "12/12
   plans" holds for the 12 plans present at the run commits. Over all plans at HEAD the result is 12/13.

## 7. Other observations

- **The impact CSV has no generator.** `construct-decisions-impact.csv` has no committed generator. The 129 effect
  figures of `construct-decisions.md` are therefore checked against the CSV for consistency, not regenerated
  independently. The CSV's reference is redefined per option, so its figures do not equal `construct-rescore.ts`.
  For example, Q1 A layered is 8/8 in the CSV and 11/11 in `construct-switches.md`.
- **Some construct figures come from stand-ins.** Q13 C, Q16 B and the three-file cycle come from the offline template
  stand-ins in `construct-simulate.ts`, as the doc itself says.
- **The fieldstate doc counts 13 fixtures.** That is the pinned list at `037e8c9e`. HEAD pins 17 (4 `ap-hosts`
  projects were added later). The group recounts on the 13.
- **Judge v2 stored entries.** "123 stored entries" is session 1's attempts plus hits in the ledger (117 + 6). Only
  117 cassette files date from session 1. Counting by `recordedAt`, "41 of 63" would be 46.
- **"Changed by addition only" is not quite true.** `judge-catch-frozen.md` says the catalogue changed only by
  addition. Its §1 heading was also edited, from "(5 operators, 5 twins)" to "(6 …)". The counts of added rows match.
- **"~230 items" depends on how items are counted.** It holds per cassette store (228 store/prompt pairs). Counted by
  prompt hash it is 190, because 19 prompts recur in both round 2 and CHECK v2.1.
- **"all 14 DDD overlays carry `// VIOLATION`" is 14/14 only if `/** VIOLATION` counts** (overlay v06). Strictly
  matching `//` gives 13/14.
- **"53 of the 60" in `adr-v13-02-draft.md:13` invites misreading.** 60 is the author-literal blocking FP total over
  all five styles; layered alone has 55. It is registered as yes under the all-styles reading.
- **Timings were not compared against re-run values.** They were checked against the committed records: under the
  parallel load of this run, the interpreter CLI took 7m33s against the stated 2m49.9s.
- **Repository history matters.** This clone was shallow, and `--unshallow` was needed for the steps that read history
  (the apg2 ablation at `72fa9203`, the cheap2 co-change counts, the commit counts).
