> **Date**: 2026-10-07 · **Scope**: every question in `v1.2E-u1-spec-compiler-functional-design-plan.md` (Q1–Q24) and `v1.2E-u2-extractor-graph-functional-design-plan.md` (Q1–Q17).
> **Method**: three independent reviewers (U1 Q1–12, U1 Q13–24, U2 Q1–17). Each was told to attack option A, argue for the strongest alternative, and check claims against the code, the corpus clones and a local Neo4j 5.26 (EXPLAIN only). Nothing was edited.
> **Lenses**: correctness; thesis validity (construct validity, researcher degrees of freedom, amending an acceptance criterion instead of meeting it, attribution of golden changes); cost on a 25–30 day schedule; coupling between units.
> **Status**: advisory. The question files are unanswered. This review only informs your answers.

## 3. Cross-cutting issues

### A. Pre-register an "observation vs fix" rule before any FR-18 re-baseline

This is the biggest thesis issue. The plans apply "no calibration change" uniformly, even to defects in the construct itself (Q20–22). Proposed rule for `business-rules.md`, cited in Ch7:

> Fix internal spec/template inconsistencies and misapplied style rules; never tune thresholds or verdict cut-offs to data; functions that cannot fire are fixed or excluded and declared; the five fixtures are the development set, the corpus is held out. Every fix is one commit with one `CHANGES.md` line, dated before the first corpus run.

Under this rule, U1 Q21 and Q22 switch to B, and the correct-reference warning → pass flip rests on spec corrections rather than on FF-P01's vacuous pass. Section 6.2's snapshot predictions must then be redone.

### B. Requirements amended instead of met

The thesis claims "requirement met" for each FR. Prefer meeting the requirement:
- **FR-19** (U1 Q3): meet it, by switching to B.
- **FR-20** (U1 Q2): clarify the wording, don't weaken it; fix FR-08's "compiler defaults" in the same change.
- **FR-20 "100 % executed"** (U1 Q6): report the denominator.
- **FR-29** (U1 Q14): amend only where the operational definition requires it, with the definition as the justification.

### C. Researcher degrees of freedom to freeze before running

Freeze each of these, with its threats-to-validity entry, before the first run:
- the `pattern` grammar (U1 Q1)
- the `layered` applicability table (U1 Q6)
- the cycle bound of 10 (U1 Q15)
- the tag definitions (U1 Q14)
- the self-spec deviations from preset defaults (U1 Q4)

### D. U1 needs a new Q25: dependency templates follow RE_EXPORTS

This is handed over from U2 Q6A.
- `-[i:IMPORTS|RE_EXPORTS]->` in `dependency-direction`, `no-layer-skip`, `no-domain-outward-dep`; `[:IMPORTS|RE_EXPORTS*2..10]` + `DISTINCT` in the cycle query.
- Return `type(i) AS relType` and `coalesce(i.isTypeOnly,false)`.
- Message verb via `CASE type(i) WHEN 'IMPORTS' THEN 'imports' ELSE 're-exports' END`, so IMPORTS rows stay byte-identical.
- Coupling metrics stay IMPORTS-only.
- Attributed `FR-34 (FD U2 Q6)` in the U1 query commit.
- EXPLAIN accepts the union before U2 merges.

### E. One decision answered in two plans

U1 Q19 = U2 Q16 (orphans), and U1 Q18 ↔ U2 Q5/Q6 (columns, `isTypeOnly`, `relType`). Answer each once, give it one owner, and use identical text.

### F. Cycle performance and timeout are on the critical path

Exposure:
- Both cycle queries are unbounded: the template and `universal-metrics.ts:13`.
- U2 adds about 1,159 ghostfolio edges.
- RE_EXPORTS widens traversal further.
- The 30 s default (U2 Q12) combined with FR-36 rejection means data loss on large projects.

Recommendation:
- Bound both queries with the same literal.
- Gate latency on ghostfolio in Build and Test.
- Pre-agree in-memory SCC (Tarjan on `APGResult`) as the fallback. It is deterministic and needs no timeout.
- U3's universal metrics use the same cycle bound, orphan rule and barrel filter as U1. Today `getNum` turns any failure into 0.

### G. Corpus hygiene before any baseline

1. Version the corpus specs (U1 Q8).
2. dev-nest has no `node_modules`, so all 166 bare imports fall into "cannot resolve" and type-based edges degrade. Its re-export figures are dominated by generated Prisma code. Install its dependencies or exclude generated code, and record the choice in `Docs/corpus.md`.

### H. U4 obligations accumulate

U4's row should gather:
- rubrics in every YAML that declares FF-N01/N02, including `layered`;
- renaming `srp-semantic` / `layering-intent` together with the rubric;
- the ADR violation type (from `source === 'adr'`);
- no score assertions before U3's FR-32;
- the existing D-U0-8 and D-U0-17 items.

### I. One bundled C10 (U0) patch before U2 code generation

Contents: `externalOutOfRootAlias` + `workspace` flag (Q1), the reworded `unresolved` comment (Q2), `droppedNoFileNode` (Q3), `ReExportEdgeProperties.isTypeOnly` (Q5). `report.schema.json` (U3) absorbs the new counters.

### J. What FLOWS_TO can claim (SO2 / FR-21)

The "bounded set of data-flow edges" wording holds. On the corpus, FLOWS_TO will be close to empty, so the thesis should present it as fixture- and mutation-validated.
