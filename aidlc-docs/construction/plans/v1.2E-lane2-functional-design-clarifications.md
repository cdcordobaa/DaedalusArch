## 2. Requirement amendments and clarifications

### 2.1 FR-19: met through an explicit kind, not reworded (U1 Q3 B; ADR-015 item 11)

- FR-19's acceptance ("binds all three parameters") is met by declaring `kind: infrastructure` on the self-spec layer `core-modules` (`specs/daedalus-arch.yaml`). The requirement text is **not** amended.
- Precedence stays as AD-4 fixes it: explicit `kind` → exact name → position. A unit test covers position inference (U1 BR-U1-12, BR-U1-16).
- This is a frozen self-spec deviation (ADR-015 item 2) and a threats-to-validity entry.

### 2.2 FR-29: operational tag definitions (U1 Q14 E; ADR-015 item 9)

- Frozen definitions, verbatim from ADR-015 item 9:
  - **structural**: a single typed edge checked against the layer model, with no name heuristic;
  - **topological**: path, degree, connectivity or ratio;
  - **pattern-proxy**: name, role or count heuristic.
- Reading notes R1–R3 are an explicit extension, frozen with the table (U1 BR-U1-27):
  - R1: a *path* runs over typed dependency edges;
  - R2: a *degree* is a count of IMPORTS edges, and a *count heuristic* is a count of members, injections or declarations;
  - R3: tie-break pattern-proxy → structural → topological, used only by `dependency-inversion`.
- **FR-29 amendment**: only `no-layer-skip` changes, from topological to **structural**. Totals: structural 3, topological 8, pattern-proxy 13 (U1 §4.1). `CypherTemplate.tag` becomes required.

### 2.3 FR-20: the visible denominator (U1 Q6 A; ADR-015 item 11)

- Each compiled spec reports these counts:
  - declared = `fitnessFunctions.length`;
  - compiled = `totalCompiled`;
  - disabled = `disabledFunctions`, with reasons (style or kind);
  - executed = the functions with a result and no `EVAL_001`, reported by U3.
- FR-20's "100 % executed" is stated against **compiled**, with declared and disabled shown next to it. The requirement is met, not reworded (U1 BR-U1-19).
- `presets/layered.yaml` gives declared 26, compiled 17 and disabled 9: 7 by style (FF-S04, FF-P02, FF-P03, FF-P04, FF-P05, FF-C01, FF-CV04) and 2 by kind (FF-CV01, FF-CV02).
- Functions that cannot fire are excluded from the denominator and declared (ADR-016 b).
- U3 routes compiler warnings for disabled functions into reports (ADR-016 c).

### 2.4 FR-08 / FR-20 wording clarifications (U1 Q2 A)

- **FR-08**: the registry carries no FR-07 defaults. A spec that declares FF-P01 without `forbidden_imports` fails with `BR-SPEC-10 FF-P01: forbiddenImports`, whether or not it sets `style:`. That is FR-08's negative acceptance, which holds literally only while there are no template defaults (U1 BR-U1-08, BR-U1-09).
- A minimal `style: layered` spec that declares no function is fatally invalid. Its error list is in U1 `business-rules.md` §6.
- **FR-20 amendment**: replace "the registry entry and the preset carry its own forbidden imports for the business layer" with "**the preset** (`presets/layered.yaml`) carries the business-layer forbidden imports; the registry entry `LAYERED_TEMPLATE` carries no FR-07 values".
- The values equal the FF-P01 `forbidden_imports` of `presets/clean-architecture.yaml`: `@nestjs/*`, `typeorm`, `express`, `prisma`, `@prisma/*`, `sequelize`. Built-ins would be written bare (ADR-016 d).
- `threshold` may still come from a registry entry (e.g. FF-C03 0.8). This asymmetry is stated.
