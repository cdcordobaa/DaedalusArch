## 2. Current behaviour that the design must change (summary of scout evidence)

1. **FR-07 fields are dropped by the parser.** `parseLayerB` (`src/spec-parser/layer-parsers.ts:65-82`) copies only the base keys; the schema lets the six keys through untyped (`spec-schema.ts:69`, `additionalProperties: true`); `buildParams` reads snake_case keys through a cast and truthiness checks (`fitness-compiler.ts:299-305`), so a value of `0` would also be dropped.
2. **No template defaults exist.** Registry built-ins for FF-P01, FF-SO01..03, FF-CV02..04 carry no parameters (`template-registry.ts:34-63`); only `presets/*.yaml` do. NestJS reuses `CLEAN_ARCH_FUNCTIONS` (`:134`).
3. **`pattern` values are globs, templates use Java regex.** `"*Service"`, `"*Repository|*Repo"` (`specs/clean-arch.yaml:214,222`, both presets, self-spec `:217-231`, all five corpus specs) against `=~` (`cypher-templates.ts:285,295,306`). Verified on the container: `"FooService" =~ "*Service"` → `Invalid Regex: Dangling meta character '*'`. Existing `globToRegex` (`glob-to-regex.ts:32`) escapes `|`: `InMemoryTaskRepository =~ "^[^/]*Repository\|[^/]*Repo$"` is false.
4. **Layer binding is by literal name** (`fitness-compiler.ts:267-273`); the layer schema rejects `kind:` (`spec-schema.ts:30`, closed). The AD-4 precedence (explicit, name, position; `component-methods.md:812-816`) applied to the self-spec (`domain`, `core-modules`, `application`; `daedalus-arch.yaml:31-63`) yields **no infrastructure layer**, so FR-19's acceptance fails without a further decision. Layer order is **bottom-up**: index 0 is the innermost layer (`fitness-compiler.ts:276-277`); `dependency-direction` flags `srcIdx < tgtIdx` (`cypher-templates.ts:38`) and `no-layer-skip` allows only `layer[i+1]>layer[i]` (`fitness-compiler.ts:286-291`).
5. **FR-22 spec side is closed today.** Dimension enum lacks `integrity` (`spec-schema.ts:44`); `full_mode_weights` requires `intent` and is closed (`:88-101`); `parseLayerC` hard-codes `integrity: 0` (`layer-parsers.ts:131,150`). All four shipped YAMLs redeclare FF-N01 (`solid`/`hybrid`) and FF-N02 (`intent`), so template-only edits have no effect. ADR-derived functions hard-code `dimension: 'intent'` (`fitness-compiler.ts:210`, `:230`).
6. **The scorer does not know `integrity`.** `ALL_DIMENSIONS` and both weight maps lack it, and neuronal results without violations are counted only under `intent` (`score-computer.ts:7,37,61-69,88-102`). U3 owns that file (FR-32).
7. **Templates are unordered and the cycle query is unbounded.** No `ORDER BY` anywhere; `no-cyclic-deps` is `*2..` with `LIMIT 100` and emits every rotation (`cypher-templates.ts:46-55`); `use-case-isolation` returns `collect(dep.name)` in match order (`:130-132`); `inheritance-depth` uses `[:EXTENDS*]` (`:253`); `repository-pattern` uses `UNION` (`:114`, needs a `CALL {}` wrapper for `ORDER BY`).
8. **`exclude_paths` injection assumes a template shape.** `injectExcludePaths` splices `AND NONE(...)` immediately before the last `RETURN` (`exclude-injector.ts:30-45`), so the clause before it must end in a `WHERE` on the violating alias. Any template tail ending in `}` (a `CALL` wrapper) or in `WITH … ORDER BY …` / `WITH … collect(…)` yields invalid Cypher or a predicate in the wrong scope. Users: self-spec FF-P02, FF-C02, FF-C03, FF-C05 (`daedalus-arch.yaml:111,147,155,170`), NestJS FF-S03 (`presets/nestjs.yaml:125`). The golden spec has none, so C16 cannot catch a break.
9. **Vacuous functions once bound.** FF-P01 cannot see package imports until U2/U3 (extractor skips non-relative imports, `edge-extractor.ts:125,252-253`); FF-SO02 cannot match (no Interface→Method `CONTAINS`, `edge-extractor.ts:76-81`); FF-CV01 always passes (`'.*'` defaults, `fitness-compiler.ts:312-314`).
10. **Metric templates return non-violating rows** (`dependency-inversion` `:101-103`, `domain-stability` `:159-161`, `abstraction-ratio` `:224`): pass/fail is right (`symbolic-evaluator.ts:114-119`), violation counts are not.
11. **Corpus specs** (sibling clones `../demo-target`, `../dry-run-test`, `../realworld-test`, `../truthy-demo`, `../ghostfolio-test/apps/api`, each `firewall.spec.yaml`) use `style: nestjs`, FF-N02 `dimension: intent`, `full_mode_weights.intent: 0.04` and glob `pattern` values. `demo-target` has layers `infrastructure`, `application`, `presentation` only (no `domain`).
12. **Other spec defects found by the probe**: presets' `default_exclude_paths` (`presets/clean-architecture.yaml:264`, `presets/nestjs.yaml:330`) is not in `knownKeys` (`spec-parser.ts:75`) and is ignored with `SPEC_001`; self-spec FF-C03 has no `threshold` and no template to inherit one; FF-N01 has no template (`COMPILER_002`); the C9 `validate` action never compiles (`cli.ts:262-299`).

## Question 1
How should the `pattern` value of naming functions (FF-CV02 `naming-services`, FF-CV03 `naming-repos`, FF-CV04 `naming-controllers`) be interpreted?

Context: every shipped value is a glob (`"*Service"`, `"*Repository|*Repo"`, `"*Controller|*Handler"`, `"*Repository|*Repo|*Store"`; `specs/clean-arch.yaml:214,222`, `presets/*.yaml`, `specs/daedalus-arch.yaml:217-231`, and the five corpus specs). The templates apply it with Java-regex `=~` (`cypher-templates.ts:285,295,306`). Verified on the container: `"FooService" =~ "*Service"` raises `Dangling meta character '*'`, so binding the raw value (FR-07 alone) leaves FF-CV02 and FF-CV03 failing with a new `EVAL_001`, while the probe would report 0 unbound. Existing `globToRegex` (`glob-to-regex.ts:32`) escapes `|`, which turns FF-CV03 into a false violation on every fixture. FR-13's acceptance ("after FR-07 it lists 0") depends on this choice.

A) (Recommended) Glob with `|` alternation: `buildParams` splits on `|`, runs `globToRegex` per part, joins as `^(?:a|b)$`; the parser validates that the result compiles (error, same path as `exclude_paths` at `spec-validator.ts:224-235`). YAML stays unchanged (in-repo and corpus), matching the authors' intent and "shipped specs keep compiling unchanged".
B) Glob as in A, plus an explicit `regex:` prefix as an escape hatch for raw regex.
C) Treat `pattern` as raw regex and rewrite all values in the four YAMLs (`.*Service` etc.) and in the corpus specs.
D) Add a new key `name_glob`, deprecate `pattern`.
E) Other (please describe after [Answer]: tag below)

[Answer]: A, with the grammar frozen in business-rules before the first run (glob over the class name, `|` alternation); validated on the evaluate path; empty alternatives rejected (ADR-015) item 2

## Question 3
How should the self-spec (`specs/daedalus-arch.yaml`, layers `domain`, `core-modules`, `application`) relate to FR-19's acceptance ("binds all three parameters")?

Context: AD-4 (`v1.2E-application-design.md:35`, `component-methods.md:812-816`) fixes precedence explicit → exact name → position. Under it `domain`→domain, `core-modules`→application (middle position), `application`→application (name): `applicationLayers = [core-modules, application]` and no infrastructure layer, so FF-P03, FF-P05, FF-CV01, FF-CV04 have no `infraLayer`. The spec's own header (`daedalus-arch.yaml:6-29`) describes `core-modules` as peer pipeline modules (spec parser, compiler, scoring engine: core logic), not infrastructure; labelling it `infrastructure` would switch on FF-P03, FF-P05 and FF-CV04 against a layer that is not infrastructure. Editing the self-spec also meets the acceptance by changing the very input it tests, so position inference is never exercised. The requirement text says explicit → position (no name step), which would satisfy the self-spec but break `presets/nestjs.yaml` (order domain, infrastructure, application, presentation: infrastructure would become application). The self-spec is outside C16; its score changes are logged per the Section 3 "Self-spec" rule.
