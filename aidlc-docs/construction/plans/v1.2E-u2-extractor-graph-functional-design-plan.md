**Business rules — import resolution**

## Question 1
An alias import resolves to a file **outside the project root**. ghostfolio `apps/api` has 330 such statements, all to `../../libs/common/src` via `@ghostfolio/common`. FR-09 says Package for imports that "cannot resolve to a project file". `normalizeFilePath` keeps absolute paths for out-of-root files (`id-generator.ts:31-33`), and the resolved file has no File node, so today it would be dropped silently (`edge-extractor.ts:267-268`). As a Package, first-party monorepo code would be counted in `importResolution.external` (C10 comment: "statements mapped to Package nodes"), which inflates the external figure reported under FR-14 and makes `@ghostfolio/common` matchable by FR-11 `forbidden_imports`. Naming for aliases that are not package-shaped follows the Section 5.2 default. How should U2 treat it?

A) (Recommended) Package node named from the specifier (Section 5.2 naming), and a new counter `ImportResolutionStats.externalOutOfRootAlias` (a subset of `external`, so the partition is unchanged) via the bundled C10 patch; the rule is recorded in `Docs/corpus.md` and the report shows the subset next to `external`.
B) Package node, no new counter; a mandatory note in `Docs/corpus.md` and in the thesis wherever `external` is reported for a project with out-of-root aliases.
C) Drop it with a new warning code (`EXTRACTOR_008` "resolves outside project root") and count it as `unresolved`.
D) Add the out-of-root files as File nodes (needs root-relative ids for paths outside the root; changes the file set the metrics see).
E) Other (please describe after [Answer]: tag below)

[Answer]: A (ADR-015 item 13: default)

## Question 2
A bare specifier **looks like a project alias but does not resolve** (for example `@app/x` when the target file is missing). Read literally, FR-09 makes it a Package node. The corpus has 0 such statements today; the risk is invented packages such as `@app/x` that later feed FR-11 `forbidden_imports` matching. Detection must cover both `paths` patterns and `baseUrl`: with `baseUrl: "."`, an unresolved `src/x` would otherwise become Package `src`. Counting it under `unresolved` widens the C10 comment "relative statements with `EXTRACTOR_002`" (`apg.ts:56-57`).

A) (Recommended) Unresolved project import: `EXTRACTOR_002`, counted in `importResolution.unresolved`, no edge. It is detected when the specifier matches a `paths` pattern, or when `baseUrl` is set and the first path segment of the specifier names an existing directory or file under `baseUrl`. The `unresolved` comment changes to "project-intended statements (relative or alias) that resolve to no file" in the bundled C10 patch.
B) As A for `paths` only; `baseUrl` bare specifiers that fail become Package nodes.
C) Package node, as the literal FR-09 text says.
D) Other (please describe after [Answer]: tag below)

[Answer]: A, with a package-existence check first (installed `node_modules/<root>` up the chain or TS `isExternalLibraryImport`); `paths` targets into `node_modules` are Package; truthy-demo `config` and dev-nest alias as fixtures (ADR-015) item 7

## Question 3
**An import resolves to a file that has no File node.** Two cases: (i) an in-root file the extractor excluded (`DEFAULT_EXCLUDE_PATTERNS`, `apg-extractor/types.ts:86-93`: `*.d.ts`, `*.spec.ts`, `*.test.ts`, `dist/`, `build/`) or skipped after a parse failure; (ii) a **relative** import that leaves the project root (`../../libs/x`; Question 1 covers only aliases). Today both are dropped silently (`edge-extractor.ts:267-268`), and FR-09's "cannot resolve to a project file" is ambiguous for them. The statement-level partition `resolvedInternal + external + unresolved` is undefined until this is decided. Counting invariant proposed with every option: each static import or `export … from` statement increments exactly one partition counter; when per-name resolution splits a statement across targets, the statement counts as `resolvedInternal` if any target is a project file, else `external`; `import()`/`require()` are counted per occurrence in `unsupportedDynamic`, outside the partition.

A) (Recommended) No edge; a new warning `EXTRACTOR_008` ("resolves to a file outside the extracted set") and a new counter `ImportResolutionStats.droppedNoFileNode` in the bundled C10 patch, part of the partition. Keeps `unresolved` meaning resolution failure.
B) No edge; `EXTRACTOR_008`, counted as `unresolved` (no C10 counter).
C) Package node named from the specifier (wrong for project code; listed for completeness).
D) Other (please describe after [Answer]: tag below)

[Answer]: A (ADR-015 item 13: default)

**Business rules — barrels and re-exports (FR-34)**

## Question 4
**What does a RE_EXPORTS edge point at?** `component-methods.md:69` and `:626` say "barrel File -> declaring File". A re-export of a package (`export … from 'pkg'`) is never seen by FR-11 `domain-purity`, which matches IMPORTS only; see Question 6 and Section 5.4.

B) Expand to the files that finally declare each name (follows nested barrels; `export *` must enumerate the module's exports).
C) Both: A as RE_EXPORTS, and B recorded only in a property (needs a C10 contract patch).
D) Other (please describe after [Answer]: tag below)

**Business rules — FLOWS_TO (FR-21, scope fixed by D8)**

## Question 9
The FLOWS_TO scope is fixed upstream (D8, Section 5.1). The open item is which value types inside that scope produce an edge. Fixed with every option: source = a Class node; sink = its own instance field; value = static type of the right-hand side resolved through `NodeLookup` to an extracted Class or Interface; one hop, intra-class; static fields and self-loops excluded; several occurrences of one pair keep the minimum `(line, field)` with its `via` (the C10 contract has no `fields[]`/`lines[]`). On the golden fixtures the result is one edge in variant-a (`InMemoryTaskRepository → CircularHelper`) and one in variant-c (`→ CircularB`), both infrastructure to infrastructure, with no consumer, under every option.

A) (Recommended) No unwrapping: generic and collection types yield nothing (`new Map<string, Task>()`), and union types are skipped.
B) Unwrap arrays and single-element containers: `T[]`, `Array<T>`, `ReadonlyArray<T>`, `Set<T>`, `Promise<T>` and the value type of `Map<K, T>` yield an edge to `T`; unions still skipped.
C) As A, but a union yields one edge per member that resolves to an extracted Class or Interface.
D) Other (please describe after [Answer]: tag below)

[Answer]: A (ADR-015 item 13: default)

**Data flow — ingestion schema and verification**

## Question 10
**Which indexes does `ensureIndexes` create?** The design (`component-methods.md:719-721`, and `v1.2E-components.md:170` "the Package label index (and the other node-type indexes)") creates `INDEX FOR (n:<T>) ON (n.id)` per node type. But the edge MATCH in `ingestEdges` is on `:APGNode {id}` (`graph-ingester.ts:101-102`), which per-type indexes do not serve; without an `APGNode(id)` index every endpoint lookup is a label scan, which threatens NFR-03 on corpus projects (unmeasured). FR-09 asks for "the `Package` label and its index". Schema statements cannot share a transaction with writes.

### 5.2 Defaults applied in the design unless the author objects (low stakes or measured at zero)

- **Built-ins and scope precedence**: a fixed built-in list pinned in the repo plus the `node:` prefix rule (not `module.isBuiltin`, which differs between Node 22 in CI and Node 24 locally). The package name and scope always come from the specifier classification, never from the resolved path (`@types/x` paths and ancestor `node_modules` under `fixtures/*` would otherwise change the output). When a root is both a built-in and an installed npm package (`punycode`, `events`, `buffer`), the built-in list wins (`scope: "node"`) and `PackageNodeRegistry.getOrCreate` never changes the scope of an existing root; a unit test covers `punycode`.
- **Alias naming (for Question 1 A/B)**: a package-shaped specifier names its root (`@scope/name/...` → `@scope/name`, scope `@scope`; `name/...` → `name`, scope `npm`). A specifier that is not package-shaped (`~/x`, `#internal/x`, baseUrl `src/x`) is named by the matched `paths` key with a trailing `/*` removed (`~`, `#internal`), or by its first segment for `baseUrl`, with scope `npm`; every such name is listed in `Docs/corpus.md` for the project.
- **Merge fixed parts (formerly in Question 4)**: `specifier` = specifier of the statement at `min(line)`; `specifiers` de-duplicated in first-line order; `lines` sorted and de-duplicated; side-effect import = `isTypeOnly: false`, `importedNames: []`.
- **Namespace and side-effect imports of a barrel**: one edge to the module file itself with names `['*']` / `[]`. Default imports resolve through the `default` symbol like named imports.
- **Unresolvable name, or chain leaving the project** (measured 0 in all probes): fall back to the module file when the failure is inside the project; Package target named from the re-export specifier where the chain reaches `node_modules`. `EXTRACTOR_006`/`007` kept for depth and cycles.
- **Emission order within a statement**: when one statement fans out to several per-name targets, its occurrences are emitted in the order of the first name routed to each target (source order of the specifiers). Together with the first-occurrence merge order this makes edge order a function of the source text only.
- **`line`**: `getStartLineNumber()` (excludes leading comments); `import x = require()` (0 in corpus) treated as a static import.
- **Edge and node property writing**: `{...flattenProperties(properties), id}` with reserved keys (`id`, and for nodes `type`, `name`, `filePath`, `layer`, `role`) written last so they always win; properties written for every edge type. `decorators` stay unwritten (see residual findings). Hand-off to U3: `i.line` is a Float in Neo4j (driver default), compare it as a number, do not `toString` it.
- **Universal orphan metric excludes barrels**, aligning it with the template (`cypher-templates.ts:197` vs `universal-metrics.ts:25-28`, a silent divergence today). Hand-off to U3 with the Question 16 change. The fixtures have no barrels, so no C16 change; corpus effect recorded as an observation attributed to FR-09 (orphan alignment).
- **D-U0-8 mechanism**: `DEFAULT_INGESTION_CONFIG` typed `Omit<IngestionConfig,'neo4jPassword'>`; constructor requires `neo4jPassword` (all callers already pass it: `pipeline-factory.ts:66`, tests, `golden.test.ts:84`).
