## 3. Current state the questions rely on (scout, read-only, `v1.2e` @ `7a2db65`)

**Evaluator (C6)**
- A failed query is only an `EVAL_001` warning followed by `continue` (`symbolic-evaluator.ts:25-29`). It leaves no trace in any denominator.
- Ids come from a module-global counter (`:50,65`). No column other than `filePath` and the message is mapped (`:57-75`). No `tag` is set on results (`:37-44`).
- `computePassFail` reads the ratio of the first record only (`:108-128`).

**Scorer (C8)**
- `integrity` is absent from `ALL_DIMENSIONS` (`score-computer.ts:7`) and from both weight maps (`:61-69`, `:94-102`).
- A passing neural result is counted only under `intent` (`:37`).
- A dimension with 0 functions gets AVR 0 and keeps its full weight (`:48`, `:71-74`). That is why the empty `solid` dimension adds 0.10 to every HEAD case.
- `functionCount` is the grand total (`:120`).
- Neuronal-only mode computes per-dimension scores over `semantic` and `intent` only (`score-computer.ts:88-89`). `ahsDeterministic` uses `scoringWeights`, which has no `semantic` or `intent` weight, so it is 0. `ahsCombined` is computed with `fullModeWeights` whenever the mode is not symbolic-only, and the verdict uses it (`scoring-engine.ts:31-37`). It can reach at most .08 (`semantic` .04 + `intent` .04), so neuronal-only scores near zero, not exactly zero. `ahsNeuronal` is never computed.
- Hybrid pairs: in symbolic-only mode the pipeline runs `SymbolicEvaluateCommand` over `symbolicQueries` only (`pipeline-factory.ts:140-141`, `symbolic-evaluate-command.ts:18`), so hybrid pairs never run. The router comment "only symbolic part runs" (`router.ts:101`) does not describe the pipeline. In full mode the router runs the symbolic half first and skips the neural half when it fails (`router.ts:60-85`). After U1 (BR-U1-22) the only hybrid pairs are ADR-derived (`fitness-compiler.ts:102-122`), with dimension `semantic`.
- `warnings: []` is set at `scoring-engine.ts:64`.

**Universal metrics**
- `getNum` turns every failure into 0 and always returns ok (`universal-metrics.ts:31-36,47`), so the fallback at `scoring-engine.ts:41-44` is dead code.
- Two queries return **no row** on legitimate input: `abstractionRatio` has `WHERE total > 0` (no Class or Interface), and `avgInstability` returns `NULL` with no File→File `IMPORTS` edge (`:16-24`). `maxFanOut`/`maxFanIn` return `NULL` on a graph with no File→File edge. All of these read as 0 today. The text formatter prints metric values with `String(…)` (`report-formatter.ts:91`), so a `null` would print as `null`.
- The cycle query is unbounded, has a meaningless `LIMIT 1`, and counts files in cycles (`:13`).
- The orphan query neither types its targets as `:File` nor filters barrels (`:25-28`).

## Question 2
**Violation id encoding, and what may be a discriminator.** (FR-12; U5b `baselineMatchKey = (functionId, filePath, target, discriminator)`; U5b entry condition 3(v))

If a measured value is part of a key, an unrelated edit changes the key. For example, adding import A→B changes B's fan-in, so B's existing violation gets a new key and is counted as a new FP.

A) Encoding and discriminator rule:
   - **Id**: `v-` followed by the first 16 hex characters of the sha256 of `JSON.stringify([functionId, filePath, target ?? "", line ?? "", ...discriminator])`. `line` is `Number(x)`; a value that is not finite counts as absent. Discriminator values are strings, and a list value (the cycle) is the JSON of the list.

A number is written as `String(Number(x))`, the ECMAScript shortest round-trip form (for example `instability=0.6666666666666666`). It is not rounded, so U5b's threshold-crossing test compares the exact value the template compared. A string is written raw, and `null` or a missing column is written `<column>=null`. The byte-stability test covers a report with float evidence, and a unit test round-trips `parseEvidence(formatEvidence(row))`.

E) Other (please describe after [Answer]: tag below)

### 6.2 Defaults applied in the design (low stakes; the author may object)

- **`domain-purity` exact text** (pending E-1):
  ```
  MATCH (src:File)-[i:IMPORTS|RE_EXPORTS]->(p:Package)
  WHERE src.layer = $domainLayer AND ANY(fp IN $forbiddenImports WHERE p.name = fp OR (fp ENDS WITH '/*' AND p.name STARTS WITH left(fp, size(fp) - 1))) /*EXCLUDE:src*/
  RETURN src.filePath AS source, p.name AS target, type(i) AS relType, <verb>, i.line AS line, i.lines AS lines, coalesce(i.isTypeOnly, false) AS isTypeOnly
  ORDER BY source, target, relType
  ```
  - `discriminatorColumns: [relType]`.
  - The message is `Domain file {source} {verb} forbidden package {target}`.
  - Type-only imports count and carry `isTypeOnly` (D3).
- **Pass rule.** Once the three metric templates return violating rows only, a function passes exactly when its violation list is empty. The `violation` and `ratio` branches of `computePassFail` are removed, and a static test asserts that no template returns a `violation` column.
- **Metric filters** (BR-U1-40):
  - `dependency-inversion` and `domain-stability` get `WITH … WHERE violation` before `RETURN`, keeping their columns.

### 6.5 Threats-to-validity notes for `business-rules.md`

- **Correlated checks.** One domain→infrastructure injection fires FF-S01, FF-S04 and FF-P06. U5b counts the seeded instance once, but AHS penalises it two or three times.
- **Merged rows.** Merging identical ids keeps the first row's identity and line; the evidence is the per-column maximum, so `inheritance-depth` reports the deepest excess depth, but only one ancestor's line.
- **SCC fallback.** If the fallback is selected, it has no length bound and reports one violation per component, not one per cycle. When a seeded cycle merges SCCs and changes the smallest member, the baseline key changes; U5b matches SCC violations by member-set overlap. A flip applies to the whole experiment, never per project.
- **Warning cap.** The cap hides individual warnings above 50 per (stage, code). Their totals are kept in `REPORT_001`.
- **Verdict thresholds across modes.** The thresholds were calibrated on symbolic-only spike runs. Full-mode (`ahsCombined`) and neuronal-only (`ahsNeuronal`) verdicts use them unchanged (D-9), which is a construct-validity limitation; SO5 reports AHS values alongside verdicts.
- **Metric empty results.** `abstractionRatio` and `avgInstability` are `null` (undefined) on graphs without classes or file-to-file imports, and the max degrees are 0. These are definitions chosen before the first run, not measurements.
- **Data-flow check under the structural tag.** FF-P06 is `structural` by ADR-015 item 9, but checks a data-flow edge (SO2). U5b reports it as its own row inside the structural tag so the two claims can be read apart.
- **Injection rows without a line.** FF-P06 violations from `CONSTRUCTOR_INJECTS` have no `line`, so location matching for them uses file, target and discriminator only.
- **Evidence and id conventions.** The evidence encoding and the id merge rule are researcher choices, frozen before the first run (BR-U3-FRZ).
- **Hybrid pairs.** In symbolic-only mode a hybrid pair (ADR-derived only, after U1) is skipped by mode; in full mode, a violating symbolic half suppresses the neural half, so the `semantic` AVR then rests on symbolic evidence for that function.
