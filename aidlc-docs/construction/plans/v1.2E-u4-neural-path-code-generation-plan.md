## Unit context

### Purpose
Give the Semantic and Integrity dimensions a real, reproducible instrument: the judge reads the unit's real source, runs through the author's subscription CLI in an isolated, probed child, records every exchange as a content-addressed cassette that replays without the binary, selects units deterministically with stated coverage, aggregates with a stated rule, and emits stable neural ids and visible failures. U4 changes **no golden snapshot** (BR §13): the golden suite is symbolic-only and never builds a provider.

## Standard gates (referenced by steps)

Shell preamble for every Bash call that runs a gate, a golden or container test, or a `cypher-shell` query (from Step 8 on): `set -a; . "$HOME/.daedalus-u4.env"; set +a; unset CI`. `SCRATCH` = the session scratchpad. Never print the lane file or `$NEO4J_PASSWORD`.

- **Gate H (probe halt; Group 1 only)**: passes only when all hold: (H1) a judge call under `CLAUDE_CONFIG_DIR=$HOME/.firewall/judge-claude-config`, the `JUDGE_ENV_ALLOW` environment and a neutral cwd returns exit 0, `is_error` false and a non-empty answer; (H2) the init event shows `apiKeySource` = `none` and no MCP server; (H3) every frozen argv flag of BR-U4-ISO-02 is accepted; (H4) the canary finds no token while its positive control does; (H5) a structured-output field or a parsable `result` exists. H1 or H2 failing → **H-halt** (ADR-017 item 9): stop U4, write the observation in this plan, escalate to the author with the options of the FD plan §9 (Q1 B flags-only with a declared residual, or another route). H3, H4 or H5 failing → **H-escalate** (design conflict). Nothing after Step 6 starts until Gate H passes.
- **Gate T (types)**: `npm run typecheck && npm run typecheck:u0-tests && npx tsc -p tsconfig.u4-tests.json` (the third from Step 10 on).
- **Gate U (unit and integration)**: `npm test` green, zero failures; total = the Step 9 baseline plus the tests U4 has added minus those it has deliberately removed (each removal named in the Done note).
- **Gate L (lint ratchet)**: `npm run lint 2>&1 | grep -cE "^\s+[0-9]+:[0-9]+\s+error"` ≤ the Step 9 baseline `L0_U4`; no touched file gains an error; every file U4 creates has 0 errors.
- **Gate B (test type-error budget)**: `npx tsc -p "$SCRATCH/tsconfig.tests-audit.json" | grep -c "error TS"` ≤ the Step 9 baseline `B0_U4`; no touched file gains an error (U0 Step 3 config, `<REPO>` = worktree path; `TS2688` means the config is wrong).
