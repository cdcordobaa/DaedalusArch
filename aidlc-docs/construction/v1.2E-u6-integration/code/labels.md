# U6 lane Labels (ADR-021)

**Date**: 2026-10-09. **Branch**: `v1.2e-u6-labels`. **Findings closed**: SO3-2, SO4-02, SO3-3, SO4-01, SO5-01, SO3-5, THR-3, THR-6 (`Docs/DiagnosticRuns/so-readiness-audit-2026-10-08.json`), and the producer part of ADR-021 item 6 (registered sizes, trimmed context, stated CI widths). No live LLM call, no Neo4j, no so4-heldout, e7-corpus, e1-grid or labelling run.

## What changed

| Finding | Change |
|---|---|
| SO3-2, SO4-02 (producer) | `scripts/build-label-plan.ts` and `-cli.ts` (with `--self-test`) build the label plan from stored outputs only. P1 items and the missed seeds come from `score-golden --label-items` (new; P1 items now carry the line of the new violation). The missed seeds go through `classifyMissedSeeds`, which writes a mechanical cause to `fn-causes.json` or else makes an MS item. P2 comes from accepted `--corpus-runs`, P3 from accepted E1 cells with `generationStatus = 'ok'`, and P4 from `p4SourceOf` runs of `--e1-runs` and `--fixture-runs`. Source roots are the report's `projectPath` (`--root-map` rewrites it) or the seeded copy `<copies>/<project>/<operator>/k-<k>`. Function descriptions are the template text of the compiled spec, matched by spec sha256. P4 contexts use an empty graph view: the labeller context never uses the APG excerpt, so no project is re-extracted and no database is touched. |
| item 6 (sizes) | `scripts/lib/label-plan.ts` and the new registered `corpus/label-plan-config.json`: agy and `gemini-3.1-pro-high`, 300 calls with a 30-call re-ask reserve, P4 1 per (cell, dimension) up to 46, P2 1 per stratum up to 20, P3 1 per stratum up to 10, P1 + MS planned at no more than 59, context ceiling 6 000 characters, at least 2 weeks at 180 calls a week, seeds 6101 (stratum draw), 6103 (permutation), 6102 (bootstrap). Sampling is two-stage, with p = (m / M) · min(perStratum, N_h) / N_h. When the budget binds, the ceilings drop in the order P3, then P2, then P4. If P1 + MS alone exceed 135 items, the plan is refused (`LABEL_PLAN_OVER_BUDGET`). The summary states the Wilson half-widths at nominal n (P4 n = 46: ±0.139 at p = 0.5) and the weeks of quota. `llm-label --usage` reports the measured input tokens per call from the cassettes. |
| SO3-3 | The producer writes `judge-verdicts.json` with `judgeVerdictsFromRuns`, so every verdict carries `source` and `generatorModel`, and `llm-label --agreement --judge-verdicts` accepts the file. `--judge-runs` still works. |
| SO4-01 | `score-golden --labels` reads the `llm-label` output (`ReconciledLabel[]`, P1 items) through `scripts/lib/label-adapters.ts`. It still reads an itemId → label object, and refuses anything else (`LABELS_SHAPE_INVALID`). Every P1 item of the score must carry a label (`SCORE_LABELS_MISSING`). |
| SO5-01 | `aggregate --labels` reads `ReconciledLabel[]`. P3 labels are keyed by the item's `runId`, which the producer sets, or else by the single accepted E1 record of the project. A label that matches no E1 record, an ambiguous project, or a labels file with no P3 label while E1 reports have symbolic violations, is refused (`AGGREGATE_INPUT_INVALID`) instead of producing zeros. `LabelledViolation[]` input still works. |
| SO4-02 (outputs) | `llm-label --agreement --fn-causes` puts the mechanical causes into `LabellingOutputs`, so `fp_fn_taxonomy.csv` gets its `mechanical` rows. `instances.csv` `fn_root_cause` / `fn_cause_source` are filled for missed seeds: the mechanical cause, else the reconciled MS label (`labeller`). `ReconciledLabel` now carries `functionId` (every kind), `runId` and `seedId`. |
| SO3-5 | New `--cassette-project-id` on the evaluate CLI (`src/cli/{cli,llm-options}.ts`, `JudgeRunSettings.cassette.projectId`, `judge-stage.ts`). `run-experiment` passes `entry.projectId` to every judge run. Reliability subjects are keyed (function, project, unit, request hash). The request hash covers the unit source, so even cassettes recorded without a project id no longer pool units of different projects. |
| THR-3 | The audit view and the allocation list the items in `sha256([seed, 'audit-view', itemId])` order, independent of the strata. `--allocate-audit` writes the allocation to a required `--allocation-out` outside the view directory (`AUDIT_ALLOCATION_EXPOSED`). `--agreement --audit` refuses an audit file that is untracked or differs from `HEAD` (`AUDIT_UNCOMMITTED`; `gitAuditCommitted`, injectable). Added to `Docs/matching-rule.md` §8: the audit is committed before any labelled SO3 / SO4 table. |
| THR-6 | Weighted agreement rows (judge vs panel, panel vs audit) use a percentile bootstrap over items, with 10 000 resamples by default and the plan's bootstrap seed (`weighted-item-bootstrap`). Rows with fewer than 10 pairs report counts only. Run vs run keeps Wilson. |
| agy wiring | PR #21 (`v1.2e-labeller-agy`) is merged. A producer plan names `provider: agy` and the pinned model, `llm-label` takes both as defaults, and a contradicting flag is refused (`LABEL_PROVIDER_CONFLICT`). `llm-label` stops at the plan budget (`LABEL_BUDGET_STOP`). `--estimate` on a `sizing: registered` plan checks items × 2 + reserve. |
