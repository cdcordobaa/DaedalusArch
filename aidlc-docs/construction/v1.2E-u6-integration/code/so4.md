## What changed

| Finding | Change |
|---|---|
| SO4-03 | `scoreDifferential` (`scripts/score-golden.ts`) no longer stops on one bad pair. A pair is listed in `GoldenScore.rejectedPairs` (`{seedId, projectId, operatorId, split, baseKind, golden, code, reason}`) and the rest are scored when: a run is missing; a report file is missing; a run's record status is not `accepted`; acceptance or provenance fails (`SCORE_INPUT_REJECTED`); or the FLOWS_TO evidence is unavailable (`EDGE_EVIDENCE_UNAVAILABLE`). Two cases still refuse the whole score: `SCORE_COLLATERAL_UNKEYED` (an instrument defect), and a case in which every pair is rejected. `loadCase` goes through the new `pairRuns`, so a missing seeded run or report marks that side `unavailable` instead of failing the case. The CLI prints each rejected pair on stderr. `manifestRejections` carries the manifest's rejections. |
| SO4-04 | New `scripts/build-score-case.ts` with `-cli.ts` (`--runs <outDir> --out <case> [--manifest]`, `--self-test` exit 1). It copies `runs/*.run.json` to `reports/` and keeps each report at its recorded `reports/<runId>.json` path. The manifest is the one every seeded record names. It filters nothing, prints one paired or unusable line per row, and writes `case-rows.json`. Convention (ADR-021 item 9): a seeded entry's `seed.baselineReportPath` is `reports/<runIdOf(planId, baselineEntry)>.json` of the same plan. |
| SO4-05 | New pure `scripts/lib/so4-coverage.ts`. Aggregate gains two files. `seed_coverage.csv` gives each seed's stage (scored / pair / mutate), status, reason, golden flag and both styles. `golden_instances.csv` gives the golden N per stage (in case, pair-rejected, not applicable, site invalid, scored, matched, missed) overall, per project, per spec style and per corpus style. The overall row adds the mutate rejections, the registered N (`aggregate-cli --golden-registered 85`), the floor and ceiling (80 and 120, equal to `K_TARGET_MIN` and `K_TARGET_MAX` by test), `floor_met`, `shortfall`, `above_ceiling` and the ADR-019 item 1 statement. `isGoldenRow` (`scripts/lib/manifest.ts`) is now the single BR-U5a-01 predicate behind `countGoldenInstances`. |
| SO4-06 | `precisionF1Intervals` (`scripts/lib/stats.ts`) applies the ADR-020 item 3 unit rule to precision and F1. Each P/R/F1 file gains the trailing `PRF_INTERVAL_COLUMNS`: basis (labelled or strict); precision cell interval (cell bootstrap from 10 cells, else `wilson-cells`, or `clopper-pearson-cells` at the extremes); precision project bootstrap (descriptive below 10 projects); precision "if independent" Wilson on the violations; F1 cell bootstrap (from 10 cells only); F1 project bootstrap. Below n = 10, only counts are given. Each scored instance now carries `fpItems` (P1 item id, function, dimension, tag, template, label), so the cells are formed per (project, operator) and must reproduce the row's counts, or only the basis is written. |
| SO1-C | `strataOf` adds `[split, style-<s>, all]` from the spec's `architecture.style`. The style is read in the same parse as the thresholds (`specInfo`). Instances carry `specStyle` and `corpusStyle` (`corpusStyles`, `scripts/lib/corpus.ts`). Denominator rows carry `specStyle`. `denominators.csv` gains `project_id`, `corpus_style` and `spec_style`, and `prf_by_project.csv` gains `corpus_style` and `spec_style`. |
| Report schema (MarvinRF defect) | In full mode, the schema now requires `ahsNeuronal` **unless** `droppedDimensions` lists both `semantic` and `integrity`, which is the zero-judge-units state the scorer already produced. `ahsCombined` and `neuralResults` are still required, and neuronal-only mode is unchanged. The change is in both `schemas/report.schema.json` and `src/scoring-engine/report-schema.ts`, and the `$comment` is amended. Before the fix, the new test reproduced `REPORT_SCHEMA_INVALID` on an assembled zero-unit report. |
