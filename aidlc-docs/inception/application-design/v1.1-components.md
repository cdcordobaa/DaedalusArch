# v1.1 Component Definitions — Architectonic Firewall

Extends v1.0 components (C1-C10). v1.1 adds 2 new components (C12, C13) and extends 5 existing components (C3, C4, C7, C8, C9).

---

## New Components

### C12: Baseline Manager (`src/baseline/`)

**Bounded Context**: Violation baseline lifecycle — create, load, compare, persist

**Responsibilities**:
- Create baseline snapshot from evaluation results (serialize violations with stable keys)
- Load existing baseline from JSON file
- Compare current violations against baseline: classify each as "baseline" or "new"
- Generate stable violation keys (rule ID + file path + violation signature hash) for reliable matching
- Persist baseline to `baseline_violations.json`
- Support baseline evolution (add new violations to baseline, remove fixed ones)

**Input**: `BaselineInput` (evaluationReport.violations[], baselineFilePath?)
**Output**: `BaselineResult` (baselineViolations[], newViolations[], removedFromBaseline[], baselineFilePath)

**Dependencies**: C8 (Scoring Engine output — violation list)
**External**: Filesystem (JSON read/write)

---

### C13: Report Generator (`src/report/`)

**Bounded Context**: HTML report generation, data embedding, template rendering

**Responsibilities**:
- Transform evaluation JSON into a self-contained HTML dashboard
- Embed evaluation data as inline JSON in the HTML file
- Include CDN references for Tailwind CSS, Cytoscape.js, dagre layout plugin
- Generate Cytoscape.js graph data from APG component/dependency information
- Map violations to actionable format (What/Where/Why/Fix)
- Render dashboard sections: header, AHS gauge, architecture graph, fitness cards, violations table, baseline split, summary stats
- Support baseline data overlay (baseline vs new visual split)
- Output a single HTML file that opens directly in browser

**Input**: `ReportInput` (evaluationReport, parsedSpec, apgResult, baselineResult?, projectName, specFilePath)
**Output**: `ReportOutput` (htmlContent: string, outputPath: string)

**Dependencies**: C8 (evaluation report), C3 (parsed spec for layer info), C1 (APG result for graph data), C12 (baseline result, optional)
**External**: Filesystem (HTML write), HTML template files

## Extended Components

### C3: Spec Parser — v1.1 Extensions

**New Responsibilities**:
- Load preset templates from `presets/` directory by style name
- Merge preset template with project-specific overrides (project spec wins on conflict)
- Parse `exclude_paths` array per fitness function (glob patterns)
- Parse `enabled` field per fitness function (boolean, default true)
- Parse `reason` field for disabled functions
- Validate preset existence when `style:` is specified
- New public method: `loadPreset(styleName: string): ParsedSpec`
- New public method: `mergeSpecs(preset: ParsedSpec, overrides: Partial<ParsedSpec>): ParsedSpec`

**New Input Fields**:
```typescript
interface FitnessFunctionSpec {
  // ... existing fields ...
  exclude_paths?: string[]    // NEW: glob patterns to exclude
  enabled?: boolean           // NEW: default true
  reason?: string             // NEW: reason for disabling
}
```

**Preset Template Format**:
```yaml
# presets/clean-architecture.yaml
style: clean-architecture
layers:
  - name: domain
    directories: ["src/domain", "src/core"]
  - name: application
    directories: ["src/application", "src/use-cases"]
  - name: infrastructure
    directories: ["src/infrastructure", "src/infra"]
fitness_functions:
  - id: FF-S01
    name: dependency-direction
    # ... canonical rules with default thresholds
default_exclude_paths:
  - "node_modules/**"
  - "dist/**"
  - "**/*.spec.ts"
  - "**/*.test.ts"
```

### C4: Fitness Compiler — v1.1 Extensions

**New Responsibilities**:
- Skip fitness functions where `enabled: false`
- Inject `WHERE NOT` clauses into Cypher templates for `exclude_paths`
- Convert glob patterns to regex for Cypher `=~` matching
- Track disabled functions in compilation output for reporting

**New Methods**:
- `injectExcludePaths(cypherTemplate: string, excludePaths: string[]): string`
- `globToRegex(globPattern: string): string`

**Modified Output**:
```typescript
interface CompiledFunctions {
  // ... existing fields ...
  disabledFunctions: DisabledFunction[]  // NEW: skipped functions with reasons
}
```

### C7: LLM Critic — v1.1 Extensions (GeminiProvider)

**New Responsibilities**:
- Implement `GeminiProvider` using Google AI SDK (`@google/generative-ai`)
- Support model configuration via spec or environment variable
- Graceful fallback when no API key configured (return symbolic-only mode signal)

**New Class**:
```typescript
class GeminiProvider implements LLMProvider {
  constructor(config: { apiKey: string; model?: string })
  evaluate(prompt: string, options: LLMOptions): Promise<DomainResult<LLMResponse>>
  getModelName(): string
}
```

**Configuration Priority**: `GEMINI_MODEL` env var > spec `llm_config.model` > default `gemini-2.0-flash`

**Fallback**: When `GEMINI_API_KEY` is not set, `LLMProviderFactory.create()` returns a `NullLLMProvider` that signals symbolic-only mode without error.

### C8: Scoring Engine — v1.1 Extensions

**New Responsibilities**:
- Generate actionable violation messages (What/Where/Why/Fix format)
- Include baseline status in violation output (baseline vs new)
- Extended report JSON schema with actionable fields
- Support baseline comparison in report generation

**New/Modified Types**:
```typescript
interface ActionableViolation extends Violation {
  what: string       // "[severity] FF-ID — rule name"
  where: string      // "file/path.ts:lineNumber"
  why: string        // Human-readable explanation
  fix: string        // Suggested action
  baselineStatus: 'baseline' | 'new' | 'none'  // none = no baseline configured
}
```

**Modified Output**: `EvaluationReport` now includes `actionableViolations: ActionableViolation[]` alongside raw violations for backward compatibility.

---

### C9: CLI — v1.1 Extensions

**New Commands**:

```
firewall validate --spec <path> [--project <path>]
  → Validates spec YAML: layer dirs exist, IDs unique, templates exist, thresholds valid, globs valid
  → Exit 0 = valid, Exit 1 = validation errors

firewall report --spec <path> --project <path> [-o <output.html>] [--baseline <path>]
  → Runs evaluation + generates self-contained HTML dashboard
  → Default output: firewall-report.html in current directory

firewall baseline --spec <path> --project <path> [-o <baseline.json>]
  → Runs evaluation + creates baseline snapshot from all current violations
  → Default output: baseline_violations.json in current directory
```

**Modified Commands**:
```
firewall evaluate --spec <path> --project <path> [--baseline <path>] [existing flags...]
  → NEW: --baseline flag to compare against existing baseline
  → Baseline violations marked as informational, only new violations affect exit code
```

## Non-Code Component

### Claude Code Skill (`.claude/commands/firewall-init.md`)

**Not a code component** — a structured prompt that orchestrates the spec generation flow using Claude Code's native capabilities.

**Responsibilities**:
- Read project structure (package.json, tsconfig, directory tree)
- Run APG extraction via `firewall evaluate` or direct ts-morph invocation
- Execute mining Cypher queries against Neo4j to extract structural signals
- Classify architecture style from signals
- Select preset template
- Map project directories to architectural layers
- Generate `firewall.spec.yaml` by merging preset + project-specific mappings
- Run `firewall validate` on generated spec
- Run first evaluation
- Create baseline via `firewall baseline`
- Optionally generate HTML report via `firewall report`

**Mining Queries** (embedded in skill, not coded):
1. Directory structure → layer naming signals
2. Dependency matrix → layer-to-layer import ratios
3. Naming patterns → I*Repository, *UseCase, *Controller counts
4. Constructor injection ratio ��� % injecting interfaces
5. Anomalies ��� cases breaking the majority pattern
