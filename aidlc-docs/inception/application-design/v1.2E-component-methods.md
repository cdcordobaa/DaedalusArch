## Conventions

- Requirement IDs are abbreviated: `FR-nn` means `FR-v1.2E-nn`, `NFR-nn` means `NFR-v1.2E-nn`. `D-n` refers to the binding design decisions (application-design plan Q1..Q10).
- **Status**: `EXISTING` = unchanged, cited at HEAD for context; `CHANGED` = exists at HEAD (file:line cited), with what changes; `NEW` = intended path.
- All `file:line` references are to commit `7cd15b4`.
- `DomainResult<T>` is the existing result type (`src/shared/errors/domain-result.ts:13-15`). Every fallible method returns it; nothing throws across a component boundary.
- Component numbers follow the existing design: C1 APG Extractor, C2 Neo4j Ingestion, C3 Spec Parser, C4 Fitness Compiler, C5 Neuro-Symbolic Router, C6 Evaluation Engine, C7 LLM Critic, C8 Scoring Engine, C9 CLI, C10 Shared Domain, C11 Firewall Context, C12 Baseline Manager, C13 Report Generator. New: **C14 Claude CLI Provider**, **C15 Experiment Toolkit**, **C16 Golden Regression Suite**. No further component is added: the cassette provider, unit selector and source assembler sit inside C7; the JSON report builder and report-schema validator sit inside C8; the process runner port and its Node implementation sit inside C10.
- Unit ownership (execution plan, shared-file table in `v1.2E-component-dependency.md` section 6): U0 owns everything in C10 (including `src/shared/interfaces/*`, `src/shared/process/*`, `src/shared/errors/scrub.ts` and the C11 slot) and the LLM port; U1 owns C3/C4; U2 owns C1/C2; U3 owns C6/C8/C13 and the C9 report and batch changes; U4 owns C5/C7/C14 and the C9 provider-selection hunks; U5 owns C15; C16 is built in U0.
- **Single source.** This file is the authority for every NEW or CHANGED name, path and signature in v1.2E. `v1.2E-components.md`, `v1.2E-services.md` and `v1.2E-component-dependency.md` cite these names and do not redeclare the types.
