**Notation**
- Requirement IDs are abbreviated: `FR-07` means `FR-v1.2E-07`, `NFR-05` means `NFR-v1.2E-05`.
- **EXISTING** = unchanged at HEAD, cited by `file:line`. **CHANGED** = exists at HEAD (cited) and is modified as stated. **NEW** = does not exist; intended path given.
- Line numbers refer to commit `7cd15b4`.
- **Single source for signatures.** Every NEW or CHANGED type, function, file path and signature is defined once, in `v1.2E-component-methods.md`. This file names them and says which component owns them; it does not restate their shapes. Where a name appears here, it is spelled exactly as in the methods file.

No more were needed. The process runner that wraps the `claude` binary is a C10 port with a C10 implementation (`src/shared/process/`), used by C14 and by C15, so it does not need its own number.

```
+----------------------+      +----------------------+
| C10 Shared Types  U0 |      | C16 Golden Suite  U0 |
+----------------------+      +----------------------+
```

**Text alternative.** The evaluation pipeline has two inputs. On the specification side, C3 Spec Parser (owned by U1) feeds C4 Fitness Compiler (U1). On the code side, C1 APG Extractor (U2) feeds C2 Neo4j Ingestion (U2). Both paths join at C5 Neuro-Symbolic Router (U4). The router sends symbolic queries to C6 Evaluation Engine (U3) and neuronal instructions to C7 LLM Critic (U4). C7 calls models through the LLM port, and its new Claude implementation is C14 Claude CLI Provider (U4). Results from both C6 and C7 reach C8 Scoring Engine (U3), which scores them and, in the last pipeline command, assembles the complete JSON report. C13 Report Generator (U3) renders that report as HTML. C9 CLI (U3 for the report and batch, U4 for provider selection) writes the report out. C15 Experiment Toolkit (U5) runs C9 as a subprocess (the arrow from C15 to C9) and, in process, reuses C3, C7 and C8; those three reuse imports are written inside the C15 box instead of being drawn as arrows, and they are listed with their functions in `v1.2E-component-dependency.md` section 3.1. C15 does not use C14. Two components sit outside the flow. C10 Shared Domain (U0) holds every contract change, the process runner and the scrubber, and every component depends on it. C16 Golden Regression Suite (U0) runs C1-C9 end to end against Neo4j through `createPipeline` and snapshots the assembled report.

## 7. Points not grounded in the code at `7cd15b4` (to settle in Functional Design)

1. **Claude CLI envelope (C14, U4).** The flags are verified against the installed binary (`claude --help`, Claude Code 2.1.290): `--effort <level>` accepts `low, medium, high, xhigh, max`; `--tools ""` disables all tools; `--no-session-persistence` works only with `--print`; `--output-format json` gives a single JSON result; `--bare` skips keychain reads and is therefore not used. Only the field names of the JSON envelope remain open: `parseClaudeCliEnvelope` must be fixed against a recorded real envelope.
2. **Re-export edges (C10, U0).** Decided here: `RE_EXPORTS` is a ninth `EdgeType`. NFR-04 lists the ADR-005 amendment for node types only, so the ADR-005 edge list needs the same amendment; this is a documentation item for the Build and Test checklist. Whether orphan checks count RE_EXPORTS is open for Functional Design U1/U3.
3. **`intent` inside the engine (C10/C3, U0-U1).** FR-22 maps `intent` to `semantic` at parse time. This design removes `intent` from the internal `Dimension` union in U0, with mechanical compile fixes at the literal sites, and moves ADR-derived functions (today `intent` at `fitness-compiler.ts:209`, `:228`) to `semantic`.
4. **FR-21 `via` values.** The requirement text says `'constructor-param' | 'new'`, but D8 cuts constructor parameters. The interface therefore uses `'new' | 'field-assignment'`.
5. **FR-28 credential wording.** The requirement row still says "Anthropic SDK with the author's OAuth profile first". D1 supersedes it with the Claude Code headless CLI with file tools, and C15.5 follows D1. The requirement row should be amended.
6. **Gemini model id.** The default `gemini-2.0-flash` appears in four places (`provider-factory.ts:7`, `gemini-provider.ts:6`, `pipeline-factory.ts:82`, `dashboard-data-builder.ts:104`) on `@google/generative-ai` 0.24.1. The pinned, verified id for the judge and the labeller is not chosen here.
7. **Figure library for `aggregate.ts` (C15.8).** No plotting dependency exists in `package.json`. The choice is open.
8. **CLI option names** (`--llm-provider`, `--llm-model`, `--llm-effort`, `--cassette-mode`, `--cassette-dir`) and the `buildChildEnv` allow-list are proposals for Functional Design U4.
