## Design Questions

### Question 1
**Preset loader placement**: The preset system (clean-arch.yaml, nestjs.yaml) needs to be loaded and merged with project-specific overrides. Should this be:

A) Extension of C3 (Spec Parser) — presets are just another spec source, parser already handles YAML
B) New component C11 (Preset Loader) — separate concern from parsing existing specs
C) Part of the skill only — presets are loaded by the Claude Code skill, not by coded components
D) Other (please describe after [Answer]: tag below)

[Answer]: A

### Question 2
**Baseline manager placement**: Baseline snapshot (create, compare, mark violations) is a new capability. Should it be:

A) Extension of C8 (Scoring Engine) — it compares violations which is a scoring concern
B) New component C12 (Baseline Manager) — separate lifecycle from evaluation scoring
C) Extension of C2 (Neo4j Ingestion) — baselines are persisted alongside snapshots
D) Other (please describe after [Answer]: tag below)

[Answer]: B

### Question 3
**Report generator architecture**: The HTML report generator transforms evaluation JSON into a self-contained HTML file. Should it:

A) Extend C8 (Scoring Engine / report-formatter) — it's another output format alongside JSON/CSV/human
B) Be a new component C13 (Report Generator) — HTML generation is sufficiently different from text formatting
C) Other (please describe after [Answer]: tag below)

[Answer]: B

### Question 4
**Mining queries ownership**: The Cypher queries that mine the APG for structural signals (used by the skill for classification) need to live somewhere. Should they:

A) Live in the skill prompt only — the skill constructs and runs them via Claude Code
B) Live in C6 (Evaluation Engine) as a new "mining mode" — reuses the Cypher execution infrastructure
C) New component C14 (APG Miner) — separate read-only analysis concern from evaluation
D) Live in C2 (Neo4j Ingestion) — it already has Cypher access and graph knowledge
E) Other (please describe after [Answer]: tag below)

[Answer]: A
