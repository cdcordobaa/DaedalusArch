## Key architectural insight

The four feature FRs all collide on the **same small set of hot contract files** (`enums.ts`, `apg.ts`, `violation-types.ts`, `spec.ts`, `graph-ingester.ts`, `pipeline/types.ts`). Landing all the additive, default-preserving schema changes **first** in a dedicated foundation unit is what unblocks parallel construction without merge wars — exactly the pattern v1.1 used with its U0 "Shared Extensions" unit before the parallel Track A/B/Gemini worktrees.

## Work Unit Decomposition

### v1.2-U0 — Type & Graph-Contract Foundation (shared seam) · **M**
*Depends on: none.* Non-feature foundation; all changes additive and default-preserving (honors NFR-V1.1-04).
- De-hardcode `NodeType`/`EdgeType` literal arrays in `graph-ingester.ts` (derive from enums)
- Enum policy AD: fixed-set + foreign-construct mapping (FR-10); additive `Component` NodeType + `RENDERS` EdgeType (FR-11)
- Extend `Violation`/`ActionableViolation` with optional `line`, `suppressed`, `suppressionReason` (FR-05)
- Add `source: 'adr'|'template'|'manual'` + `adr_ref` provenance to spec `FitnessFunction` (FR-08)
- Add `PipelineConfig.graphBackend` selector + `SpecParserOptions` provider/`useLLMExtraction` fields (FR-12/FR-08)
- **Gate:** full 421-test suite green, zero behavior change
- *Stages:* Functional Design → Code Generation

### v1.2-U1 — In-Memory Graph Backend (FR-12) · **XL** ⚠️ highest risk
*Depends on: U0.* The platform enabler — `firewall evaluate --symbolic-only` with zero Docker/Neo4j.
- `src/neo4j-ingestion/in-memory-graph-repository.ts` implementing the existing `GraphRepository` port over a typed adjacency-list store
- **JS-traversal path over a Cypher parser**: per-function registry mapping the ~18–20 common structural/coupling/convention fitness functions to hand-written traversals returning the same record shape the Cypher templates `RETURN` (keeps `symbolic-evaluator.ts` + report mapping unchanged)
- Re-implement exclude-path (FR-V1.1-03) and disable (FR-V1.1-04) as JS post-filters
- Branch on `graphBackend` in `pipeline-factory.ts`; **default-flip to in-memory**, Neo4j selected via explicit `--neo4j-uri`
- `EVAL_001`-style "unsupported in in-memory mode" warning for functions outside the supported set
- **Mandatory:** Neo4j-vs-in-memory equivalence test on a fixture (score-parity guard vs calibrated AHS thresholds)
- *Stages:* Functional Design → NFR Requirements → NFR Design → Code Generation

### v1.2-U2 — Language-Agnostic Extractor + React/JSX (FR-10, FR-11) · **L**
*Depends on: U0.* Combined because FR-11 is the first real consumer of the FR-10 plugin seam; both touch the identical 4 extractor files.
- **Part A (FR-10):** `LanguageExtractor` interface (contract = `Promise<DomainResult<APGResult>>`, no ts-morph leakage); refactor `extractAPG` into `TypeScriptExtractor`; keep `extractAPG` as a thin TS-default shim; extractor-registry + language-detection. **Fenced to interface + dispatch + TS reference impl — no second non-TS extractor.**
- **Part B (FR-11):** opt-in `reactMode` (default off); collect `.tsx`/`.jsx`; detect components → `Component` nodes; `JsxElement` → `RENDERS` edges; hook calls → `CALLS`; `'use client'/'use server'` as File metadata; react/next.js preset + 2–3 React fitness templates; hook-rules exceeding structural Cypher routed to neuronal
- *Stages:* Functional Design → Code Generation

### v1.2-U3 — Inline Suppression (FR-05) · **L**
*Depends on: U0.* Modeled on baseline, but inserted **before** scoring so it influences AVR/AHS.
- `node-extractor.ts` captures start line + parses `// firewall-ignore <rule-id>[,...] [reason]`
- `src/suppression/suppression-matcher.ts` partitions kept vs suppressed (baseline-style key)
- Suppression pipeline command before `score-command`; **recompute `SymbolicFunctionResult.passed`** so fully-suppressed functions flip (AVR is per-function pass/fail, not per-violation-count)
- Non-optional "Suppressed" audit section + dashboard badge/filter; GAP-09 suppress-hint in fix output
- `allow_inline_suppression` spec flag (default on) + per-rule `suppressible: false` for Tier-1 rules; define suppress/baseline/disabled precedence
- **Recommendation:** ship file+rule granularity first; line-precise suppression deferred
- *Stages:* Functional Design → Code Generation

### v1.2-U4 — ADR→Fitness-Function LLM Extraction (FR-08) · **L**
*Depends on: U0 (hard-depends on FR-15 Gemini, shipped v1.1).* Replaces the 500-char truncation heuristic.
- `src/spec-parser/adr-extractor.ts`: `LLMProvider` → typed `ConstraintSet` (forbidden-import / layer-rule / naming / required-pattern), reusing `GeminiProvider` + `extractJSON()`
- Mapping layer resolving constraints against `cypher-templates.ts`: matched → programmatic `symbolicRule`; unmatched → enriched `SemanticCriteria` (neuronal)
- **LayerModel validation** of every emitted symbolic constraint (hallucination guard)
- Opt-in `firewall adr --adr <dir> --out firewall.spec.yaml` CLI command + `firewall-init --adr` step
- Graceful fallback to truncation heuristic when provider null/mock; **all LLM calls via VCR cassette-manager** (deterministic CI/demo); idempotent re-extraction
- *Stages:* Functional Design → NFR Requirements → Code Generation

## Recommended Build Sequence

```
U0 (foundation, merge to main)
   └─► U1 ┐
       U2 ├─ parallel worktrees off post-U0 main
       U3 │
       U4 ┘
                 └─► single Build & Test (full suite + equivalence/capability tests)
```

**Rationale:** U0 lands the shared contracts that prevent the four feature worktrees from colliding. U1 (FR-12) sequenced first among features because it is XL, riskiest, and the platform enabler giving React adopters + the demo a zero-Docker path. U2/U3/U4 are self-contained vertical features.

## AI-DLC Workflow for v1.2

Run a **fresh INCEPTION pass** re-running only lightweight planning stages, then a per-unit CONSTRUCTION loop (mirrors v1.1, which did App Design + Units Gen, skipped NFR/Infra at planning level):

1. **Requirements Analysis** — formalize the 5 FRs + their open questions; resolve clarifying questions (FR-05 granularity, FR-08 constraint taxonomy, FR-10 scope boundary, FR-11 RENDERS-vs-CALLS, FR-12 parser-vs-JS + default-flip) **before construction**
2. **User Stories** — light pass, a handful per FR
3. **Workflow Planning** — confirm App Design runs; NFR Requirements only for U1 + U4; parallel worktrees at code-gen
4. **Application Design** — `LanguageExtractor`, `InMemoryGraphRepository` + traversal registry, `adr-extractor` + taxonomy, `suppression-matcher`; ADs for enum policy, graph-backend selection, JS-traversal-vs-parser
5. **Units Generation** — emit the 5 units above
6. **SKIP** Reverse Engineering (greenfield) and Operations (placeholder)
7. **Construction** — U0 first (branch → merge to main), then U1–U4 in parallel worktrees; single Build & Test after all merge

## Cross-Cutting Risks

1. **Enum expansion blast radius** — `NodeType`/`EdgeType` referenced by literal string in ~48 Cypher spots + ingester/annotator/drift/report. U0 must apply additive entries + de-hardcode the ingester array centrally, once.
2. **Score-parity / calibrated thresholds** — both FR-12 (in-memory semantics) and FR-05 (must recompute `passed`, not just drop violations) can silently shift AHS off the empirically calibrated verdict thresholds. Equivalence tests are mandatory.
3. **Backward compatibility (NFR-V1.1-04)** — every change a no-op for v1.0 specs. All new fields additive/optional; all new behaviors opt-in — **except FR-12's deliberate default-flip to in-memory**, which needs a migration note + `--neo4j-uri` opt-in.
4. **Feature-interaction precedence** — inline suppression (pre-scoring), baseline (post-scoring exit-code), disabled functions (compile-time) need a single defined categorization to avoid double-counting. Resolve in Application Design before U3.
5. **LLM determinism (FR-08)** — ADR extraction must be VCR-replayed in CI; opt-in/off the hot path; every constraint validated against LayerModel.
6. **Scope-creep fences** — FR-10 fenced to abstraction + TS reference impl; FR-12 fenced to common-function subset with explicit unsupported-warning path; FR-05 fenced to file+rule granularity.
