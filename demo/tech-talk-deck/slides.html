Building a Graph-Based Architectural Firewall
How we turn source code into a property graph, evaluate 25 fitness functions
via Cypher queries, and compute a deterministic health score for every commit.
Cristian Cordoba · Software Architect
The Problem

Linters see files.
Architecture lives between them.

ESLint, SonarQube, CodeQL — all operate on single files or local scopes. None of them can answer:

  • -- Does my domain layer import from infrastructure?
  • -- Are there circular dependency chains across 4 files?
  • -- Does every repository implement an interface?
  • -- Is the codebase structurally compliant with our spec?

These are graph questions. You need a graph to answer them.

// ESLint can catch this: const x = null; // no-null-assignment // ESLint CANNOT catch this: // domain/Order.ts imports infra/PgClient.ts // which violates dependency-direction rule // and breaks clean architecture layer model // // Because it requires CROSS-FILE analysis // + knowledge of your architectural spec. // That's what Daedalus Arch does.

Stage 1 — The Graph Model

The Architecture Property Graph (APG)

We parse the codebase with ts-morph and build a typed property graph. Every file, class, interface, method, and function becomes a node. Every import, declaration, inheritance, and call becomes an edge.

Stage 2 — The Architectural Spec

Define your architecture in YAML

Layers, roles, fitness functions, weights, thresholds — everything is declarative and version-controlled.

spec_version: "1.0.0" architecture: style: clean-architecture layers: - name: domain directories: [src/domain/**] roles: - entity - value-object - repository-interface - name: application directories: [src/application/**] roles: [use-case, dto] - name: infrastructure directories: [src/infrastructure/**] roles: [repository-impl, controller] scoring: weights: structural: 0.35 coupling: 0.20 pattern: 0.20 solid: 0.15 convention: 0.10 thresholds: pass: 0.80 warning: 0.65 soft_block: 0.50
Presets
Ship with clean-architecture.yaml and nestjs.yaml presets. NestJS uses file_patterns (*.service.ts, *.controller.ts) instead of directory-based layers.
Spec Validation
YAML is validated against a JSON Schema via ajv. Layer directories use picomatch for glob matching. Invalid specs fail fast with descriptive errors.
Extensibility
Teams define custom fitness functions. Each function has: id, dimension, severity, route (symbolic / neuronal / hybrid). Weights are configurable per-team.

// dependency-direction — Cypher template WITH $layerOrder AS layerOrder MATCH (src:File)-[:IMPORTS]->(tgt:File) WHERE src.layer IS NOT NULL AND tgt.layer IS NOT NULL AND src.layer <> tgt.layer WITH src, tgt, apoc.coll.indexOf(layerOrder, src.layer) AS srcIdx, apoc.coll.indexOf(layerOrder, tgt.layer) AS tgtIdx WHERE srcIdx >= 0 AND tgtIdx >= 0 AND srcIdx < tgtIdx RETURN src.filePath AS source, tgt.filePath AS target // Returns rows = violations found. // $layerOrder = ['infrastructure','application','domain']
// no-cyclic-deps MATCH path = (f:File)-[:IMPORTS*2..]->(f) RETURN [n IN nodes(path) | n.filePath] AS cycle LIMIT 100 // domain-purity MATCH (src:File)-[:IMPORTS]->(tgt:File) WHERE src.layer = $domainLayer AND tgt.layer <> $domainLayer RETURN src.filePath AS source, tgt.filePath AS target // repository-pattern MATCH (c:Class) WHERE c.name =~ '.*Repository.*' AND NOT (c)-[:IMPLEMENTS]->(:Interface) RETURN c.filePath AS filePath, c.name AS className
Stage 6 — Scoring

From violations to a single number

Step 1: AVR per dimension
AVRd = violated functions / total functions in dimension d

structural: 2/4 violated → AVR = 0.50
coupling: 1/6 violated → AVR = 0.17
pattern: 3/5 violated → AVR = 0.60
solid: 0/3 violated → AVR = 0.00
convention: 2/6 violated → AVR = 0.33
Step 2: AHS (weighted sum)
AHS = Σ ( wd × (1 − AVRd) )

= 0.35×(1−0.50) + 0.20×(1−0.17)
+ 0.20×(1−0.60) + 0.15×(1−0.00)
+ 0.10×(1−0.33)
= 0.175 + 0.166 + 0.080 + 0.150 + 0.067
= 0.638
Step 3: Verdict
●
PASS — AHS ≥ 0.80
●
WARNING — AHS 0.65 – 0.79
●
SOFT-BLOCK — AHS 0.50 – 0.64
●
HARD-BLOCK — AHS < 0.50
Design decisions
-- Branded value objects: AVRScore, AHSScore via Zod — impossible to pass a raw number where a score is expected.
-- Weights are per-team configurable: a startup can zero-out convention, an enterprise can max structural.
-- Neuronal results multiplied by confidence weight — low-confidence LLM findings penalize less.
The Neuro-Symbolic Router

Symbolic where you can. LLM where you must.

24 functions are pure Cypher (deterministic, <1s). 2 functions use Claude/Gemini for semantic analysis.

Symbolic Route
24
Pure Cypher queries on Neo4j.
Deterministic. Reproducible.
<1s per function.
Rows returned = violations.
Neuronal Route
2
LLM-based semantic analysis.
SRP intent + layering intent.
Confidence-weighted scoring.
Claude or Gemini backend.
// Route decision from spec YAML: fitness_functions: - id: FF-S01 route: symbolic # → Cypher on Neo4j - id: FF-N01 route: neuronal # → Claude/Gemini API - id: FF-N02 route: hybrid # → Cypher + LLM confirm
Why this split?
Structural rules are binary graph properties. "Does file A import file B across a layer boundary?" — that's a graph traversal, not a judgment call.
Semantic rules need understanding. "Does this class have a single responsibility?" requires reading the code and reasoning about intent. Graph structure alone can't answer that.
Confidence gating: neuronal results below a threshold are flagged unstable and down-weighted in the score. Prevents hallucination from tanking AHS.
Stage 3 — Graph Ingestion

Bulk load into Neo4j + layer annotation

APG nodes → Neo4j via UNWIND batch. Layers assigned by glob matching file paths against spec directories.

// Bulk node ingestion (UNWIND) UNWIND $nodes AS n CREATE (f:File { id: n.id, filePath: n.filePath, name: n.name, type: n.type }) // Layer annotation (post-ingestion) MATCH (f:File) WHERE f.filePath =~ $layerPattern SET f.layer = $layerName, f.role = $role
Layer matching strategies
1. Directory-based — src/domain/** via picomatch on relative paths.
2. File-pattern-based — *.service.ts for NestJS-style co-location.
3. Decorator-based — @Controller(), @Injectable() for framework inference.

Engineering Decisions

Tech stack + key trade-offs

Why Neo4j?
Architecture is a graph problem. Cypher lets us express "find all paths from domain to infrastructure" in 3 lines. Variable-length path matching ([:IMPORTS*2..]) makes cycle detection trivial. Alternatives considered: in-memory adjacency list (too manual), SQL (painful path queries), TigerGraph (overkill).
Why ts-morph?
Full TypeScript compiler API access without the complexity. We get: resolved imports (not just string parsing), class hierarchies, decorators, type information. Trade-off: TypeScript-only for now. Future: tree-sitter for multi-language support.
Branded value objects
AVRScore, AHSScore, Confidence, FunctionId — all branded types via Zod. Prevents accidentally passing a raw number where a score is expected. Runtime validation + compile-time safety.
BDD test suite
Jest + jest-cucumber for behavior-driven specs. Every fitness function has a Gherkin scenario. Integration tests hit a real Neo4j container (Docker Compose). No mocks for graph queries.
