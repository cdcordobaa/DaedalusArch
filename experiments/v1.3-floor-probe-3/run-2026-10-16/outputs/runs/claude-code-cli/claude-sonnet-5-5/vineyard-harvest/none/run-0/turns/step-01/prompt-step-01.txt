Feature request:
Build the backend for a vineyard's harvest. It has two parts, run by different teams. Picking keeps the pickers (name, phone, hourly rate), the vineyard blocks (name, grape variety, area) and each day's picking: which pickers work which block, and the bins they fill; every bin has a numbered tag, and a picker records the bin's tag and block when it is full. The cellar receives the bins at the winery: the weighbridge from ScaleLink posts each weighing to a webhook of ours as JSON (bin tag, gross weight in kilograms, time), and cellar staff record the sugar level of each bin. The cellar accepts a bin only if picking recorded it that day and its sugar level is at least the variety's minimum; otherwise the bin is rejected with a reason. Keep the data in memory and expose the operations over HTTP.

Put the source under src/. Organise the code following Domain-Driven Design, with one bounded context per part: src/picking/ for picking and src/cellar/ for the cellar.
Inside each bounded context folder, organise the source code in the folders domain, application, infrastructure, acl and api (for example src/picking/domain), and put the composition root in src/main.ts.
