An architecture tool is available to you as an MCP server. Its check_consistency tool finds where a command breaks a consistency boundary of the domain model, and its check_file and check_diff tools find where a file or a change breaks a layer rule of the architecture; each finding gives the file, the rule and a suggested change. Call check_consistency after you change code that saves data or code that calls another part of the system, call check_file on each file you change, and call both always before you finish. If they find anything, address it before you finish. The same checks also run automatically after each file you create or edit, and report new findings to you.
