# Author-B specs for the external set: mapping rationale (v1.3 K2)

Written blind to #133's specs, rationale, findings and summary (blinding and protocol:
`Docs/DiagnosticRuns/v1.3-spec-author-plan.md`). Inputs per repo: the tree at the pinned SHA in
`results/v1.3-external/selection.json` (branch `v1.3-external-set`), its README, and `presets/<style>.yaml`.
The specs are generated by `generate-specs.py` (this folder) so every glob is in one reviewable place; the fitness
functions, thresholds and weights are the preset's, byte for byte. All 15 pass `firewall validate` at their root.

General choices (applied to every repo):

- Preset layer names and kinds are kept; no layer is added. Where the preset has no composition-root layer
  (clean-architecture, layered, nestjs), bootstrap files (`main.ts`, loaders, config) go to the outermost layer if the
  style puts wiring there (clean-architecture: infrastructure), otherwise stay unmapped.
- Cross-cutting utility folders (`helpers`, `utils`, `lib/logger`, `constants`, `decorators`) used by every layer stay
  unmapped rather than being forced into a ring.
- Tests, mocks and fixtures are excluded; migrations and seeds are kept (they are persistence code).
- Option taken under delegation: the DDD protocol also needs `architecture.ddd` (contexts, aggregates, value objects,
  repositories, event types, application services); the preset says to replace its example declarations, so these
  were authored per repo from the code (classes extending the repo's own `AggregateRoot`/`ValueObject`/event base).
  Globs in the DDD block avoid braces and extglobs (the DDD binder's glob-to-regex does not support them).

## clean-architecture (3 layers: domain, application, infrastructure)

- **pvarentsov-clean.** `src/core/domain/**` and `src/core/common/**` (entities, value objects, port and use-case
  interfaces, shared kernel) -> domain; `src/core/service/**` (use-case implementations) -> application;
  `src/infrastructure/**`, `src/application/**` (here "application" is the HTTP API and DI wiring, i.e. the outer
  ring) and `src/*.ts` -> infrastructure. `test/**` excluded.
- **luizomf-clean-api.** `src/domain/**` -> domain; `src/application/**` (use cases, ports, validation) ->
  application; `src/infrastructure/**`, `src/presentation/**` (controllers, interface-adapter ring), `src/main/**`
  (factories, composition) and `src/common/adapters/**` (bcrypt/JWT/validator adapters implementing application
  ports) -> infrastructure. `src/common/helpers/**` (pure date/number/object helpers) unmapped.
- **dannielhugo-clean.** README: app = enterprise rules (core entities/definitions + features), data = interface
  adapters, frameworks = frameworks and drivers. `src/app/core/**` -> domain; the feature folders under `src/app/`
  and `src/app/app.ts` -> application; `src/data/**`, `src/frameworks/**` -> infrastructure.
  `src/test-environment.ts` unmapped.

## layered (3 layers bottom-up: persistence, business, presentation)

- **bulletproof-nodejs.** `src/models/**` (Mongoose models) -> persistence; `src/services/**`, `src/interfaces/**`,
  `src/subscribers/**`, `src/decorators/**` (event dispatcher used by services) -> business; `src/api/**`,
  `src/jobs/**` (Agenda job entry points) -> presentation. `src/loaders/**`, `src/config/**`, `src/app.ts` unmapped
  (bootstrap; the preset has no composition layer). `tests/**` excluded.
- **w3tec-express-boilerplate.** README table: repositories = DB layer, services = service layer.
  `src/api/repositories/**`, `src/api/models/**` (TypeORM entities), `src/database/**` -> persistence;
  `src/api/services/**`, `src/api/subscribers/**`, `src/api/errors/**`, `src/auth/**` -> business;
  `src/api/controllers/**`, `src/api/middlewares/**`, `src/api/resolvers/**`, `src/api/types/**` (GraphQL types),
  `src/api/Context.ts` -> presentation. Loaders, `lib/`, `decorators/`, `env.ts`, `app.ts`, `commands/` unmapped.
  `test/**` excluded.
- **talento90-typescript-node.** `src/repositories/**`, `src/lib/**` (database, hasher, JWT, health) -> persistence;
  `src/managers/**`, `src/entities/**`, `src/errors.ts` -> business; `src/server/**` -> presentation.
  `src/index.ts`, `src/container.ts` unmapped. `test/**` excluded.

## nestjs (4 layers: domain, infrastructure, application, presentation; preset file patterns kept)

The preset's directory globs and file-name patterns are kept; repo-specific directories are appended.

- **zeldaplay-api** (root `apps/api`). `src/app/models/**` and `src/app/**/models/**` -> domain (the preset maps
  `src/models/**` to domain; the repo has no other entity classes, so this is the only candidate);
  `src/app/database/**`, `src/app/redis/**`, `src/app/config/**`, `src/app/options/**` -> infrastructure;
  `src/app/interfaces/**`, `src/app/validators/**` -> application; `src/app/guards/**` -> presentation; the rest by
  the preset's file patterns (`*.controller.ts`, `*.service.ts`, `*.module.ts`, ...).
- **neoteric-nestjs-auth.** `src/app/**/entity/**`, `_helpers/entity/**`, the repository interface -> domain;
  `src/app/database/**`, `src/migrations/**`, `_helpers/{database,filters,middleware,mail,sms,push}/**`,
  `home/attom/**`, `*.providers.ts` (TypeORM repository providers), `auth/stategies/**` (the repo's spelling of the
  preset's `strategies`), `**/pipe/**` -> infrastructure; `src/app/security/**` (except its module), per-feature
  `*/security/**` voters, `*.validator.ts` -> application; `*.resolver.ts`, `_helpers/graphql/**`,
  `_helpers/decorators/**`, `*.command.ts` -> presentation.
- **vivify-nestjs-boilerplate.** `src/modules/**/*.entity.ts` -> domain; migrations, the password transformer, the JWT
  strategy, `src/utils/**`, `common/transformer/**` (pipes; the preset puts pipes in infrastructure),
  `config/config.service.ts` -> infrastructure; `auth/*.payload.ts` (DTOs), `common/validator/**` -> application;
  `auth/jwt-guard.ts`, `common/decorator/**` -> presentation. Barrels and `swagger/` unmapped.

  adapters. `src/core/types/**`, `src/core/*/types.ts` -> domain; `src/core/*/use-cases/**` (use cases and their

- **ddialar-hexagonal-boilerplate.** README: adapters/{dataSources,transportLayer}, core, ports/{repositories}.

## ddd (5 layers: domain, application, infrastructure, api, composition; preset edges)

- **ddd-forum** (analysis is `src/`; `public/**`, the React app, excluded). Contexts `forum` and `users` under
  `src/modules/` (source root). Domain: `modules/*/domain/**`, `shared/domain/**`, `shared/core/**`, repository
  interfaces `modules/*/repos/*Repo.ts`. Application: use-case folders except controllers and `index.ts`,
  subscriptions, DTOs, the `authService` interface. Infrastructure: repo implementations and the repos barrel,
  mappers, Redis services, Sequelize. API: `infra/http/**`, `*Controller.ts`, `shared/infra/http/**`. Composition:
  `src/index.ts`, use-case `index.ts` wiring files, subscription and service barrels, `src/config/**`.
  Aggregates from the code (`extends AggregateRoot`): User (users), Member and Post (forum); Post's inner entities
  `comment.ts`, `postVote.ts`, `commentVote.ts` (`extends Entity`). Public API per context: its domain events and
  DTOs (and, for users, its use-case `index.ts` files). Value objects: the 12 files whose class extends
  `ValueObject`. Application services: the 30 use-case classes.
- **finance-project-ddd.** Contexts `budget-box`, `transaction`, `user` under `src/modules/`; `src/modules/shared/**`
  declared outside the contexts (shared kernel). Domain: `modules/*/domain/**`, shared domain, interfaces, utils,
  proxies. Application: `modules/*/application/use-cases/**`. Infrastructure: `infra/repo/**`, `infra/entities/**`,
  query services, JWT strategies, shared connections. API: resolvers, GraphQL inputs and types, decorators, guards,
  the per-module Nest service facades, docs and health-check controllers, `src/utils/**`, `src/types/**`.
  Composition: `main.ts`, `app.module.ts`, module files, `src/config/**`. Aggregates `*.aggregate.ts` (BudgetBox with
  inner entity `reason.domain-entity.ts`; Transaction; User); value objects `*.value-object.ts`; repositories the
  domain interfaces and `infra/repo/*.repository.ts`; application services `*.use-case.ts`. Tests and mocks excluded.
- **event-sourcing-ddd.** One bounded context. The tool requires a context root to be a top-level module under the
  source root, so the context `library` is `src/domain/` and the technical folders (`core`, `commandHandlers`,
  `commands`, `eventHandlers`, `infrastructure`, `interfaces`, `projection`, `config`, `constants`, root files) are
  declared outside contexts. Declaring each aggregate folder as a context was rejected: it would turn
  aggregate-to-aggregate references into context violations. Domain: `src/domain/**`, `src/core/**` (base classes and
  interfaces, the shared kernel). Application: command handlers, commands, event handlers. Infrastructure:
  `src/infrastructure/**`, `src/projection/**` (Redis read models). API: `src/interfaces/**`. Composition: `index.ts`,
  `entrypoint.ts`, `config/**`. Aggregates Book and User; event types `IEvent`, `Event`; no value objects exist, so
  the value-object glob matches nothing by design.
